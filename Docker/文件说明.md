## 〇、先分清三种角色

这个目录里长得像的文件其实分三类，**处理方式完全不同**：

| 类别 | 特征 | 进版本库 | 能不能直接改 |
|---|---|---|---|
| **模板** | 文件名带 `.example`，值写成 `<占位符>` 或 `__TOKEN__` | ✅ | ★ 要改的就是它 |
| **生成物** | 同名去掉 `.example`（或由脚本另起名字） | ❌ | 改了会被下次 `bootstrap.sh` 覆盖 |
| **常驻文件** | `docker-compose.yml`、两份 Dockerfile、`snippets/*.conf`、`scripts/*` | ✅ | 直接改，没有模板层 |

生成关系一览（箭头 = 「由谁产出，给谁读」）：

```
Docker/.env.example ──cp+手填──► Docker/.env ──compose 启动时插值──► docker-compose.yml
                                                                          
scripts/bootstrap.sh（唯一的生成器，幂等可反复跑）
  ├─ render __TOKEN__ ◄─ .env 的四个域名 + LIVE_SIGN_SECRET
  │    ├─ nginx/conf.d/im.conf.example ──► nginx/conf.d/im.conf      ──► nginx 容器
  │    └─ app/extra/application-prod-extra.example.yml
  │                              ──► app/extra/application-prod-extra.yml ──► java 进程（外挂配置）
  ├─ cp + set_kv 同步 7 项凭据
  │    └─ conf/im.env.example ──► conf/im.env ──env_file──► im-server 容器里的 java
  ├─ openssl 补缺证书 ──► certs/live/<域名>/{fullchain,privkey}.pem
  └─ 从仓库拷入 ──► sql-init/01_*.sql、02_*.sql、scripts/live-retention.js

CI（.github/workflows/build-and-package.yml）
  ├─ im-bootstrap/target/im-server.jar ──► Docker/app/im-server.jar ──COPY──► 镜像
  └─ 三站 dist ──ssh 覆盖──► Docker/web/<站>/ ──bind mount──► nginx 容器
```

★ 由此得出一条最容易忘的规矩：**`.env` 改了值必须重跑 `bash scripts/bootstrap.sh`**。
改密码不重跑 = nginx 与 `conf/im.env` 还在用旧值；改域名不重跑 = 证书路径与 CORS 白名单还是老域名。

## 一、顶层

### `docker-compose.yml` —— 编排入口（常驻文件）

**谁读它**：`docker compose` 命令本身。

栈里 **4 个必选服务**：`mysql` 与 `redis` 并行起，两个都 healthy 才放 `im-server`，`im-server` healthy 才放 `nginx`（`depends_on: condition: service_healthy`；★ redis 自己不等 mysql，它没写 `depends_on`）。
另有 **2 个注释掉的选装**：`live-retention`（开直播就是必装）、`coturn`（公网跨 NAT 通话才要）。
★ **minio 不在此栈**：官方镜像 2026-09-11 从 Docker Hub 整仓下架，改宿主机二进制 + systemd，im-server 经 `extra_hosts` 的 `host.docker.internal:9000` 连它。

关键设计与它的理由（都在文件注释里，这里只列改之前必须知道的）：

- `name: im-docker` 是**卷名前缀**，改了等于换一批空卷。
- 只有 `nginx` 真写了 `ports:`（80/443，8088 那行是注释）。3306/6379/8080/8081 一律不发布 —— Docker 发布的端口**绕过 UFW**；`im-server` 里的 `8947:8947/udp`（远控打洞）也是注释掉的，放开时记得 `IM_DIRECT_PUNCH_HOST` 必须填公网 IP。
- `im-server` 的 healthcheck 必须写 `CMD ["bash", "-c", …]`，不能图省事用 `CMD-SHELL`：Ubuntu 底的 `/bin/sh` 是 dash，dash 不认 `/dev/tcp`，表现是「永远 unhealthy → nginx 永久等不到 → 整个栈起不来」。
- MySQL 用命名卷而不是 bind mount（官方镜像运行 uid 各异，挂宿主目录十有八九 Permission denied）；MySQL/Redis 的数据因此**不在 `./data` 下**，备份脚本相应走 `mysqldump`。
- `deploy.resources.limits.memory: 2g` 与镜像里 `MaxRAMPercentage=75.0` 配套 → 堆上限约 1.5g。
- 顶层 `volumes:` 必须声明，漏声明的报错是 `refers to undefined volume`，整个 project 无效。

### `.env.example` → `.env` —— compose 层参数（模板 → 生成物）

**谁读它**：docker compose 自己在启动时插值进 `docker-compose.yml`（同目录自动读取，不需要 `--env-file`）。

分组：镜像 tag（写死版本而非 `latest`，回滚全靠它）、依赖镜像来源（默认直连 Docker Hub 短名；拉不动时改回 GHCR 镜像站，`<owner小写>` 由脚本自动回填）、`MINIO_DATA_DIR`、`IM_SERVER_TAG`、**四个域名**、**凭据**、`TURN_SECRET`。

★ 这份文件是**唯一需要人手填**的：`conf/im.env` 里的 7 项凭据由 `bootstrap.sh` 从这儿同步，域名与直播密钥也由此灌进各生成物。同一值只填一次是设计目标（防两边写歪）。

> ⚠ 注意：本模板是**进版本库**的，而当前里面已经填了几个看起来是真的口令（`MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD`、`REDIS_PASSWORD`、`minioadmin`、两串 dev secret）。
> 严格口径下示例文件只该放 `<占位符>`；仓库一旦转公开或泄露，这些就是明文凭据外泄。要么换成占位符、要么确保仓库私有并轮换过这些口令。

### `README.md` / `开发必备.txt` / `文件说明.md`（本文件）

纯文本，没有任何程序读它们。三份的分工见开头表格。

## 二、应用侧的两份配置（`conf/` 与 `app/extra/`）

这两份是给 **java 进程**看的，但机制完全不同，常被搞混：

| | `conf/im.env` | `app/extra/application-prod-extra.yml` |
|---|---|---|
| 机制 | 环境变量（`env_file` 注入） | Spring 外挂配置文件（`SPRING_CONFIG_ADDITIONAL_LOCATION`） |
| 能改什么 | `application.yml` 里**带 `${}` 占位符**的那些键 | **不带占位符**的字面列表（目前只有 CORS 白名单） |
| 语法约束 | 不加引号、不写行内注释、不指望 `${}` 展开 | 标准 yaml |
| 谁生成 | `bootstrap.sh` 第 ④ 步 cp + 同步凭据 | `bootstrap.sh` 第 ③ 步 render 域名 token |

### `conf/im.env.example` → `conf/im.env`

37 个生效键 + 3 个注释掉的可选键，分组是：必填 / 文件存储（MinIO 或 local）/ 按需（AI、短信、邮件）/ 直播 / TURN / 远控打洞 / 监控 / CORS 开关。

★ 这份文件最值钱的部分是那些标 ★ 的「**不报错但功能没了**」：`IM_LOG_HOME`（默认 Windows 路径 → 日志静默丢失）、`IM_UPLOAD_TMP_DIR`（不在卷上 → 重建容器丢分片）、`IM_AI_KNOWLEDGE_DIR`（Linux 上路径不存在 → 检索永远空转）、`IM_SMS_PROVIDER`（默认 mock → 用户收不到验证码）、`MANAGEMENT_ADDRESS`（容器里的 loopback 只有本容器能到）。
容器特有条款：栈内中间件必须写服务名（`mysql` / `redis`），`127.0.0.1` 指的是它自己；`TZ=Asia/Shanghai` 要与 MySQL 的 `--default-time-zone=+08:00` **两边一起设**。

### `app/extra/application-prod-extra.example.yml` → 同名去 `.example`

只干一件事：**覆盖 `im.cors.allowed-origins`**。`application.yml` 里那个列表是字面量、没有 `${}`，环境变量动不了它，于是换域名后浏览器全量 `403 Invalid CORS request` 而 `curl` 一切正常（curl 不发 Origin 头）。

★★ 两个必须知道的口径：① Spring 绑 List 是**整体替换不是追加**，所以桌面端（`tauri://localhost`）、移动端（`capacitor://localhost`）、vite 联调端口、局域网 `*.*.*.*` 那二十多条要一并抄全，只写三行域名的结果是桌面端与安卓端连不上；
② 生效靠 `conf/im.env` 里那行 `SPRING_CONFIG_ADDITIONAL_LOCATION`，`bootstrap.sh` 生成文件后会**顺手把开关打开**。公网上线建议删掉末尾 4 条局域网通配。

## 三、`app/` —— 后端镜像怎么来

两条路线，**最终镜像刻意做成一模一样**（同基础镜像、同 uid 处理、同 `JAVA_OPTS`、同 `ENTRYPOINT`），差别只有「jar 从哪来」。不一致会造出「本机能跑线上不能跑」。

| | `Dockerfile`（路线 A，默认） | `Dockerfile.multistage`（路线 B，兜底） |
|---|---|---|
| 谁编译 | 容器外（CI 或构建机 `mvn package`） | 容器内第一阶段 `maven:3.9-eclipse-temurin-21` |
| 构建上下文 | `Docker/app`（看不见源码） | **仓库根**（`.dockerignore` 因此才生效） |
| 命令 | `docker build -t local/im-server:1.0.0 Docker/app` 或 `docker compose build im-server` | `docker build -f Docker/app/Dockerfile.multistage -t local/im-server:1.0.0 .` |
| 构建机要装什么 | 需要 Maven + JDK | 只要 docker |
| 什么时候用 | 日常（CI 就是这条） | 没有构建机 / 服务器连不上 GitHub 时现场构建 |

两份共有的关键决策（别改回「看起来更顺」的写法）：

- **不能用 `eclipse-temurin:21-jre-alpine`**：busybox sh 不认 `/dev/tcp`，健康检查永远失败。
- **uid/gid 1000 复用优先，不新建 `im` 用户**：Ubuntu 24.04 底已自带占用 1000 的用户/组，裸写 `groupadd --gid 1000 im` 会退出码 4，`useradd --uid 1000 im` 会报 `UID 1000 is not unique`。正解是 `getent` 查数字、存在就复用。
- `ENTRYPOINT`（不是 `CMD`）+ `exec java`：让 java 顶替 sh 成 PID 1，否则 `docker stop` 的 SIGTERM 只打到 sh，连接池与 WS 会话没有优雅关闭机会。
- 不写死 `--spring.profiles.active`：profile 由 `conf/im.env` 的 `SPRING_PROFILES_ACTIVE` 控制，命令行优先级更高，写死了改 env 改了个寂寞。

`app/im-server.jar`（**不进库**）：路线 A 的输入，由 CI 的 `download-artifact` 放进去；名字来自 `im-bootstrap/pom.xml` 的 `<finalName>im-server</finalName>`。

## 四、`nginx/`

### `conf.d/im.conf.example` → `conf.d/im.conf`

**谁读它**：nginx 容器（`./nginx/conf.d` 以 `:ro` 挂到 `/etc/nginx/conf.d`）。

结构：一个 80 server（ACME 挑战、`location = /healthz`、其余 301 到 https）+ 三个 443 server 按 `server_name` 分流：

- **聊天端**：SPA `try_files` 兜底、静态资源 7d 缓存、`/ws`（`Upgrade` 头 + `proxy_read_timeout 3600s`）、`/api`（include proxy.conf + 120s）、`/live/` 播放面（`root /data` + `limit_except GET HEAD OPTIONS`）。
  ★ 只有 `index.m3u8` 做 `secure_link_md5` 签名，**变体清单不能签**（hls.js 拉它不带 query，签了就是画质切换全 403）。
- **管理后台**：只有 `/api`，没有 `/ws` 与 `/live`（与 `im-admin-ui/vite.config.js` 口径一致）；prod 已关 knife4j，`/doc.html` 回 404 是设计如此。
- **官网**：纯静态，不反代。
- 推流口 8088 那一整块是**注释掉的**（要开：取消注释 + compose 发布端口 + 手工填 `allow` 源 IP）。容器里 `$remote_addr` 可能是网关而非真实 IP，所以按 IP 挡天生不可靠，正解是 `userland-proxy: false` 实测或交给云安全组 / `DOCKER-USER` 链。

★ 模板里的 `__IM_DOMAIN__` 这类 token **不用 envsubst**：nginx 配置里满是 `$host` / `$uri` / `$remote_addr`，envsubst 会把它们一并替成空串，表现是接口全 404 却看不出根因。

改完正式文件的自检与生效：`docker compose exec nginx nginx -t && docker compose exec nginx nginx -s reload`（新建文件用 restart 更稳，目录项不一定穿透 `:ro` 挂载）。

### `snippets/proxy.conf` 与 `snippets/ssl.conf`（常驻文件，无模板）

反代公共头（Host / X-Real-IP / X-Forwarded-For / X-Forwarded-Proto + `proxy_http_version 1.1`）与 TLS 参数（1.2/1.3、会话缓存、`ssl_stapling off`、HSTS）。
★ 它们放 `snippets/` 而不是 `conf.d/`：`conf.d` 下的 `*.conf` 会被主配置当 http 上下文自动 include，片段扔错目录早晚会让 `nginx -t` 失败。
HSTS 那行当前是**启用**状态，注释里建议测试期先关掉 —— 一旦下发，浏览器半年内只认 https，回退要清 HSTS 列表。

## 五、`scripts/` —— 七个脚本

| 脚本 | 什么时候跑 | 一句话职责 |
|---|---|---|
| `bootstrap.sh` | 每次 `.env` 改值后（幂等，可反复跑） | 校验 → 建目录摆权限 → 生成三份配置 → 补证书 → 静态校验 |
| `import-sql.sh` | 有 migration 要上库时 | 把 SQL 原样 `cp` 进容器再 `-e "source"` 执行 |
| `clear-perm-cache.sh` | 权限点变更后（**必跑**） | 清 `im:auth:*` 缓存 |
| `backup.sh` | 日常 cron / 升级前 | 数据库 + 对象存储 + 编排配置 + Redis 快照 |
| `health.sh` | 起完栈 / 出问题时 | 六层排查 + 打印容器内变量真值 |
| `update.sh` | 升级或回滚后端 | 换 tag → pull → 只重建 im-server → 等 healthy |
| `im-docker.service` | 装一次 | systemd 开机自启 |

要点（每条都对应一次真实踩坑）：

- **`bootstrap.sh`** 七步：① 校验 `.env`（拦下所有仍留 `<...>` 的项）→ ①.5 从 `IM_SERVER_TAG` 反推 owner 回填依赖镜像 → ② 建目录 + `chown 1000:1000` 四个可写目录 → ③ render 生成 `im.conf` 与 CORS 外挂 → ④ 生成 `conf/im.env` 并同步 7 项凭据（顺带扫引号/行内注释/残留占位符）→ ⑤ 缺证书补 30 天自签名（openssl 失败会当场说，不静默中止）→ ⑥ 从仓库拷 `sql-init/01_..02_..`（★ 必须加序号前缀，否则 `im_data.sql` 按字典序排在 `im_schema.sql` 前面 → 往不存在的表插数据）与 `live-retention.js`，并检查三站 `index.html` → ⑦ `docker compose config -q`。
- **`import-sql.sh`** 拒绝执行含 `DROP TABLE` 的脚本（那是全量建库脚本，在生产库上跑一次＝清库）；★ 不走管道也不走 heredoc，因为字节流会被按容器 LANG 重编码，**中文静默变 `?`**、不报错、行数还对得上。导完涉及权限点要接着跑 `clear-perm-cache.sh`。
- **`clear-perm-cache.sh`** 三步：先数 → 再删（`xargs -r -n 50 DEL`）→ 删完回头再数一次确认为 0。不可省略第三步：`--scan` 与 `DEL` 分两次连接，中间新写回去的键会漏。为什么必须有：`im:auth:perm:{userId}` TTL 30 分钟且**登录不刷新**，不清的表现是「SQL 明明执行了、后台菜单还是旧的」。
- **`backup.sh`** 四段：`mysqldump --single-transaction --routines --default-character-set=utf8mb4`；minio 数据目录按 `.env` → `/etc/default/minio` → `/data/minio` 三级回落读取，**先停服务再 tar**（运行中打包会漏 in-flight 分片）；`app/extra` 等配置打成 tar 并 `chmod 600`（里面有明文密码）；Redis `BGSAVE` 后拷出 `dump.rdb`。★ 备份落同一块盘等于没备份。
- **`health.sh`** 六层：编排（含宿主 minio）→ 最近 10 分钟报错 → 容器内问 Actuator → nginx 跨容器探后端 + `nginx -t` → 外部走完整链路 → 打印 java 进程实际看到的变量真值。判定口径记住一条：**未登录回 HTTP 200 + `code:1002` 才是正常**（全局异常处理器不带 `@ResponseStatus`），`404` 说明控制器没加载，`403 Invalid CORS request` 回 CORS，`502` 回 nginx→后端那段。
- **`update.sh`** 三条规矩：换版本＝换 tag（绝不用 `build` 覆盖同名 tag，否则回滚失去目标）；只点名 `im-server`（裸 `up -d` 会顺带重建别的容器）；回滚镜像 ≠ 回滚数据库。pull 失败会把 `.env` 改回旧 tag，`up --wait` 不 healthy 就失败退出并提示回滚命令。★ 旧 tag 别 `image prune -a`，那是回滚目标。
- **`im-docker.service`**：`Type=oneshot` + `RemainAfterExit`，`ExecStart` 带 `--wait`（等健康检查），`TimeoutStartSec=300`（首次 initdb + 冷启）。★★★ `ExecStop` 特意**只有 `down`，没有 `-v`** —— 一字之差把数据卷一起删掉。装它之前确认 `WorkingDirectory` 与实际部署目录一致。

## 六、四个 `.gitkeep` 占位目录

它们各带几行注释（说明由谁填、挂去哪），存在的唯一理由是「空目录进不了版本库」：

| 目录 | 谁来填 | 挂到哪 | 注意 |
|---|---|---|---|
| `data/` | `bootstrap.sh` 建 `logs/upload-tmp/files/live/knowledge` 并 chown 1000 | `im-server` 的对应容器内路径 | ★ 容器内路径与 `conf/im.env` 必须一一对应，宿主机看不到＝没挂卷 |
| `web/` | CI deploy job 或手工 `scp` 三站 dist | `nginx` 容器（全 `:ro`） | bind mount，覆盖即生效，不用重启容器 |
| `certs/` | certbot 签发，或 `bootstrap.sh` 补 30 天自签名 | `nginx:/etc/letsencrypt:ro` | 结构必须是 `live/<域名>/{fullchain.pem,privkey.pem}`；私钥绝不进版本库 |
| `sql-init/` | `bootstrap.sh` 从 `sql/` 拷入并重命名 `01_/02_` | `mysql:/docker-entrypoint-initdb.d:ro` | ★ 只在「空卷首次启动」执行一次；建完库建议注释掉这行挂载并清空目录（`01_im_schema.sql` 开头有 37 条 `DROP TABLE IF EXISTS`）。非 `*.sql`/`*.sql.gz`/`*.sh` 的文件会被 entrypoint 静默 ignoring |

## 七、本目录之外但强相关的四处

| 位置 | 为什么和这里绑在一起 |
|---|---|
| 仓库根 `.dockerignore` | 只在路线 B（上下文＝仓库根）生效。少了它多阶段构建慢到不能用；`!**/im-bootstrap/target/im-server.jar` 必须排在 `**/target` **之后**，否则第二阶段无产物可 COPY |
| `.github/workflows/build-and-package.yml` | 产出 `im-server.jar` 与三份 dist 并推 GHCR；改本目录的产物名/路径时要同步它 |

## 八、改了怎么生效（最常问的一张表）

| 改动 | 必须做的动作 |
|---|---|
| `.env` 任何值 | `bash scripts/bootstrap.sh`，再按下面几行决定要不要重启谁 |

## 九、四条不能破的红线

细节见 [`README.md` 第四节](README.md)，这里只复述结论：① **单实例**（WS 扇出只认本进程连接表，12 个 `@Scheduled` 没有 ShedLock）；② **主栈只发布 80/443**（按需 8088/3478/8947-udp），Docker 发布的端口绕过 UFW；③ **应用连栈内中间件必须用服务名**（minio 在宿主，走 `host.docker.internal:9000`）；④ **时区两边一起设**。

## 十、本目录当前存在的口径偏差（读其他文档时注意）

写这一节不是为了挑错，是因为照旧口径操作会真踩坑：

1. **minio 已移出主栈**，但 [`开发必备.txt`](开发必备.txt) 第一节的服务表仍把 `minio minio/minio` 列为栈内服务、第三条红线仍写「必须用服务名 `minio`」。现况：宿主机官方二进制 + systemd，连接走 `host.docker.internal:9000`（以 `docker-compose.yml`、`conf/im.env.example` 为准）。
2. **建用户那段只剩「复用 / 补建」两条分支**，两份 Dockerfile 的注释已更新为实测结论（占用 1000 的是 Ubuntu 自带的 `ubuntu` 用户，不是网传的 `gro`）；`开发必备.txt` 第三节仍描述「四级阶梯 + `groupmod -n im gro` 让位」那套旧写法。
3. 两份 `.example` 的头注释都写「`application.yml` 里那 **60** 个 `${}` 占位符」，实测现为 **63 个唯一键 / 64 处引用**。数字只是量级描述，不影响行为。
4. `scripts/im-docker.service` 的 `Description` 与 `ExecStop` 注释仍提到 minio / `minio-data` 卷，那个卷已经不在 compose 里了（`ExecStop` 没有 `-v` 这条约束本身依然成立）。
5. ⚠ `.env.example` 里已填明文口令（见第一节那条警告）。这是本目录唯一一处与安全直接相关的偏差，建议优先处理。

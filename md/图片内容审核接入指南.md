## 一、这次到底落地了什么

`md/待开发功能.txt` 第 12 条要求「图片敏感词过滤 + 血腥暴力 + NSFW Model」。现状拆成两半说清楚：

| 目标 | 状态 | 说明 |
|---|---|---|
| 图内文字敏感词 | **已完成**（上一轮） | 发送端 tesseract.js 本地 OCR → 服务端 `SensitiveWordFilter` 遮蔽 → 存 `extra.ocrText` |
| **色情 / NSFW 图像识别** | **已完成**（本轮） | nsfwjs + TensorFlow.js，MobileNetV2 五分类，命中即拒发 + 审计留痕 |
| **血腥 / 暴力图像识别** | **已完成（本轮，默认关闭）** | nsfwjs 的模型**根本没有这两类**（只有 Drawing / Hentai / Neutral / Porn / Sexy），不是调阈值能补出来的，所以另接了一个 ViT-Base 的 ONNX 模型走 onnxruntime-web。默认关闭是因为模型 83MB 不入库、要运维先投放，且真实照片精度未验收——详见[第九节](#九血腥--暴力路线-a-已实现默认关闭) |

一句话定性：**这是一道装在发送端正常路径上的闸门，不是对抗性防御。** 判定跑在用户浏览器里，
绕过它只需要绕开这个页面直接调 `/api/file/upload`。它能拦住的，是「用官方界面正常发图的人」。

## 二、链路一眼看完

```
用户点发送 / 选头像 / 提交直播封面
        │
        ├─ 1. GET /api/file/moderation/policy   ← 阈值与开关（前端缓存 10 分钟，拉不到用内置默认值）
        │
        ├─ 2. 本机按编排表加载模型（首次约 4.5MB 按需 chunk，之后常驻复用，空闲 120s 释放）
        │        图片 → 224×224 canvas → tf.browser.fromPixels → 5 类概率
        │        配了 Violent 阈值时再走一路：同一张画布 → ONNX(ViT-Base) → NonViolent / Violent
        │        两路评分汇进同一张判定表，任一类别命中即拒发，命中后不再跑后面的模型
        │
        ├─ 3. 任一类别概率 ≥ 阈值？
        │        ├─ 否 → 照常走原有上传 + 发送链路（图片字节才第一次离开本机）
        │        └─ 是 → 【拒发】图片不上传、消息不发、气泡不入栈
        │                  └─ POST /api/file/moderation/report  （尽力而为，失败不重试不提示）
        │                          └─ logger com.im.moderation → MODERATION/moderation.log
        │
        └─ 4. 界面提示「图片含违规内容，已拒发」
```

服务端**从没见过那张图**——它只收到一串判定结果数字。因此 `report` 端点不采信客户端结论、
恒返回成功，唯一作用是把「谁、在哪个场景、试过什么文件、哪一类多少分」落进审计文件。

## 三、为什么把推理放在前端

这是本次唯一的技术选型，理由要留在仓库里，否则下次会重新纠结一遍：

| 考虑点 | 前端 nsfwjs | 服务端 DJL / ONNX |
|---|---|---|
| 内网无外网出口 | ✅ 模型权重以 base64 内置在 `nsfwjs` npm 包里，随 `npm run build` 产物分发，运行期**零外部请求** | ⚠️ 得先把 `.onnx` 模型文件与原生运行时一并落地到服务器 |
| 模型从哪来 | ✅ `npm install nsfwjs` 就有 | ❌ 仓库里没有 `.onnx`；nsfwjs 的产物是 TF.js 格式，要用 tf2onnx 从**原始 Keras/SavedModel** 重新导出，不能从 TF.js 产物反推 |
| 服务端资源 | ✅ 不占一个线程、一块显存 | ⚠️ 每张图一次 CPU/GPU 推理，上传峰值直接打在应用进程上 |
| 延迟 | ✅ WebGL 上单张几十毫秒 | ⚠️ 需先传完字节才能判，图已在服务器上，「拦下」变成「删掉」 |
| **能不能绕过** | ❌ **能**（客户端说了算） | ✅ 不能，服务端可硬拒 |
| 隐私 | ✅ 图片不出本机 | ⚠️ 图片必须先到服务端 |

结论：先把「正常使用路径的拦截 + 零依赖离线部署 + 隐私」这三头拿到，把「对抗性」明确标注为代价。
真要把这道闸门升级成防线，走[第九节](#九血腥--暴力路线-a-已实现默认关闭)路线 B——**阈值配置与上报口径可以原样复用**。

**体积实测**（`npm run build` 产物，`im-ui/dist/assets/`）：

| chunk | 原始 | gzip | 何时加载 |
|---|---|---|---|
| `nsfw-*.js`（编排工具代码） | 4.29 KB | 2.00 KB | 进聊天页即随 `ChatWindow` 加载（很小，不做懒加载） |
| `core-*.js`（nsfwjs core + tfjs） | 1061 KB | — | **首次识别图片时**动态 import |
| `model.min-*.js`（模型拓扑） | 105 KB | 11.5 KB | 同上 |
| `group1-shard1of1.min-*.js`（权重） | 3412 KB | 2496 KB | 同上 |
| `violence-*.js`（血腥 / 暴力工具代码） | 2.42 KB | 1.28 KB | **仅当 thresholds 里配了 `Violent`** 时动态 import |
| `ort.wasm.bundle.min-*.js`（ORT 的 wasm EP） | 72 KB | 24 KB | 同上 |
| `ort-wasm-simd-threaded-*.wasm` | 13.58 MB | 3.70 MB | 同上 |
| `models/violence/model.onnx` | 82.78 MB | — | 同上（还得先投放，见第九节） |

不发消息图片的用户永远不会下载那 4.5MB。只打一个模型（而非 nsfwjs 默认的三个 39MB）是关键做法：
必须用 `nsfwjs/core` + 显式传 `modelDefinitions`，**不要 `import ... from 'nsfwjs'`**。
血腥 / 暴力那一列同理：`nsfw.js` 对它用的是 `await import('./violence')` 而不是顶上的静态 import，
否则那 2.4KB 的工具代码会被算进 eagerly 可达的模块，「不启用 = 零开销」就不成立了。

## 五、配置项与生效方式

```yaml
im:
  moderation:
    enabled: ${IM_MODERATION_ENABLED:true}   # 总开关：false 时前端整个识别环节跳过
    audit-enabled: true                      # 命中是否上报审计；false = 只拦不记
    thresholds:                              # 任一类别 ≥ 阈值即拒发；没列出的类别不参与判定
      Porn: 0.80
      Hentai: 0.80
      # Violent: 0.75                        # 血腥 / 暴力：注释掉＝整个检测器不激活（第九节）
    max-score-entries: 16                    # 上报评分条目上限（防御性，超出直接丢）
    max-text-length: 120                     # 上报里文件名等字符串字段的最大长度
```

| 改动 | 怎么生效 |
|---|---|
| 改阈值 / 开关 | **重启后端**即可。阈值是运行期下发给前端的，用户不必重新下载前端包；前端策略缓存有 **10 分钟 TTL**，已打开的页面最多 10 分钟内自动重拉（不必刷新） |
| 改前端判定逻辑 | `cd im-ui; npm run build`（Electron 用 `npm run build:electron`），用户端要拿到新产物 |
| 换色情模型 | 改 `utils/nsfw.js` 的 `import` 与 `load()` 参数，属于代码变更，同上 |
| 换血腥 / 暴力模型 | 改 `utils/violence.js` 的 `MODEL_URL`、`LABELS`、`INPUT_SIZE` 与归一化口径，同上 |
| 投放 / 移除血腥暴力模型 | 把 `model.onnx` 放进 `im-ui/public/models/violence/` 后重新构建；已构建完的直接拷进 `dist/models/violence/` 也生效。后端不用改，用户端下一次发图才会去取 |

前端在**策略接口拉不到**时用内置默认值（`Porn 0.80 / Hentai 0.80`）兜底——拦不住新阈值，
但不会因为策略接口抖动就不发图。这个默认值必须与 `application.yml` 保持一致，改一边就要改另一边。

## 六、阈值怎么调

模型固定输出五类，`classify()` 按概率降序返回：

| 类别 | 含义 | 默认是否拦 | 理由 |
|---|---|---|---|
| `Porn` | 露骨色情 | ✅ 0.80 | 最没有争议的一类 |
| `Hentai` | 二次元色情 | ✅ 0.80 | 与 Porn 同级；只写实照片的场景可以删掉它 |
| `Sexy` | 性感（泳装、内衣、健身） | ❌ 不拦 | **误报重灾区**，加进来会拦掉大量正常生活照。要拦建议从 0.90 起 |
| `Neutral` | 正常 | ❌ | 反向指标，配了等于把正常图拦掉 |
| `Drawing` | 普通绘画/素描 | ❌ | 同上 |

血腥 / 暴力那个模型只有两个类，阈值写在**同一个 `thresholds` 里**（不另开一组）：

| 类别 | 含义 | 默认是否拦 | 理由 |
|---|---|---|---|
| `Violent` | 血腥与暴力（同一类） | ❌ 默认注释掉 | 它同时是**激活开关**：不出现就整个检测器不加载。起点不要低于 0.75（合成无结构图也能拿到 0.66~0.73） |
| `NonViolent` | 非暴力 | ❌ | 反向指标，且被 `blockable` 白名单挡住，配了也不生效 |

调法（按这个顺序，别一上来就拍最严的值）：

1. 先保持现状上线，只观察**审计日志里的概率分布**（第七节有统计命令）。
2. 误放多 → 把 `Porn` 降到 0.70 / 0.60；误拦多 → 升回 0.90。
3. 每改一次重启后端，让用户端重新拉一次策略即可（不用重新构建前端）。
4. 阈值写 `0` 或 `>1` 会被服务端 `cleanThresholds` 判为无效并**跳过该条**（打一条 WARN），
   前端对拿不到阈值的类别一律不拦——不会出现「配错一个数把全站图片拦死」。
5. 判定按注册表顺序跑（先色情、后血腥），**命中即早退**：一张露骨色情图不会再去跑那 1.2s
   的 ViT。一个模型抛异常不影响另一个，只是那一路的结果缺失（降级列表会带上原因）。

## 七、审计日志

- **位置**：`${im.log.home}/MODERATION/moderation.log`（默认根目录 `D:/rizi1/IM`，即 `D:/rizi1/IM/MODERATION/moderation.log`），跨天滚成 `moderation-yyyy-MM-dd.N.log`。
- **单独成档的理由**：这不是排障日志，是事后追责记录——「谁在什么时候试过发什么图」必须能从海量 `info.log` 里单独拎出来。它含**原始文件名（本身可能敏感）与用户 ID**，目录权限按敏感数据对待，与 SQL 档同规。
- **dev 环境**额外在控制台镜像一份，试阈值不必开文件。

格式（一行一条，字段顺序固定）：

```
2026-10-13 11:32:07.412 INFO [im-async-3] [web-lt9x2k1a-7h3nq] [uid:10023] com.im.moderation : [审核命中] userId=10023 scene=chat_image class=Porn prob=0.931 threshold=0.800 size=1048576 name="IMG_0231.jpg" conv=8812 scores=[Porn:0.931, Hentai:0.041, Sexy:0.018, Neutral:0.007, Drawing:0.003]
```

| 字段 | 来源 | 备注 |
|---|---|---|
| `userId` | 登录态（`SecurityUtil`） | **不采信上报体里的用户身份** |
| `scene` | 客户端上报 | 服务端强校验必须是 `avatar` / `chat_image` / `video_cover`，否则 400 |
| `class` / `prob` | 命中的最高分类别与概率 | 概率强制夹 0~1，定长三位小数输出 |
| `threshold` | 客户端实际使用的阈值 | 用于事后核对「这次拦人是按哪条阈值」 |
| `size` / `name` / `conv` | 客户端上报 | 文件名折空白、去 `"` 与 `\`、限长——它是自由文本，不洗干净等于给对方一个伪造日志行的机会 |
| `scores` | 全部评分：nsfwjs 5 类 + 血腥暴力 2 类，最多 7 条 | 只开了色情时就是 5 条；超过 `max-score-entries`（16）的尾部直接丢 |

常用统计命令（PowerShell）：

```powershell
# 今天有多少次命中、都落在哪些场景
Select-String -Path 'D:/rizi1/IM/MODERATION/moderation.log' -Pattern '\[审核命中\]' | Measure-Object
# 某个用户试过几次
Select-String -Path 'D:/rizi1/IM/MODERATION/moderation.log' -Pattern 'userId=10023'
# Porn 概率的分布（用来决定阈值往哪儿压）
(Select-String -Path 'D:/rizi1/IM/MODERATION/moderation.log' -Pattern 'class=Porn prob=([\d.]+)') |
  ForEach-Object { [double]$_.Matches[0].Groups[1].Value } | Sort-Object
```

`enabled=false` 时收到上报只打 DEBUG 不落审计；`audit-enabled=false` 时只拦不记，但**场景校验仍然生效**。

## 八、再加一个接入点

任何「用户可自选图片再上传」的地方，三行接入：

```js
import { guardImage } from '@/utils/nsfw'

const guard = await guardImage(file, { scene: 'chat_image', conversationId })
if (!guard.pass) {
  ElMessage.error(guard.message)   // 「图片含违规内容，已拒发」
  return                          // 不上传、不发送
}
```

约束：

- `scene` 必须是**图片类** `FileBizType` 的 code（`avatar` / `chat_image` / `video_cover`）。
  新增业务类型要先在 `im-file` 的 `FileBizType` 注册，否则服务端 `requireImageScene` 会回 400。
- `guardImage` **永不抛异常**：模型加载失败、解码超时、WebGL 不可用、策略接口挂掉，全部返回 `pass: true` 放行。
  要改成「识别不了就不许发」，得显式改 `utils/nsfw.js` 的降级分支，别在各个调用点各写一套。
- 聊天场景要把闸门放在**挂占位气泡之前**：被拒发的图不该在记录里留下一条带「重发」按钮的失败气泡
  （重发必然再被拦一次）。重发路径（`retryClientMsgId` 非空）要顺手 `markFailed` + `forgetRetryFile`。
- 开了 `Violent` 之后每张图会**多等 1.2~2.3s**（同步卡在发送前，不是后台校验）。
  `ChatWindow` 已经有 `uploadStage='nsfw'` 那一档转圈提示，不必再加东西；但要接受这个代价才能开。

## 九、血腥 / 暴力：路线 A 已实现（默认关闭）

**为什么必须再加一个模型**：nsfwjs 的 MobileNetV2 是在五个类别上训练的，输出层只有五个神经元
（`nsfwjs/dist/esm/nsfw_classes.js` 写死索引 0~4）。给它一张血图，它只会把结果错分到
`Neutral`/`Porn`/`Sexy` 中的某一个——**不是精度不够，是这个问题它没被训练过**。
换 `MobileNetV2Mid` / `InceptionV3` 也一样，它们只是同五类的精度/速度权衡。

### 已落地的形态

| 项 | 取值 |
|---|---|
| 模型 | `jaranohaal/vit-base-violence-detection`（Apache-2.0），backbone `google/vit-base-patch16-224-in21k`，在 Kaggle「Real Life Violence Situations」上微调 |
| 取的产物 | `onnx-community/vit-base-violence-detection-ONNX` 的 `onnx/model_quantized.onnx`（int8，82.78MB） |
| 输出类别 | 只有两类：`NonViolent`(索引 0) / `Violent`(索引 1)。**血腥与暴力在这同一个类里**（数据集本身就是真实斗殴 / 伤害 / 血迹照片），分不开，也别指望它看懂卡通打斗 |
| 推理运行时 | `onnxruntime-web@1.30.0`，只取 wasm EP（`onnxruntime-web/wasm` 子入口） |
| 代码 | `im-ui/src/utils/violence.js`（模型侧）+ `im-ui/src/utils/nsfw.js` 的 `MODELS` 注册表（编排侧） |
| 激活条件 | 后端 `im.moderation.thresholds` 里出现 `Violent`（取值必须是 0~1 之间的数）。没配就整个检测器不进编排循环，连 `violence.js` 那个 chunk 都不请求 |
| 拦截白名单 | 只有 `Violent` 能拦图。写 `NonViolent: 0.9` 不生效（`detector.blockable` 白名单挡掉，否则每张正常照片都会被拦） |

标签顺序的口径：源模型 config 不带 `id2label`，靠同族模型（`Tite2/violence-detection`、
`locih/violence_classification`）确认惯例 `0 = NonViolent/safe、1 = Violent/unsafe`。
预处理照抄它的 `preprocessor_config.json`：224×224 → `/255` → `(x-0.5)/0.5`；
ONNX 导出的是 raw logits，`violence.js` 自己过 softmax 再汇进同一张判定表。

服务端**没有任何改动**：`thresholds` 是自由 Map，只原样下发；`hitClass` 是字符串，
审计行直接写成 `class=Violent prob=...`；`max-score-entries=16` 兜住了两个模型拼起来的 7 条评分。

### 投放步骤（默认关闭就是因为这一步没做）

模型 83MB 不入库（`.gitignore` 里的 `im-ui/public/models/`），要用就自己取一次：

```powershell
# 1) 取模型（HuggingFace，约 83MB）
New-Item -ItemType Directory -Force im-ui\public\models\violence | Out-Null
curl.exe -L -o im-ui\public\models\violence\model.onnx `
  https://huggingface.co/onnx-community/vit-base-violence-detection-ONNX/resolve/main/onnx/model_quantized.onnx

# 2) 打开阈值：im-bootstrap/src/main/resources/application.yml
#    im.moderation.thresholds 下把 "# Violent: 0.75" 的注释去掉

# 3) 重新构建前端（第 1 步的文件是构建输入，会被拷进 dist/models/…）
cd im-ui; npm run build

# 4) 重启后端
```

已经构建完了才想起来投放：把同一个文件拷进 `im-ui/dist/models/violence/model.onnx` 也生效（它只是静态资源）。
没投放会怎样：前端首次 `fetch` 撞 404 → `notProvisioned` 记死 → 该检测器停用，色情那条链路照常，
不会每张图重试下载。

### 代价（实测）

| 项 | 数值 |
|---|---|
| 模型下载 | 82.78MB（onnx 二进制，无 gzip 收益） |
| 运行时 | `ort-wasm-simd-threaded-*.wasm` 13.58MB（gzip 3.70MB）+ `ort-wasm-simd-threaded-*.mjs` 24KB + `ort.wasm.bundle.min-*.js` 72KB + `violence-*.js` 2.42KB |
| 首次判定 | Electron + 局域网 dev、两个模型齐用：**7~16s**（含 83MB 下载与建会话） |
| 热态单张 | 约 **2.3s**：`scoreViolence` 单模型 1.1~1.3s，色情那一路在 WebGL 上只占几十毫秒 |
| 线程 | 页面没有 SharedArrayBuffer（实测 `crossOriginIsolated=false`）时退回 `numThreads=1`；**没有**为提速去加 COOP/COEP，因为 COEP 会连带影响页面上所有跨源资源 |

这是卡在发送前的**同步等待**，不是后台异步校验。所以开不开这个检测器是个运营决策，不是免费的。

### 三个坑（改这块代码前必读）

1. **别把 wasm 拷到 `public/` 再用字符串路径指过去**。onnxruntime-web 是动态 `import()` 那个 `.mjs` 入口的，
   Vite 对 public 下的文件加 `?import` 会直接回 500（public 不参与依赖分析），报出来的却是
   `no available backend found`，看不出根因。正确做法是 `?url` 交给打包器 + `ort.env.wasm.wasmPaths = { mjs, wasm }`。
2. **`?url` 的子路径必须写包 `exports` 里点到的那几条**：`onnxruntime-web/ort-wasm-simd-threaded.mjs?url` 可以，
   `onnxruntime-web/dist/ort-wasm-simd-threaded.wasm?url` 会被 exports map 挡住（模块自身 500）。
3. **入口要 `onnxruntime-web/wasm`，不是默认入口**。默认入口带 WebGPU EP，会去找 27MB 的
   `ort-wasm-simd-threaded.jsep.wasm`，体积白多一倍；`/wasm` 子入口只含 wasm EP，用 13.58MB 那份。

另外 `session.dispose` 在 1.30 上不保证是函数（Node 侧实测就不是），`violence.js` 的 `releaseSession()`
带了 typeof 守卫，别改成直接调用。

### 还没做、需要人工补的

1. **真实照片的精度没验**：本轮拿不到真实暴力图片（HF 数据集是 gated，401）。合成图（纯黑、纯红加黑块）
   也能拿到 `Violent 0.66~0.73`，所以**阈值起点不要低于 0.75**；投放后先看审计日志里正常照片落在什么区间，
   再决定往下压还是往上抬。
2. **桌面端（Electron）没验**：electron 构建 `base: './'`，模型地址按 `import.meta.env.BASE_URL` 拼
   （`./models/violence/model.onnx`，相对 `dist/index.html` 解析正好落在 `dist/models/…`），但 file:// 下
   fetch 与 wasm 加载这一组合本轮没跑过。真要上桌面端，先把 dist 交给本地 HTTP 服务再验。
3. **只有二分类**：要把「血腥」与「暴力」分开处置（例如血迹只标记、斗殴才拦）的话，这个模型给不了，得换或自训。

### 路线 B：服务端推理（唯一能变成真防线的路）

依赖形态是 DJL + ONNX Runtime（或 TensorFlow Java、OpenCV DNN）。要解决的问题按顺序是：

1. **模型文件**：仓库里没有任何 `.onnx`。ONNX 要从模型的**原始权重**（Keras `.h5` / SavedModel）经
   `tf2onnx` 转换，**不能**从 nsfwjs 的 TF.js base64 产物反推。本机有 Python 3.13 + pip，转换链路可行，
   但需要先把原始模型离线取到。依赖坐标与版本本次未能联网核实（`search.maven.org` 查询返回空、
   `central.sonatype.com` 页面为 JS 渲染），落地时以官方仓库实际可用版本为准。
2. **接法**：在 `im-file` 的上传链路里（`FileServiceImpl` 落库前）加一道 SPI 校验，命中就抛
   `ResultCode.FILE_CONTENT_UNSAFE(7010)`——前端已有该错误码的文案，`ChatWindow` 的失败分支会自动呈现，**前端可零改动**。
3. **复用现成的东西**：`im.moderation.thresholds`（再加一类 key 即可）、审计 logger `com.im.moderation`、
   `MODERATION/moderation.log` 的字段格式。上报体 `ModerationReportReq` 可以顺势废弃。
4. **成本**：推理跑在上传关键路径上，要评估线程池/显存与图片解码开销；Java 侧还需带原生运行时（ONNX Runtime 的 JNI 包）。

### 路线 C：第三方内容安全 API（阿里云 / 腾讯云 / 网易易盾）

准确率和「血腥暴力」覆盖度最好，且是**服务端判定**（天然不可绕过）。但本项目主打内网离线部署，
公有云 API 需要外网出口与 AK/SK，与部署前提冲突；`md/待开发功能.txt` 第 1 条里的「云厂商内容安全 API」
就是指这条。**能出外网的部署形态**下，它比路线 B 更省事——建议在 SPI 里做成可插拔实现，与路线 B 共用一个接口。

> 路线 B / C 都不改动已落的「策略下发 + 拒发 + 审计」骨架：它们换的是判定发生的位置，
> 阈值配置、审计格式、错误码 7010 均可原样复用。路线 A 已经把「多一路模型」这条路跑通了，
> 服务端那侧一个字段都没动，将来把推理搬到服务端时同样不需要改前端下发结构。

## 十一、已知局限与排查

| 局限 | 影响 | 处理建议 |
|---|---|---|
| **客户端判定可绕过** | 直接调上传接口就能把违规图发上去 | 需要真防线走路线 B/C |
| **血腥 / 暴力默认关着** | 模型 83MB 不入库；没投放就整个检测器停用（只撞一次 404 就记死） | 要开就按第九节投放模型 + 配 `Violent` 阈值 |
| 血腥 / 暴力只有二分类 | 血迹与斗殴都算 `Violent`，分不开；卡通打斗它看不懂 | 要分开处置就得换或自训模型 |
| 开了之后每张图多等 1.2~2.3s | 同步卡在发送前；页面没 SharedArrayBuffer 时只能单线程 wasm | 不想付这个代价就别配 `Violent`；提速要开跨源隔离，代价见第九节 |
| 桌面端（file://）未验 | Electron 用 `loadFile`，模型与 wasm 的相对地址算得对但没实跑过 | 上桌面端前先验一遍，或把 dist 交给本地 HTTP 服务 |
| 真实照片精度未验收 | 合成图也能给到 0.66~0.73，阈值只能靠日志分布校 | 别把 `Violent` 压到 0.75 以下，先观察 |
| GIF 只判首帧 | 动图后续帧可夹带违规内容 | 可接受；严格场景在服务端逐帧判（路线 B） |
| 透明 PNG 铺白底再判 | 与肉眼合成结果一致，但与某些在线服务的判法可能不同 | 无需处理 |
| 大图内存 | 已先缩到 224×224 再喂模型，不再产生原图尺寸的像素张量 | 无需处理 |
| 低端设备 / WebGL 不可用 | tfjs 会自动回落 CPU 后端，慢但能跑；整条链路异常时**放行** | 已知取舍：宁可漏放也不卡发送 |
| 模型 120s 空闲后释放 | 下一次发图要重新加载（内网局域网很快） | 别把这个时间调到极小，重建成本比 OCR 高 |
| 服务器时间线里只有「命中」 | 看不到「判过但通过」的量，无法算精度 | 有意为之：全量落盘会把审计变成隐私负担 |

常见故障：

| 症状 | 大概率原因 | 怎么确认 |
|---|---|---|
| 改了阈值没效果 | 后端没重启；或前端内置默认值正在兜底（策略接口 401/500） | 直接 `GET /api/file/moderation/policy` 看返回的 `thresholds` |
| 任何图片都不被拦 | `im.moderation.enabled=false`；或 `thresholds` 被清空/全为无效值 | 同上；再看 `im-server.log` 有无「阈值配置项无效，已跳过」 |
| 命中了但审计文件没内容 | `audit-enabled=false`；或日志根目录不可写（logback 静默丢） | 看控制台有没有 `[审核命中]`（dev 有镜像）；确认 `im.log.home` 目录可写 |
| 上报返回 400「业务场景不是图片类型」 | 新场景的 `scene` 没在 `FileBizType` 注册，或传了 `chat_file` | 核对前端传的 `scene` 与 `FileBizType` code |
| 页面报 `Model 'MobileNetV2' was not found in the provided models registry` | `load()` 没把 `modelDefinitions` 传进去（改成了 `import from 'nsfwjs'` 又缺 shard 文件） | 确认 `utils/nsfw.js` 用的是 `nsfwjs/core` + `modelDefinitions: [MobileNetV2Model]` |
| 配了 `Violent` 但血腥图没被拦 | 模型没投放（前端 404 后记死）；或页面缓存的还是旧策略（10 分钟 TTL） | 浏览器 Network 看 `/models/violence/model.onnx` 是不是 404；`GET /api/file/moderation/policy` 看返回里有没有 `Violent` |
| 控制台报 `no available backend found` | wasm 被拷进 `public/` 后用字符串路径指过去了（Vite 对 public 的 `?import` 回 500） | 按第九节改成 `?url` + `env.wasm.wasmPaths` |
| 控制台报 `no available execution provider` / 拉了 27MB 的 jsep | 入口用了 `onnxruntime-web` 默认入口（带 WebGPU EP） | 改成 `onnxruntime-web/wasm` 子入口 |

★ **本轮刻意不验的两件事**（不是漏做）：

1. **破冰不接 LLM** 是设计决定（可控、可审、零延迟），所以不会出现「AI 生成开场白」的入口，看到的全是 `im_icebreaker` 里的字典文案。
2. **`fileId` 即凭证**：照片与动态附图的 `bizType` 落在 `FileBizType.isPublic()` 里，`/api/file/download/{id}` **不带登录头就能取到图**（前端用 blob 渲染，所以 `<img>` 裸地址能出图是预期，不是漏洞）。真正要验的是**待审核 / 被驳回的照片行根本不进响应**——见 §1.4 与 §10.6。

## 1. f1 交友资料卡（`im_user_profile`）

入口：`我的` → `Profile.vue` 页面里的「交友资料」卡片（与顶部「编辑资料」是**两次独立保存**，字段校验与限流配额都不同）。

- [ ] 1.1 填昵称以外的画像字段（生日、城市、学历、收入、婚恋状况、交友目的、简介），点「保存交友资料」→ 提示「交友资料已更新」，刷新页面仍在。
- [ ] 1.2 **存生日不存年龄**：资料里只填出生日期；关掉「展示年龄」后，别人那一行**直接不渲染**（服务端返 `age = null`，★ 不是显示 0 岁也不是打星），本人仍看得到。
- [ ] 1.3 「我的定位」行点「重新定位」→ 浏览器授权后文案变成 `已定位：<大致位置>`；点「清除定位」→ 提示保存后将清除定位。
- [ ] 1.4 卡片顶部显示的**完资料度分数**随填写进度上升（照片占 30 分、标签按真实张数计），填满后为满分。
- [ ] 1.5 用 bob 的窗口打开 alice 的资料卡（`UserProfile.vue`）：看到的是脱敏后的卡片，**页面源码与 Network 响应里不应出现经纬度字段**，距离只显示模糊档位。

失败先看：`PUT /api/dating/profile` 是否 400（字段校验）、限流 20 次/分钟（`dating.profile.save`）。

## 5. f5 滑动匹配与配对（`im_match_like` / `im_match_pair`）

入口：`发现` → 「滑动匹配」tab。卡片按钮：**跳过 / 看资料 / 喜欢**。

- [ ] 5.1 点「喜欢」→ 卡片飞走，下一张顶上；**同一人再滑一次不会多出记录**（`uk_from_to` 幂等，重复滑是 UPDATE）。
- [ ] 5.2 没有 `friend:apply` 权限的账号：只留「看资料」，**不出现点不动的「喜欢」按钮**（不是灰着让人反复试）。
- [ ] 5.3 **双向喜欢成对**：alice 喜欢 bob → bob 的「喜欢我的」tab 出现 alice；bob 点「喜欢」→ 两边**同时**收到「配对成功」通知（WS `bizType=match-success`），发起方是 HTTP 返回的弹框「去聊天 / 继续刷」，被触发方是右上角通知，会话列表自动刷出新会话。
- [ ] 5.4 打开这个会话 → 里面有一条系统通知「你们互相喜欢，开始聊天吧」，**入口不同文案不同**（附近的人里成的对会写成「你们在「附近的人」里…」）。
- [ ] 5.5 **配对 ≠ 加好友**：成对后去「好友列表」看，对方不在好友里。
- [ ] 5.6 「我的配对」tab 能看到关系，点进去直接进聊天（用返回的 `conversationId`）。
- [ ] 5.7 「解除配对」（`DELETE /api/dating/match/pairs/{pairId}`）→ 关系消失，但**聊天记录与原来的配对行都留着**；再互相喜欢一次 → 复用同一条配对记录（后台查库只会有一行）。
- [ ] 5.8 已配对的人不再出现在卡池里；被我拉黑的人、低质号也不出现。

## 10. f10 亲密度与火花（`im_intimacy`）

入口：别人的资料卡 `UserProfile.vue` 的「你们的火花」卡片。

- [ ] 10.1 卡片显示 `档位 · 分数 分` + 火花天数 + 进度条 + 四项明细（消息 / 互动 / 共同好友 / 共同群）。
- [ ] 10.2 加分数值：**任一方**发一条消息 **+1**、点赞对方动态 **+2**、评论对方动态 **+3**（成对行用 `a < b` 归一，所以两边看到同一个分）。
- [ ] 10.3 进度条画的是**当前档位内走了多少**，而不是占顶档的比例（按顶档算，绝大多数人会长期停在 3%）；顶档恒为 100%。档位边界：0 初识 / 50 熟悉 / 200 亲近 / 500 默契 / 1000 知心。
- [ ] 10.4 **火花**：两人连续两天互发消息 → `streak_days` 变 2、`max_streak` 同步为 2；断一天后再聊 → `streak_days` 回到 1，但 **`max_streak` 保持历史峰值不清零**。
- [ ] 10.5 卡片旁那句说明会区分「今天或昨天聊过，火花还亮着」与「火花已经熄灭，说一句话就能重新点燃」；熄灭时只是把火花压成次要色，**不隐藏整块**。
- [ ] 10.6 关系行用 `a < b` 归一：两人之间**只有一行**，不存在 (A,B) 与 (B,A) 两条。

## 12. f12 动态互动、转聊天与可见范围

### 12.1 点赞与评论

- [ ] 12.1.1 点赞 → 计数 +1，再点取消 → 计数 -1 且**流水行被物理删除**（不是置标志位）。

- [ ] 12.1.6 评论的闸门是「**你能不能看到这条动态**」而不是好友关系：`friend:apply` 是所有普通用户都有的能力位，不是关系判定。看不到这条的人来评论 → 同样回 **2050**（不透露「它存在而你不在受众里」）。

### 12.2 动态转聊天（不建新表）

- [ ] 12.2.3 来源信息存在消息的 `extra` 里，不建 `im_moment_share` 这类表。
- [ ] 12.2.4 **按收件人重算可见范围**：把一条「仅自己可见」的动态转给别人，对方点开应看到「这条动态不在了」（2050），而不是把内容渲染出来。
- [ ] 12.2.5 从卡片点开时与 Feed 里点开是同一个详情组件，文案与 2050 提示一致。

### 12.3 两层可见性（★ 最容易漏验的一项）

- [ ] 12.3.1 **profile 级**：`Profile.vue` →「动态可见范围」选「三天可见」→ bob 翻 alice 三天前的动态，Feed 与个人主页都看不到，三天内的仍能看到；切「全部可见」后又回来。

- [ ] 12.3.3 单层语义是**交集而不是并集**：把某条改成「仅自己」后，任何白名单里的人都查不到它（后台仍能查到）。
- [ ] 12.3.4 「仅好友」：配对但未加好友的对象看不到。

## 13. f13 后台管理三屏

入口：`im-admin-ui` 侧边栏三条独立菜单（**不是一个「交友」页做页内判定**）。

### 13.1 交友管理（`system:dating:manage`，`DatingView.vue`）

- [ ] 13.1.1 「资料」tab 能按昵称/城市检索全服资料，包括**已强制隐身**的行；点「强制隐身」→ 该账号立刻从别人的卡池、附近的人里消失，「解除隐身」后回来。
- [ ] 13.1.2 「质量标记」把某号标为低质（`quality_flag=2`）→ 它不再进推荐流；★ 前台用户接口**不能**写这个字段。
- [ ] 13.1.3 「照片审核」tab：待审列表里「通过」→ 用户侧与别人资料卡都能看到图（并重算完资料度）；「驳回」→ 图只对本人可见；「删除」→ 行消失且分数重算。

### 13.2 动态管理（`system:moment:manage`，`MomentsView.vue`）

- [ ] 13.2.1 分页能查到**已下架**和**仅自己可见**的动态（后台是无视角的全状态行）。
- [ ] 13.2.2 下架一条带评论的动态：**Feed 里对所有人（含作者本人）都消失**；但作者看**自己的主页**仍能看到这一条并带「已下架」标（`includeOffline` 只在他看自己主页时才为真，否则他会以为发布失败然后重发），别人看就是空；点详情对非作者一律 2050；后台仍查到 `status=2`。点「恢复」→ Feed 里回来。
- [ ] 13.2.3 「删除」是不可逆的（连带媒体引用）；评论队列同样支持分页 / 下架 / 恢复 / 删除。

## 15. 落库核对（只读 SELECT，由你本人执行）

界面上看对了，再用这几条确认库里是真的（★ MySQL 的写一律由你执行，这些只是查询）：

```sql
-- 一次滑动一行、重复滑不增行
SELECT from_user_id, to_user_id, action, source, updated_at
  FROM im_match_like WHERE deleted = 0 ORDER BY updated_at DESC LIMIT 10;

-- 关系只有一行且 a < b；解除后 status=2 而不是被删
SELECT id, user_a, user_b, status, like_source, conversation_id
  FROM im_match_pair WHERE user_a = 1001 OR user_b = 1001;

-- 一人一天一行
SELECT visitor_id, visited_user_id, visit_date, view_type
  FROM im_profile_visit WHERE visited_user_id = 1001 ORDER BY visit_date DESC LIMIT 10;

-- 火花断了但峰值还在
SELECT score, level, streak_days, max_streak, last_active_date
  FROM im_intimacy WHERE user_a = 1001 AND user_b = 1002;

-- 待审照片没有流到对外接口（后台视角：应有 audit_status<>1 的行存在，而用户侧响应里没有）
SELECT id, user_id, is_main, audit_status FROM im_user_photo WHERE user_id = 1001;

-- 冗余计数与流水是否一致（偏差可由后台重算拉齐）
SELECT m.id, m.like_count, m.comment_count, m.media_count, m.visibility, m.status
  FROM im_moment m WHERE m.user_id = 1001 ORDER BY m.created_at DESC LIMIT 10;
```

## 16. 症状 → 原因速查

| 看到什么 | 先查什么 |
|---|---|
| 所有 `/api/dating/**` 都 **1007「功能暂时不可用」** | 交友 16 张表没建全，或模块没装配（★ 交友域**不做优雅降级**，1007 就是「缺基础设施」这一种含义） |
| 只有后台三屏 1003，且 admin 也不例外 | 权限点 132/133/134 没种进去，或种了没清 `im:auth:perm:*` / `im:auth:role:*` |
| 接口 200、页面白屏，Console 报 `xxx is not a function` | 前端某个 api 模块漏了 re-export（本批踩过一次 `listTags`）；先按 Network 是否发出请求分诊：没发出 = JS 运行时炸，发出了 = 数据渲染问题 |
| 后台某屏 Network 里根本没发请求 | 该 Controller 没进 Knife4j 的 `pathsToMatch`（`/api/admin/dating/dict` 前缀是手工补的那条） |
| 某条接口在 Swagger 里整个消失 | 同上，`pathsToMatch` 是**静默丢弃**，不报错 |
| 明明有权限却处处 1003，看着像登录坏了 | 权限缓存旧快照，清缓存 |
| 附近的人一直空 | 分两种：2042 = 你自己没定位 / 定位超 7 天；空列表 = 真没人，换半径 |
| 图片 `<img>` 裸地址能打开 | 预期。`isPublic()` 的类型不做会话校验；要验的是待审行的 ID 不外泄（§2.5） |

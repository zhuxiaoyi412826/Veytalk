# 语音接收与转文字 — 实现解析与复用指南

> 适用项目：spring-boot-duomokuia（IM 即时通讯系统）
> 覆盖四条链路：**语音的录制发送 → 接收播放 → 语音消息转文字（事后） → 录音滑动转文字（微信式，事中）**，
> 每条都附关键代码与文件位置，方便学习理解和以后直接复用。

---

## 0. 链路总览

```
┌────────────── 发送端 ──────────────┐          ┌────────────── 接收端 ──────────────┐
│ 按住说话 (HoldTalkButton.vue)       │          │ WebSocket 推送 / 离线拉取           │
│   ├─ 手指区判定: 松手=语音 左滑=取消 │          │   └─ 消息列表追加 msgType=4 气泡    │
│   └─ 右滑=转文字 → /ai/interview/asr│          │ MessageBubble.vue 语音条            │
│ 录音 (utils/audioRec.js)            │          │   ├─ 宽度随时长变化                 │
│   └─ 16k 单声道 16bit WAV 自编码    │          │   └─ mediaUrl 懒加载 → new Audio() │
│ 上传 (im-file) + 发消息 (HTTP/WS)   │          │ 长按「转文字」(事后)                │
│ POST /message/send (content=fileId) │          │   └─ POST /message/{id}/to-text    │
└─────────────────────────────────────┘          └─────────────────────────────────────┘

                        两条转文字链路殊途同归，最终都收敛到同一个 ASR 出口：
   /message/{id}/to-text ──► MessageServiceImpl.toText ──► SpeechToTextSpi (取已上传文件) ─┐
                                                                                           ├─► AudioService.transcribe
   /ai/interview/asr ──────► InterviewController.asr (multipart 直传音频字节) ────────────┘    └─► 阿里云百炼 qwen3-asr-flash
```

两条链路的本质区别：

| | 语音消息「转文字」（事后） | 录音「滑动转文字」（事中，微信式） |
|---|---|---|
| 时机 | 对方发来的语音，点开长按再转 | 自己按住说话，还没发送，右滑直接转 |
| 音频来源 | 已入库文件，服务端按 `fileId` 直读存储字节 | 前端刚录好的 WAV Blob，multipart 直传 |
| 接口 | `POST /api/message/{id}/to-text` | `POST /ai/interview/asr` |
| 结果去向 | 只贴在**本端**气泡下方（不落库、不同步给对方） | 作为**文本消息**正式发出 |
| 前端入口 | ChatWindow 长按菜单 | HoldTalkButton 手势 + `onTalkResult({action})` |

## 1. 语音消息的数据格式（理解一切的前提）

消息类型定义在 [MsgType.java](file:///d:/daima/Lianshi/spring-boot-duomokuia/im-common/src/main/java/com/im/common/enums/MsgType.java)：

```java

语音消息落库时：`content` 存**文件 ID**，`extra`（MessageExtra）存 `fileId / fileUrl / duration / fileName / contentType / ext` 等元数据。

关键设计：**客户端上报的附件元数据一律被服务端覆盖**（防止把别人的 fileId 填进来越权），回填逻辑在
[AttachmentContentHandler.java](file:///d:/daima/Lianshi/spring-boot-duomokuia/im-message/src/main/java/com/im/message/handler/AttachmentContentHandler.java)：

```java
extra.setFileName(sensitiveWordFilter.mask(file.getOriginalName()));
extra.setFileSize(file.getSize());
extra.setContentType(file.getContentType());
extra.setExt(TextUtil.isBlank(file.getExt()) ? TextUtil.extension(file.getOriginalName()) : file.getExt());
extra.setDuration(file.getDuration());
// 存后端受控地址而不是预签名直链：受控地址长期有效，且访问时会再校验一次会话成员身份
extra.setFileUrl(fileSpi.accessUrl(fileId));

cmd.setContent(String.valueOf(fileId));
```

> ★ 复用要点：`fileUrl` 存的是**受控地址**（要登录态 + 成员身份校验），不是公网直链。
> 这决定了后文「播放要懒加载换 ticket」「转文字要按 fileId 直读存储」两处设计。

### 2.2 录音编码：为什么不用 MediaRecorder

[audioRec.js](file:///d:/daima/Lianshi/spring-boot-duomokuia/im-ui/src/utils/audioRec.js)：

```js
/**
 * 为什么不用 MediaRecorder：它输出的容器/编码随内核（webm/opus/mp4…），
 * 国产浏览器行为不齐，而后端 ASR 需要我们声明格式；自己采 PCM、
 * 自己写 44 字节 WAV 头，模型侧 `format:"wav"` 才是永远成立的。
 *
 * 三层结构，各层都能单独测：
 *   createMicSource   麦克风 → 帧流（Float32Array 单声道 + 采样率）
 *   encodeWav16k      帧流列表 → 16k/mono/16bit WAV Blob
 *   createSpeechRecorder  按住说话/一段录音的启停封装（前两层拼起来）
 */
const TARGET_RATE = 16000

// AudioWorklet 只透传首声道 PCM 帧，重采样与编码都在主线程做
const WORKLET_SRC = `class PcmPassthrough extends AudioWorkletProcessor {
  process(inputs) {
    const ch = inputs[0] && inputs[0][0]
    if (ch) { this.port.postMessage(ch.slice(0)) }
    return true
  }
}
registerProcessor('pcm-passthrough', PcmPassthrough)`
```

### 3.2 播放：受控地址必须换凭证

```js
async function toggleVoice() {
  if (playing.value) { audio?.pause(); playing.value = false; return }
  if (!audio) {
    // 语音地址是受控地址，必须带登录头取回 blob 才能交给 Audio 播放，
    // 直接塞 <audio src> 会因为拿不到凭证而失败
    const url = mediaUrl(extra.value.fileUrl)
    if (!url) {
      // mediaUrl 是懒加载的：第一次调用触发拉取并返回空串，稍后再点就有了
      ElMessage.info('语音加载中，请稍候再点一次')
      return
    }
    audio = new Audio(url)
    audio.addEventListener('ended', () => { playing.value = false })
    audio.addEventListener('error', () => { playing.value = false; ElMessage.error('语音播放失败') })
  }
  try {
    await audio.play()
    playing.value = true
  } catch {
    // 浏览器可能因为缺少用户手势或格式不支持而拒绝播放
    playing.value = false
    ElMessage.error('语音播放失败，可能是不支持的音频格式')
  }
}
```

> ★ 复用要点：凡是「受控媒体地址」（图片/语音/文件通用，`utils/media.js` 的 `mediaUrl`），
> 都是懒加载 + 一次性 ticket 换临时可播 URL 的模式。第一次调用只触发拉取、返回空串，
> 调用方必须容忍「再点一次才有」的中间态。

### 4.3 服务层：校验 → SPI → 空结果分开报错

[MessageServiceImpl.java](file:///d:/daima/Lianshi/spring-boot-duomokuia/im-message/src/main/java/com/im/message/service/impl/MessageServiceImpl.java)：

@Override
public String toText(Long userId, Long messageId) {
    Message message = messageMapper.selectById(messageId);
    BusinessException.throwIf(message == null || message.isRecalledNow(), ResultCode.MESSAGE_NOT_FOUND);
    // 只有会话成员能转别人的语音
    BusinessException.throwUnless(conversationSpi.isMember(message.getConversationId(), userId),
            ResultCode.CONVERSATION_NO_PERMISSION);
    // 只有语音消息能转（msgType 必须 = 4）
    BusinessException.throwIf(MsgType.of(message.getMsgType()) != MsgType.VOICE,
            ResultCode.MESSAGE_TO_TEXT_UNSUPPORTED);
    // 总开关关闭或没有 SPI 实现 → 优雅降级，不冒充真实结果
    SpeechToTextSpi spi = imProperties.getIntelligence().isEnabled() ? speechToTextSpiProvider.getIfAvailable() : null;
    if (spi == null || !spi.available()) {
        throw new BusinessException(ResultCode.MESSAGE_TO_TEXT_UNAVAILABLE);
    }
    MessageExtra extra = message.getExtra();
    // 优先按 fileId 识别：实现方能直接走 FileStorageSpi 读字节，不必拿受控地址再发一次
    // 带登录态的 http 回环请求（预签名地址还有时效，取到可能已过期）
    String text = spi.toText(extra == null ? null : extra.getFileId(),
            extra == null ? null : extra.getFileUrl(),
            extra == null ? null : extra.getDuration());
    if (TextUtil.isBlank(text)) {
        // 识别为空是「没听清/静音」，与「服务未配置」分开：前者提示重说，后者才提示配置
        throw new BusinessException(ResultCode.MESSAGE_TO_TEXT_EMPTY);
    }
    return text;
}
```

### 4.4 SPI 契约：为什么多给一个 fileId 入口

[SpeechToTextSpi.java](file:///d:/daima/Lianshi/spring-boot-duomokuia/im-common/src/main/java/com/im/common/spi/SpeechToTextSpi.java)：

```java
public interface SpeechToTextSpi {

    /** 当前是否具备可用的识别能力（厂商凭据已配置、服务可达）。为假时调用方直接降级 */
    boolean available();

    String toText(String audioUrl, Integer durationSeconds);

    /**
     * 带文件 ID 的识别入口，实现方优先用这一条。
     *
     * toText(String, Integer) 只给了地址，而地址要么是受控地址（要登录态，
     * 服务端自己 http 回环去取既绕又过不了鉴权）、要么是预签名直链（有时效，SPI 实现
     * 拿到时可能已经过期）。给 fileId 就能直接走 FileStorageSpi 读字节，
     * MinIO 与本地磁盘两种存储都不需要经公网。
     */
    default String toText(Long fileId, String audioUrl, Integer durationSeconds) {
        return toText(audioUrl, durationSeconds);   // 默认委托旧签名，兼容内置桩
    }
}
```

### 4.6 ASR 出口：qwen3-asr-flash（SDK-free）

[AudioService.java](file:///d:/daima/Lianshi/spring-boot-duomokuia/im-ai/src/main/java/com/im/ai/service/AudioService.java) —— 全项目唯一的语音识别出口：

```java
public String transcribe(byte[] audioBytes, String format) {
    requireAvailable();                                   // 没配 ALI_BABA_API_KEY 直接拒
    if (audioBytes == null || audioBytes.length == 0) {
        throw new BusinessException(ResultCode.AI_ASR_FAILED.getCode(), "音频为空，请重新录制");
    }
    if (audioBytes.length > MAX_WAV_BYTES) {              // 4MB 上限
        throw new BusinessException(ResultCode.AI_ASR_FAILED.getCode(), "音频过大（上限 4MB），请缩短录音时长");
    }

    String dataUri = "data:;base64," + Base64.getEncoder().encodeToString(audioBytes);

    // ★ content 里只能有 input_audio 这一项，不能再塞 text：qwen3-asr-flash 是 dedicated task
    // 模型，实测多带一条转写指令会被厂商直接拒 —— 400
    // "InternalError.Algo.InvalidParameter: The dedicated task `asr` corresponding to the
    // current service does not support this input."
    List<Map<String, Object>> content = new ArrayList<>();
    content.add(Map.of("type", "input_audio",
            "input_audio", Map.of("data", dataUri, "format", audioFormat)));

    Map<String, Object> body = new LinkedHashMap<>();
    body.put("model", audio.getAsrModel());               // 默认 qwen3-asr-flash
    body.put("messages", List.of(Map.of("role", "user", "content", content)));

    // JDK HttpClient 直连 DashScope compatible-mode /v1/chat/completions，不引厂商 SDK
    HttpRequest request = HttpRequest.newBuilder()
            .uri(chatCompletionsUri())
            .header("Authorization", "Bearer " + properties.getApiKey())
            .timeout(audio.getAsrTimeout())
            .POST(HttpRequest.BodyPublishers.ofString(jsonUtil.toJson(body)))
            .build();

    String responseBody = send(request, ResultCode.AI_ASR_FAILED, "语音转文字");
    JsonNode node = jsonUtil.mapper().readTree(responseBody);
    JsonNode message = node.at("/choices/0/message/content");
    return stripFences(message.asText());                 // 剥掉模型偶尔包裹的 ``` 围栏
}
```

## 5. 录音「滑动转文字」直接发送（事中，微信式）

### 5.1 前端：未上传的 WAV 直接调 ASR，成功后发文本消息

[ChatWindow.vue](file:///d:/daima/Lianshi/spring-boot-duomokuia/im-ui/src/views/ChatWindow.vue)：

```js
import { transcribeAudio } from '@/api/ai'

/**
 * 录音右滑「转文字」：把刚录的 WAV 直接调 ASR 转写，成功即作为文本消息发出。
 * 复用上传态 uploading 占住按钮（busy），转写期间不让连按。
 * 识别为空 → 提示「没有识别到文字」；服务未配置/失败 → 弹后端原因（与微信一致，不静默吞）。
 */
async function transcribeVoiceToTextAndSend(blob) {
  if (uploading.value) return
  uploading.value = true
  try {
    const text = ((await transcribeAudio(blob)) || '').trim()
    if (!text) {
      ElMessage.warning('没有识别到文字，请确认是否说清楚了')
      return
    }
    await chat.send(props.conversationId, { msgType: 1, content: text })  // 发的是普通文本消息
  } catch (error) {
    if (isBusinessError(error)) ElMessage.error(sendErrorText(error))
    else ElMessage.error(error?.message || '转文字失败，请稍后重试')
  } finally {
    uploading.value = false
  }
}
```

### 5.2 API 层：multipart 直传（绕过 axios 让 boundary 自动生成）

[ai.js](file:///d:/daima/Lianshi/spring-boot-duomokuia/im-ui/src/api/ai.js)：

```js
/**
 * 入参是 utils/audioRec.js 编码的 16k 单声道 WAV Blob；用 fetch 不用 axios：
 * FormData 的 multipart boundary 交给浏览器自己填，鉴权头与主管线同一套。
 */
export async function transcribeAudio(blob) {
  const form = new FormData()
  form.append('file', blob, 'speech.wav')
  const response = await fetch(`${apiBaseURL()}/ai/interview/asr`, {
    method: 'POST',
    headers: { [getTokenName()]: getToken() || '' },
    body: form
  })
  const body = await response.json().catch(() => ({}))
  if (body.code !== 200) {
    throw new Error(body.message || `语音转写失败（${body.code ?? response.status}）`)
  }
  return body.data?.text ?? ''
}
```

### 5.3 后端入口：与面试「按住说话」共用一个端点

[InterviewController.java](file:///d:/daima/Lianshi/spring-boot-duomokuia/im-ai/src/main/java/com/im/ai/controller/InterviewController.java)：

```java
@RateLimit(count = 30, seconds = 60, dimension = RateLimit.Dimension.USER, key = "ai.interview.asr")
@PostMapping("/asr")
public Result<Map<String, String>> asr(@RequestPart("file") MultipartFile file) {
    String contentType = file.getContentType();
    if (contentType == null || !contentType.startsWith("audio/")) {
        throw new BusinessException(ResultCode.AI_ASR_FAILED.getCode(), "只接受音频文件（16k 单声道 WAV）");
    }
    byte[] bytes = file.getBytes();
    return Result.ok(Map.of("text", audioService.transcribe(bytes)));   // 前端自录必是 wav
}
```

> ★ 复用要点：这条链路**不需要先上传文件再转**——WAV Blob 直接 multipart 上云转写，
> 识别成功后作为文本消息发出，音频本身不落盘、不留痕。

## 9. 复用清单与避坑笔记

以后新项目要搬这套能力时，按下面的顺序抄，坑都已标注：

1. **数据格式先定**：`content=文件ID`、`extra={fileId, fileUrl(受控), duration}`，附件元数据一律服务端权威回填（防 fileId 越权）。
2. **录音层直接抄 audioRec.js 三层结构**。别用 MediaRecorder——容器随内核，后端没法可靠声明 `format`。
3. **手势层抄 HoldTalkButton**，三个必带护栏：
   - `pointercancel` 一律丢弃不发送（否则移动端第二次起会误发）；
   - 秒表 tick 加 `if (!pressing || !startedAt)` 护栏（否则 `Date.now()-0` 会 1 秒自动发）；
   - `session` 会话号作废上一段异步收尾（否则快速连按会串段）。
4. **ASR 只留一个出口**（AudioService.transcribe 的角色），两条业务链路（事后转写 / 事中直转）都收敛到它，
   换厂商只改这一处；接法遵循「im-common 定 SPI 契约 + 能力模块出 @Primary 实现 + 消费方 ObjectProvider 取」。
5. **qwen3-asr-flash 是 dedicated task**：content 里只能有 `input_audio` 一项，多塞一条文字指令厂商直接 400。
6. **服务端取音频走 fileId → FileStorageSpi 直读**，不要拿受控地址做 http 回环（过不了鉴权），也不要依赖预签名直链（会过期）。
7. **「识别为空」与「服务未配置」必须两个错误码**（5016 vs 5014），否则静音语音会误导用户「服务没配」。
8. **转文字结果默认只存本端内存**（message.transcript），不落库不同步——与微信一致；要改成持久/双向同步时再动 toText 的返回语义。
9. 全链路体积上限 **4MB**、录音上限 60s、转文字限流 60 次/用户、ASR 限流 30 次/分钟——参数都在各自常量/注解里，按需调。

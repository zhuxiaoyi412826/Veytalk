# 项目知识点全景（按重要性从高到低）

> 一句话定位：**Spring Boot 4 + JDK 21 的多模块即时通讯（IM）系统**，含 Web 三站 + Electron/Tauri/安卓多端客户端，Docker Compose 全栈部署 + GitHub Actions 自动化发布。
> 分级口径：**P0 = 不懂就改不动这个项目；P1 = 跑通生产环境必须懂；P2 = 某个功能域的核心；P3 = 周边但踩过坑；P4 = 工具性知识**。
> 版本与模块清单均按 `pom.xml`（im-parent 1.1.0）与仓库实际目录核对过，最后核对日期 **2026-11-24**（本轮同步：库表 43 → **67 张**、交友域 16 表上线并新增 §17，逐列解析见《[数据库表解析](数据库表解析.md)》§十七）。

## P0 · 命脉级（架构与主链路，动哪都是全局影响）

### 1. Java 21 与 Maven 多模块工程

| 知识点 | 在本项目中的应用 | 备注 / 踩坑 |
|---|---|---|
| JDK 21（LTS） | 全后端语言基线，`<java.version>21</java.version>` | 基础镜像必须 `eclipse-temurin:21-jre`（Ubuntu 底，自带 bash） |
| Maven 聚合工程 | 父 pom `im-parent` + **14 个 module**（13 个后端含 im-common / im-bootstrap，加 1 个独立 Agent；im-ui / im-admin-ui / im-website 三个前端工程不走 Maven），共 **15 个 pom** | ★ 升版必须同步 **16 处**：根 `<version>` + `<im.version>` 属性 + 14 个子模块 `<parent><version>`；漏改本地测不出（`~/.m2` 缓存），CI 干净环境必报 `Non-resolvable parent POM` |
| dependencyManagement 统一版本 | Sa-Token / MyBatis-Plus / MinIO 等全部在父 pom 管版本 | `mvn versions:set` 是升版正路，但不认识自定义属性 `im.version`，要手工补 |
| finalName 产物命名 | `im-bootstrap` 打出的 fat jar 固定叫 `im-server.jar`（不带版本号） | Dockerfile / scp / update.sh 全依赖这个名字 |

**模块地图**（星型结构，业务模块只依赖 `im-common`，彼此无直接依赖）：

```
im-common（公共层：API 返回体/异常/常量/SPI 接口/安全/工具）
 ├─ im-user        认证与用户（验证码登录、JWT、RBAC）+ 交友资料/照片墙/标签/破冰字典
 ├─ im-friend      好友关系（申请/管理/黑名单）+ 匹配四表/访客/亲密度/动态 Feed
 ├─ im-conversation会话（单聊/群聊/置顶/免打扰）
 ├─ im-message     消息（收发/撤回/已读回执/离线消息/分页历史）
 ├─ im-group       群组
 ├─ im-file        文件（MinIO/本地双实现 + 访问票据）
 ├─ im-websocket   实时通道（心跳/重连/多端踢线）
 ├─ im-ai          AI（面试/语音转文字/知识库）
 ├─ im-remote      远程控制（服务端侧）
 ├─ im-live        直播
 ├─ im-admin       管理后台（含客户端版本管理）
 ├─ im-bootstrap   启动装配（唯一打 fat jar 的模块）
 └─ im-remote-agent 被控端 Agent（独立 fat jar，不被 bootstrap 依赖）
```

### 2. Spring Boot 4 生态

| 知识点 | 应用 | 踩坑 |
|---|---|---|
| Spring Boot **4.0.8**（parent） |  whole 应用骨架、自动装配、starter 体系 | Boot 4 很新：MyBatis-Plus / Sa-Token / Knife4j 都要用**专门的 boot4 启动器**，老 starter 直接挂 |
| 多 profile 配置体系 | `application.yml`（默认）/ `-dev` / `-prod` + 外挂 `app/extra/application-prod-extra.yml` | 配置优先级：命令行 > env > yml；prod 的 CORS Origin 列表在 extra 文件里，换域名必须重跑 bootstrap 渲染 |
| SPI 接口解耦 | 跨模块调用走 `im-common/spi` 的接口 + `ObjectProvider` 注入，模块缺席也能降级启动 | 加跨模块功能先想"该不该开 SPI 口"，别直接引对方 bean |
| 分层规范 | 每模块内 controller / service(+impl) / mapper / entity / dto(req·vo·po) / convert | 全项目一致，看一个模块就会看所有模块 |
| Actuator 健康检查 | 管理端口 8081 只绑 127.0.0.1，`/actuator/health` 是容器 healthcheck 的依据 | ★ `MailHealthIndicator` 不受 `test-connection:false` 控制，占位符邮箱凭证 → 535 → 聚合 DOWN → 容器**永远 unhealthy**。workaround：`conf/im.env` 加 `MANAGEMENT_HEALTH_MAIL_ENABLED=false` |
| Lombok / configuration-processor | 父 pom 统一声明（provided） | Lombok 只声明在 im-common 会让下游模块 `package lombok does not exist`，必须父 pom 全覆盖 |

### 3. 鉴权体系：Sa-Token（不是 Spring Security）

| 知识点 | 应用 | 备注 |
|---|---|---|
| Sa-Token 1.46.0 | 登录态、踢线、多端互斥全走 `StpUtil`（`login(userId, device)`） | 同端互斥、多端共存即基于 device 类型实现 |
| JWT 混合模式 | `sa-token-jwt`：token 可离线验签 + Redis 保留会话索引 | |
| 全局拦截 + 白名单 | `SaTokenConfigure` 的 `SaRouter.match("/api/**")`；匿名接口（验证码、`/api/release/**` 等）在白名单 | 新开公开接口忘加白名单 = 401 |
| 注解式权限（RBAC） | `@SaCheckLogin` / `@SaCheckPermission`，权限点常量在 `ImConstants`（如 `system:release`） | 权限缓存在 Redis `im:auth:perm:<userId>`，TTL 30 分钟且**登录不刷新**——动过 `im_permission` 表必须跑 `clear-perm-cache.sh`，否则菜单还是旧的 |
| spring-security-crypto 7.0.7 | **只用它的 BCrypt/Argon2 哈希**，没有 Spring Security 过滤器链 | 面试高频误区：pom 里有 spring-security 字样 ≠ 用了 Spring Security |

### 4. 数据层：MySQL 8 + MyBatis-Plus + Redis

| 知识点 | 应用 | 踩坑 |
|---|---|---|
| MySQL 8.0 | 主库 `im_db`，`sql/im_schema.sql`（结构，**开头有 67 条 DROP TABLE，共 67 张表**）+ `im_data.sql`（种子数据） | 建库脚本用完必须 `guard-sql-init.sh` 挪走——卷被重建时静默清库 |
| MyBatis-Plus 3.5.17 | 通用 CRUD、分页插件（3.5.9+ 拆分，需显式引 `mybatis-plus-jsqlparser`）、逻辑删除、AuditEntity 自动填充 | |
| utf8mb4 全链路 | 连接串与导入一律 `--default-character-set=utf8mb4` | 管道方式导 SQL 中文/emoji 静默变 `?`，必须走 `scripts/import-sql.sh`（cp 进容器再 source） |
| Redis 7 | 会话、验证码、在线状态、权限缓存；键统一从 `RedisKeys` 常量取（`PREFIX="im:"`） | 键名不许凭记忆拼；`im:auth:perm:*` / `im:auth:role:*` 是关键两组 |
| 幂等迁移脚本 | 增量变更写 `sql/migration_*.sql`（预检→变更→验证→回滚段），登记进 `md/SQL变更文档.md` | MySQL 写操作只在生产由人本人执行，工具链拒收含 DROP TABLE 的文件 |
| **自研 SQL 版本管理** | `sql/versions/V<版本>__<名>.sql` 与同名 `U<版本>__<名>.sql` **成对**交付，台账落 `im_schema_migration` + `im_schema_migration_log` 两张表，后台「SQL 版本」页按 checksum 校验后点应用/回滚 | ★ 脚本**一经应用正文就不可再改**（改一个字符 checksum 就漂移，页面报「脚本被篡改」）——已上线脚本里的注释写错也只能留给下个版本订正；只应用当前**最小的待应用版本**（1.0.4 当年是手工 source 的，台账仍记为待应用，要补点一次才对得上）|

### 5. WebSocket 实时通信（IM 的心脏）

- **im-websocket 模块**：连接管理（`WebSocketSessionManager`）、心跳与断线重连、消息分发（dispatch/handler）、离线消息补投、已读回执。
- **多端登录与踢线**：同一 userId 多 device 共存、同端互斥，基于 Sa-Token device 语义。
- **nginx 升级转发**：`/ws` location 要带 `Upgrade/Connection` 头，101 = 握手通。
- ★ **单实例部署限制**：WS 连接管理和定时任务没做分布式协调，横向扩容前必须先解决这一层（记忆库长期约束）。

## P1 · 生产环境必须懂（部署 / 发布 / 反向代理）

### 6. Docker Compose 全栈编排

| 知识点 | 应用 | 踩坑 |
|---|---|---|
| compose 栈 | mysql / redis / nginx / im-server / coturn / live-retention 六服务，`/opt/im-docker`（生产实际路径以服务器为准） | 全部操作**永远不带 `-v`**（`down -v` 连数据卷一起删） |
| bind mount vs 镜像 | 三站前端 `./web/<站>` 挂进 nginx `:ro`——**覆盖即生效不用重启**；后端是**镜像**——必须换 tag 重建 | 这两类生效方式完全相反，是最高频的搞反点（手册 §18） |
| healthcheck | im-server 用 `CMD bash /dev/tcp/127.0.0.1:8081` 探 `/actuator/health` | 不能写 `CMD-SHELL`：dash 不认 `/dev/tcp`，表现是容器永远 unhealthy 且看不出原因 |
| env 分层 | `.env`（compose 层：镜像 tag/密码/域名）+ `conf/im.env`（应用层：功能开关） | `restart` 不重读 env_file，改 `conf/im.env` 必须 `up -d --force-recreate` |
| 非 root 运行 | 镜像内 uid/gid 固定 1000，与宿主机 data 目录 chown 对齐 | uid 不对 → 日志写不进卷且 logback **静默丢**不拦启动 |
| 宿主机二进制服务 | **MinIO 不在 compose 栈里**，是 systemd 服务 | ★ 宿主机重启 → MinIO 没了 → im-server 连 9000 refused → 崩溃循环 unhealthy。必须 `systemctl enable minio` |

### 7. Nginx 反向代理与 HTTPS

- 四个 server 块：im / admin / www / 8088 推流口，由 `im.conf.example` 模板（`__IM_DOMAIN__` 等占位符）经 `bootstrap.sh --force` 渲染生成。
- **SSL**：三个域名各一张证书（别签成一张多 SAN）；换证后必须 reload，浏览器仍旧告警 = 幽灵证（配置没真加载，`nginx -T` 验证）。
- ★ **上游 DNS 缓存坑**：nginx 对 `proxy_pass` 域名只解析一次；im-server 容器重建换 IP 后 nginx 攥着旧 IP → 静态页能开、接口全 502「服务异常」→ `nginx -s reload` 即愈。
- 同源反代：www 站的 `location /api/release`（官网动态下载卡的数据源，没配则**静默回落静态页**，最易误判为"部署没生效"）。
- 直播相关：`secure_link` 回放签名（`base64url(md5("${uri}${expire}${secret}"))` 与 `LiveUrlSigner` 逐字对齐）、DAV 推流 `client_body_temp_path`、location 正则 `{24}` 必须加双引号。

### 8. CI/CD：GitHub Actions + GHCR

| 知识点 | 应用 | 踩坑 |
|---|---|---|
| workflow 结构 | `build-and-package.yml`：meta（解析版本）→ build-jar / build-web / mirror-images → docker-image（buildx 推 GHCR）→ deploy | meta 用 sed 从根 pom 提版本当**镜像 tag**——pom 版本 = 镜像 tag 的绑定关系 |
| 触发规则 | push main / tag `v*` 只构建**不部署**；部署必须手动 Run workflow 勾 `deploy`（默认 false） | tag 触发时镜像 tag 取 tag 名去 `v` 前缀——tag 打错 commit 镜像就错，补救 `git tag -f` + `push -f` |
| environment secrets | deploy job 绑 `environment: production`，`DEPLOY_HOST/USER/SSH_KEY/DIR` 四个 secret | 空 secret 展开成空串 → `ssh "@"` usage error 255；`DEPLOY_DIR` 必须绝对路径（`~` 不展开） |
| SSH 免密部署 | 私钥进 secret、**公钥预先登记** `authorized_keys`；SSH 只是"遥控"通道 | 没登记公钥 → `Permission denied (publickey)`；镜像文件本身从不经 SSH |
| deploy 内部顺序 | ①取 dist ②备 SSH ③前端 tar-over-ssh 覆盖④改 tag→查本机镜像（有则跳过 pull）→`up -d --wait`⑤探活 | ★ **Re-run 永远用原 run 的 commit**，修复后必须重新发起；前端先于后端是有意的中间态设计 |
| 红线 | **换版必换 tag**——覆盖同名 tag = 回滚失去目标 + compose 认不出要重建（`update.sh --rollback` 依赖 GHCR 上每个版本都在） | |
| GHCR 慢的对策 | 国内机拉 ghcr 几百 KB/s；层去重 + 同 tag 跳过 pull 缓解；兜底路线 = jar 直传 + 服务器本地 `docker compose build`（`local/im-server:<版本>`） | 本地 build 的 tag 同样不许覆盖复用 |

### 9. 运维脚本链（Docker/scripts/）

`bootstrap.sh`（渲染配置三件套，`--force` 才覆盖且先备份）· `import-sql.sh`（安全导 SQL）· `clear-perm-cache.sh`（SCAN 删权限缓存）· `update.sh`（换 tag 重建 im-server，先备库，不 healthy 即失败）· `backup.sh`（mysqldump --single-transaction + cron）· `health.sh`（六层体检）· `guard-sql-init.sh`（锁建库脚本防清库）· `im-docker.service`（开机自启，ExecStop 刻意无 `-v`）。

## P2 · 功能域核心知识（按功能模块）

### 10. 音视频通话（WebRTC）

- RTCPeerConnection / SDP 协商 / ICE / STUN / TURN 全套；1:1 与群通话（SFU 改造见 `md/SFU群通话计划.md`）。
- **coturn**：跨公网 NAT 才需要；`TURN_SECRET`（.env）与 `IM_TURN_SECRET`（conf/im.env）两处必须一致；云安全组 TCP **和** UDP 3478 都要放行。
- 配置形态坑：`IM_CALL_STUN_URLS` 写 `stun:`（冒号）不是 `stun=`。
- 视频切换用固定流绑定 + CSS 类切换（项目规范）。

### 11. 直播（im-live）

- 链路：主播 PUT（HTTP-DAV 推流到 8088）→ nginx 落 `data/live/<roomId>/<streamKey>/`（HLS：`index.m3u8 + init_*.mp4 + seg_*.m4s`）→ 观众 443 拉流走 `secure_link` 签名校验。
- 连麦：webm manifest 两条 location；回放保留策略由 `live-retention` Node 容器执行（脚本住在 `electron/`，部署漏拷则容器 Restarting）。
- 三处密钥对帐（.env / im.conf / 后端签名器）是不黑屏的前提。

### 12. 文件存储与传输（im-file）

- **MinIO 8.6.0** Java SDK（bucketExists/makeBucket/putObject/getPresignedObjectUrl...），与本地磁盘双实现按 `im.file.storage` 切换。
- ★ Maven 依赖坑：minio 8.6.0 带的 okhttp 5.1.0 是 Gradle 多平台产物，纯 Maven 必须**显式补 `okhttp-jvm`**，否则编译 `cannot access okhttp3.HttpUrl`、运行 `NoClassDefFoundError`。
- **分片上传** + 断点续传（前端 spark-md5 算 MD5 秒传校验）；**受控访问票据**（hutool-jwt 签发，下载鉴权不走裸 URL）。
- `FileBizType` 枚举管业务类型与允许格式（新增一类就扩展此处：`CLIENT_RELEASE`、交友域的 `DATING_PHOTO` / `MOMENT_IMAGE` / `MOMENT_VIDEO`）。
- ★ `isPublic()` 是一个**安全口径而不是方便口径**：落进这一项的类型，`/api/file/download/{id}` 不再做会话校验（头像、五板块内容、交友图都是「替别人渲染」）。推开它的代价就是**fileId 即凭证**，可见性必须回到业务表里判（照片靠 `audit_status`、动态靠 `visibility`），**不该下发的行连 ID 都不能出现在响应里**。

### 13. 消息内容安全与限流

- 关键词过滤（`md/内容过滤实现详解.md`，词库 `md/txt/关键词屏蔽*.txt`）+ 阿里云图片内容审核（`图片内容审核接入指南.md`，命中记录落 `MODERATION/moderation.log` 追责档）。
- 自研 `@RateLimit(Dimension.IP)` 注解防刷（公开下载接口 `/api/release/download/**` 在用）。

### 14. AI 能力（im-ai）

- 阿里百炼（DashScope）API：面试问答、语音转文字；知识库 = 往 `data/knowledge` 放文件 + restart 重索引。
- key 在 `conf/im.env`（`ALI_BABA_API_KEY`），未配置时接口回"未配置"兜底文案。

### 15. 远程控制（im-remote + im-remote-agent）

- 被控端 Agent 是**独立 fat jar**（不进主应用），设备注册 → 在线 → 会话弹窗授权 → 画面/输入转发 → 文件传输与 cmd 回显。
- 中继默认可用，直连（P2P）只是提速选项；Agent 使用说明见 `md/远程控制Agent使用说明.md`。

### 16. 客户端版本管理（im-admin + 官网）

- 后台上传安装包（走分片上传，bizType=client_release）→ **启用互斥**（同平台仅一个启用版本，service 层事务保证）→ 官网 `onMounted` 拉 `/api/release/list` 动态渲染下载卡，拉不到回落静态数组。
- 公开接口进 Sa-Token 白名单 + IP 限流 + `Content-Disposition` 流式下载。

### 17. 交友与匹配（im-user / im-friend，2026-11-24 十六表上线）

> 逐列设计取舍见《[数据库表解析](数据库表解析.md)》§十七，实现细节与接口清单见《[README详细开发指南](../README详细开发指南.md)》§十九，逐项点验步骤见《[交友功能手动验证清单](交友功能手动验证清单.md)》。这里只留能迁移到别处的知识。

- **LBS 与距离模糊化**：`lng/lat` 存 DECIMAL(10,6)（不用 DOUBLE：浮点做等值/范围比较会抖）+ **6 位 `geohash`**，「附近的人」靠 geohash 前缀匹配圈候选、服务端再算精确距离排序；对外只给模糊距离 + 受 `show_distance` 管，★ **精确坐标永不出接口**（递出去就是可被爬的住址）。`location_time` 超 7 天不采用——位置是会过期的数据，宁可显示「未提供」。
- **推荐流 = 三段拼装**：候选池（`discoverable` + 隐私开关 + 筛选条件）→ 排序（`profile_score` / 活跃 / 同好标签数 / 未曝光优先）→ 去重（`im_match_exposure` 曝光池，超 7 天回池）。★ 排序键名存 `sort_by` 字符串，新增一种排序只加一个分支，不动表结构。
- **滑动配对的正确性靠两个不变式**：`im_match_like` 的 `uk_from_to`（一人对一人只一行，重复滑是 UPDATE，双击不会插出三行也不会误判双向）+ `im_match_pair` 的 **`a < b` 归一**（(A,B) 与 (B,A) 必落同一行，**一个唯一键顶替一把分布式锁**）。这是「用数据模型解决并发」比「用锁解决并发」更值得讲的面试案例。
- **冗余计数 + 唯一键幂等**：`like_count` / `comment_count` / `media_count` 全走 `UPDATE ... = xxx + 1` 配唯一键同时成败，而不是 `SELECT COUNT(*)`（Feed 一页 15 条就是 15 次聚合）。偶发偏差由后台重算拉齐——**这是显式选择最终一致，得写进注释**。
- **一条 UPDATE 里的求值顺序**：`max_streak = GREATEST(max_streak, streak_days)` **必须排在 `streak_days = ...` 之后**（MySQL 单表 SET 从左到右求值，后面的表达式读到的是已改过的值，写反了历史峰值当场丢）。同族手法：钱包的 `balance >= 扣款额` 条件 UPDATE。
- **破冰字典不接 LLM**：`im_icebreaker` 三型文案（1 打招呼 / 2 话题卡 / 3 标签开场白）全部预置 + 后台可维护，`content` 用 `{nickname}`/`{city}`/`{tag}` 占位符服务端现替。★ 理由不是技术不够，是**可控、可审、零延迟**——模型生成的开场白没法后台下线一条错的。
- **后台屏按动作性质拆而不是按业务域拆**：`system:dating:manage`（132）/ `system:moment:manage`（133）/ `system:tag:manage`（134）三个权限点、三个 Controller。★ 因为 Sa-Token 的**类级与方法级 `@SaCheckPermission` 是「两道都要过」而不是覆盖**，写在一个类上就只能给全部端点同一个码——「改字典」与「下架别人的动态」就再也分不给两拨人。
- **码表必须四处对齐**：表注释 / Java 枚举 / Swagger 文案 / 后台前端映射。本批真实事故：`DatingDictView.vue` 把 `type` 的 2 与 3 写反，「标签开场白必须绑标签」的校验落到了话题卡上（后端用枚举没被带偏）——**这类错能逃过编译也逃过构建，只有人对码表时才会发现**。
- **跨模块只留一处接口**：配对成功写 `im_match_pair.conversation_id`（调会话 SPI），**不写 `im_friend`**（配对 ≠ 加好友，两条独立关系，否则解除配对要反过来删好友）；动态转聊天不建表，来源快照放消息 `extra`（`MsgType.MOMENT = 15`）。
- **交友域故意不做降级**：表没建就直接 1007，不像法定文本那样「查不到当没有」。★ 但它同时造了一个难查的假症状：只建表没种权限点时接口回 **1003**（无权限），看上去像登录态坏了而不是库的问题——所以跑完 SQL 必须清 `im:auth:*`。

## SpringBoot 学习路线：完全掌握需要哪些知识

> 口径：**L1 是"用 Boot 写业务"的底线，L2 是"3 年经验"的天花板考点，L3 才是"完全掌握"（能造 starter、能改框架）**。本项目代码覆盖 L1 全部 + L2 大部分，L3 需要读源码补。

### L1 · 必须熟练（日常写业务全靠它们）

- **IOC / DI / Bean**：容器概念、`@Component/@Service/@Autowired`、构造器注入（优于字段注入的原因）、`@Configuration + @Bean`、Bean 作用域与生命周期（`@PostConstruct` → 初始化 → `@PreDestroy`）。
- **配置体系**：`application.yml` 多 profile、`@ConfigurationProperties`（本项目 `configuration-processor` 就是给它补元数据的）、属性优先级（命令行 > 环境变量 > yml——理解了它就理解了 `conf/im.env` 为什么能覆盖镜像内默认值）。
- **Web 层**：`@RestController` 全家桶、参数校验（`@Valid`）、统一返回体与全局异常处理（`@RestControllerAdvice`，对照 im-common 的 api/exception 包）、拦截器 vs 过滤器。
- **数据访问**：Spring JDBC → MyBatis/MyBatis-Plus、事务传播与失效场景（见 4.2）。
- **starter 机制（会用层面）**：依赖了什么就自动配了什么；`spring-boot-starter-*` 与 `spring-boot-dependencies` BOM 的版本管理——本项目 15 个 pom 的 dependencyManagement 就是教科书。
- **打包运行**：fat jar、内嵌容器、`java -jar` 与 JVM 参数（本项目 ENTRYPOINT 的 `$JAVA_OPTS` 拼接顺序、`-XX:MaxRAMPercentage` 配合容器内存 limit）。
- **日志**：SLF4J 门面 + Logback 实现、多 appender 分档（对照 §20 的七档落盘）、MDC traceId。

### L2 · 进阶考点（面试拉开差距的地方）

- **自动装配原理**：`@SpringBootApplication` 三注解拆解 → `AutoConfigurationImportSelector` → `@Conditional` 系列 → 配置文件位置随版本变化（Boot 4 的 `AutoConfiguration.imports`）。**能画出"加一个 starter 到 bean 生效"的完整流程才算过关。**
- **BeanPostProcessor / BeanFactoryPostProcessor**：框架扩展点的主动脉，读懂一个就懂了 Spring 的"插件式"本质。
- **AOP**：动态代理（JDK vs CGLIB）、切面执行顺序——`@Transactional`、`@RateLimit`（本项目自研注解，可直接当案例）、`@SaCheckPermission` 全是 AOP/拦截实现。
- **事件与异步**：`ApplicationEvent`、`@Async` 线程池管理、定时任务（本项目单机 `@Scheduled` 的局限正是分布式调度的引子）。
- **自研 starter**：把 im-common 里某个能力（如 RateLimit）抽成独立 starter + 配置元数据 + `@ConditionalOnProperty` 开关——**从"会用"到"懂框架"的分水岭，强烈建议做一遍**。
- **WebFlux / 响应式**：了解 Reactor 与净线程模型，能讲"IM 网关场景下 vs 传统 WS 的取舍"（本项目是阻塞模型，答题时能对比即可）。
- **监控运维**：Actuator 端点体系 + Micrometer 指标模型 + Prometheus/Grafana（本项目已接，见 §21），理解 HealthIndicator 聚合机制——能讲清 MailHealthIndicator 拖垮 /actuator/health 的原理，你就真懂了这个模块。
- **虚拟线程（Java 21）**：本项目跑在 21 上，Boot 3.2+ 一个开关 `spring.threads.virtual.enabled` 就能用；WebSocket 长连接 + 百万会话场景下它改变了什么，是当下最新的高频考点。

### L3 · "完全掌握"（源码与造轮子层）

- **Spring Framework 源码两主轴**：IoC 容器启动流程（BeanDefinition 注册 → 实例化 → 属性填充 → 初始化 → AOP 代理）+ 事务同步器机制。
- **Boot 启动流程**：`SpringApplication.run` 逐步读，含事件回调（ApplicationListener）。
- **Boot 插件与构建原理**：fat jar 的类加载器（LaunchedClassLoader）——顺便你就懂了 `im-server.jar` 为什么能 `java -jar` 直接跑。
- **常见第三方集成源码**：HikariCP 连接池参数背后、Redis 客户端（Lettuce）线程模型、Tomcat/Netty Connector 模型。
- **能造轮子**：独立实现一个带自动装配、配置校验、可观测的中间件 starter，并在团队项目里替换掉手写配置——做到这一步，"完全掌握 SpringBoot"才敢写进简历。

### 与本项目的对照：学 Boot 为什么应该拿它当教材

| Boot 知识点 | 本项目现成案例 |
|---|---|
| 多 profile 配置 + 外部化配置优先级 | `application.yml/-dev/-prod` + `app/extra/` + `conf/im.env` 三层覆盖 |
| 统一返回体 + 全局异常 | im-common 的 `api/`、`exception/` 包 |
| AOP 自定义注解 | `@RateLimit(Dimension.IP)` |
| SPI 解耦 + 条件装配 | `im-common/spi` 接口 + `ObjectProvider` 注入降级 |
| starter 版本管理 | 父 pom dependencyManagement + boot4 专用 starter 选型（Boot 4 升代的坑全在注释里） |

| 打包与容器化 | finalName → Dockerfile COPY → ENTRYPOINT exec 信号处理，一条线全通 |

> 看书学不到、只有这个项目能教你的：**框架配置项在容器里会变成什么问题**（restart 不重读 env_file、uid 1000 对不上静默丢日志、dash 不认 /dev/tcp）——这正是 L2/L3 知识和真实生产之间的接缝，也是"玩具项目"和"上线项目"在面试官眼里的分水岭。

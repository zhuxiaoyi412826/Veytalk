## 记录 1：语音视频通话全挂——STUN/TURN 地址把冒号写成了等号（2026-11-13）

### 症状

- 公网浏览器拨打/接听，弹「**无法获取麦克风/摄像头：SyntaxError**」；
- **第一次访问会先弹摄像头/麦克风权限提示**，用户点了允许，**几秒后**才报上面这句；第二次开始不弹权限、直接报错；
- F12 网络面板看不到任何外发的 STUN/TURN 请求、也没有新的 HTTP 请求；
- 「局域网里测是好的，公网才炸」——当时被当成网络路径问题排查了很久。

### 排查过程（三步分诊，命令可在服务器直接复用）

```bash
cd /opt/im-docker
# ① 源头文件长什么样
grep -nE 'IM_CALL|IM_TURN' conf/im.env
# ② 运行中容器里的真实环境变量（决定性一步：证明改动生没生效）
docker compose exec im-server sh -c "env | grep -E 'IM_CALL|IM_TURN'"
# ③ 最终答案在浏览器：登录 → F12 网络面板 → 过滤 config → /api/call/config 的 Response
#    iceServers 里每条 urls 必须以 stun: / turn: 开头（该请求在页面加载时就发完了，要 Ctrl+F5 后看列表最前面）
```

实测输出（①② 完全一致）：

```
IM_CALL_STUN_URLS=stun=120.78.126.132:3478     ← 等号！应为 stun:120.78.126.132:3478
IM_CALL_TURN_URLS=turn=120.78.126.132:3478?transport=udp   ← 同款等号
IM_CALL_TURN_ENABLED=true                       ← coturn 还没部署就先开着 true
```

### 根因链

1. **病灶在文档/模板里**：`conf/im.env.example` 与三份部署文档把示例写成了 `stun=<公网IP>:3478`（等号），照抄的人忠实地保留了等号、只替换了 IP。仓库内 7 处已全部勘误为 `stun:<公网IP>:3478`（2026-11-13）。
2. **浏览器对非法 ICE 地址零宽容**：`/api/call/config` 原样下发坏地址，Chromium 在 `new RTCPeerConnection({iceServers})` **构造即抛 SyntaxError**——不是逐条跳过的软错误。
3. **报错文案张冠李戴**：旧前端把 buildEngine 的异常统一报「无法获取麦克风/摄像头」，真凶（ICE 配置）被冤枉成了设备问题。
4. 症状逐条对上：权限弹窗在 getUserMedia 阶段就出现并成功；随后建 PC 才抛错；teardown 把轨停掉。网络面板安静是因为 pc 根本没建出来、一个探测包都发不出去；信令走已有 WS 长连接，不产生新 HTTP 请求。

### 修复

```bash
cd /opt/im-docker
sed -i -E 's/^(IM_CALL_STUN_URLS)=stun=/\1=stun:/; s/^(IM_CALL_TURN_URLS)=turn=/\1=turn:/' conf/im.env
grep -nE 'IM_CALL|IM_TURN' conf/im.env                        # 肉眼确认两行已是冒号
docker compose up -d --force-recreate im-server              # ★ 必须 recreate，见教训 3
docker compose exec im-server sh -c "env | grep -E 'IM_CALL|IM_TURN'"   # 复核容器内真值
```

### 为什么「局域网正常、公网报错」是假象

SyntaxError 是**配置字符串解析失败**，与请求从哪张网发来无关：同一台服务器、同一个生产页面，局域网机器和公网手机读到的 `/api/call/config` 是同一份。**局域网测通 ≠ 生产配置没问题**——那次「通」几乎必然是没打到这份 `conf/im.env`（本机 dev 环境 iceServers 本来就是空、或改配置前的旧标签页）。跨网对比只能用来区分「P2P 打洞/中继不通」这类真网络问题，对「构造即抛」的解析错误没有区分度。

### 代码层加固（同批入库，随下次构建生效）

- 后端 `CallSignalingService.buildIceServers`：下发前校验 URL 格式（`^(stun|stuns|turn|turns):[^\s<>]+$`），非法条目跳过并 log.warn 指到具体配置键——保护所有旧客户端；
- 前端 `utils/webrtc.js`：`sanitizeIceServers` 丢弃非法条目降级 console 警告（配置笔误最多丢打洞能力，不再打挂整通电话）；`mediaErrorHint` 把 SyntaxError 的文案分流为「ICE 地址非法，查 IM_CALL_*」；
- `im.env.example`：`IM_CALL_TURN_ENABLED` 默认改回 `false` 并加警示注释。

### 可复用教训

1. **浏览器报错名带 Error 后缀的「构造/解析」类异常（SyntaxError/TypeError）先怀疑下发配置字符串本身**，而不是网络路径；getUserMedia 成功后的权限弹窗出现 ≠ 麦照有问题。
2. **配置排障双验范式**：源头文件 `grep` + 运行进程 `exec env | grep`，两者一致才谈「改了没生效」；只看文件会漏掉 recreate 没做的情况，只看接口响应会分不清是缓存还是现值。
3. **env_file 的改动一律 `up -d --force-recreate`**：环境变量在容器创建时注入，`restart` 和裸 `up -d`（compose 判定配置未变时）都不重读 `conf/im.env`——restart 了等于没改。与「挂载文件用 restart、up -d 反而没用」（app/extra/*.yml、证书）恰好相反，两类文件别搞混。
4. **非空的占位符比空值更毒**：`IM_TURN_SECRET=<与coturn逐字一致>` 不是空串，后端判「secret 非空才下发 TURN」于是照样签发了一条坏中继条目；模板里凡是「配了才生效」的开关（如 TURN_ENABLED）默认值就该 false。
5. **照抄文档前先怀疑文档**：本次病灶源头是模板与三份手册共 7 处笔误，用户一字不差照抄反而必炸——文档示例值改动后要在真实环境验一次语法类字段（URL/正则/cron）。
6. **coturn 部署的独立检查点**（与 SyntaxError 无关但决定公网能否接通）：compose 的 coturn 段放开后，`--external-ip=<公网IP>/<内网IP>` 必须替换（阿里云公网 IP 是 NAT 映射不在网卡上），安全组放行 `3478 TCP+UDP` 与 `49160-49200 UDP`，`.env` 的 `TURN_SECRET` 与 `conf/im.env` 的 `IM_TURN_SECRET` 逐字相同，否则客户端一律 401。

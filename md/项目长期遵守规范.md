## 一、铁律：无论做什么都适用

### 1.1 MySQL 的写操作由用户本人执行

- **禁止**助手运行任何改动数据或表结构的语句：`INSERT` / `UPDATE` / `DELETE` / `TRUNCATE` / `DROP` / `ALTER`，
  以及导入 SQL 脚本（`mysql -e "source"`、管道导入、`mysqldump` 回灌、`mysqlbinlog` 前像恢复）。
- 需要改动时，**只输出可直接复制的 SQL + 前置备份 + 回滚说明 + 影响解释**，由用户自己执行。
- 用户明确豁免的两类：① **只读查询**（`SELECT` / `SHOW` / `DESC` / `EXPLAIN` / `information_schema`）可自由运行做诊断核对；
  ② **Redis 只是缓存**，读写命令（`SET` / `DEL` / `EXPIRE`）可直接执行，不用交给用户。
  ★ ② 有边界：**Redis 里不只有缓存**，发号器、红包状态、互斥锁、幂等标记都在这台实例上，
  动它们的破坏半径与一条 `DELETE FROM` 一样大——分类表见 [1.10](#110-redis-命令助手可直接执行但要先分辨缓存与业务状态)。
- *为什么*：这是唯一一条能把「误删生产数据」的责任从工具转回人的闸门；同时留了豁免口子，避免为了查一个数也要来回沟通。

### 1.2 写进文档和回复里的数字必须是实测出来的

- 任何数量级断言（表数、接口数、行数、文件大小、比例、耗时）都要**先跑出真值**；拿不到就写「未实测」，不要写估算。
- 历史文档里的数字发现不对，**订正时保留原话**并加引号说明「原写 X，实测为 Y」，不要悄悄改掉——
  数字被打脸的那次记录本身就是有价值的信息。
- 用户手写的需求原文**一律不订正**（哪怕里面有错别字和过时口径），那是诉求凭证，不是事实陈述。
- *为什么*：这个仓库的文档量大、互相引用，一个假数字会顺着引用链扩散到八处（真发生过：CORS 段行号被一次注释追加带歪）。

### 1.3 每一轮改动都要有 CHANGELOG 条目，且「描述性文档」要同步

- 改了什么、为什么、影响范围、涉及文件路径，写进 `md/CHANGELOG.md` 顶部「未发布 Unreleased」。
- 仅写 CHANGELOG **不够**：若这轮改变了「既有事实描述」（架构链路、交互布局、命令与配置指引、踩坑结论），
  必须**同轮**同步 `README详细开发指南.md` 等描述性文档。用户会核查，漏了算未完成。
- *为什么*：本项目没有自动化测试与 CI，文档就是验收凭证本身。
- ★ 条目**怎么写**（三要素、一条不超 3 行、哪些属无效信息）见 [6.6](#66-文档只写必要描述一条三要素不超-3-行)。

### 1.4 SQL 变更必须当轮登记进台账

见 [`md/SQL变更文档.md`](./SQL变更文档.md)：起始版本 `1.0.0`，每条记录标注 **★ 清除 / ★ 增加 / ★ 修改** 动了哪些
`表.列 / 索引 / 种子 id 区间`，并回答「是否已并回 `im_schema.sql` + `im_data.sql`」。闸门同时挂在 `CONTRIBUTING.md` 硬性门槛第 8 条。

### 1.5 注释要写「为什么」，不是「做什么」

- 反直觉的实现、刻意保留的冗余、被撤掉的老写法，都必须在原地写清理由（本仓库的实际样板见
  `im-ui/src/styles/index.css` 的 `.im-dialog--fit` 与 `im-ui/src/views/Login.vue` 的 `hintInvalid()`）。
- 配置项一律带「为什么是这个值」的注释（`application.yml` 是全仓注释密度最高的一份）。
- *为什么*：只有「做什么」的注释会在下一次重构时误导人——它会让人以为那段代码是随便写成这样的。

### 1.6 文档里引用配置文件：只写键名，不写行号，也不写文件总行数

- 写法定为「`application.yml` 的 `im.file` 段」/「搜 `storage: ${IM_FILE_STORAGE:minio}` 那一行」。
- 要拿行数做量级叙述的（如「多少个 `${ENV:默认值}` 占位符」），只写实测值并声明会漂移。
- *为什么*：`application.yml` 注释密度全仓最高，加两行注释就会让下游全部行号引用集体偏位，**而且不会有任何报错**。
  前科：`im.file.storage` 从 L370 移到 L372，八处文档同时变假（2026-11-08 清完）。

### 1.7 不许凭印象处置不属于本轮的进程

要停一个服务之前，先证明它是自己起的。判据（三者齐全才动手）：

1. **命令行形态**：`java -jar im-server.jar` 才是打包产物启动；
   `-cp @…spring-boot-*.argfile com.im.bootstrap.ImApplication`（父进程是 maven classworlds）是 `mvn spring-boot:run`。
2. **父进程链**：看是谁把它起来的。
3. **自己那份重定向日志是否还在增长**。

- **不要拿文件 mtime 排先后**——同一轮里出现过 `.ps1` 的落盘时间比它输出的 `.txt` 还晚。
- *为什么*：2026-11-08 差点 `Stop-Process` 杀掉用户为手点验证自己起的一对前后端（8080 + vite），
  端口和前端都是用户的，杀掉等于把用户的验证环境砸了。

### 1.8 共享 Redis 实例上禁止 `FLUSHDB` / `FLUSHALL`

- 只 `DEL` 明确列出的键，模式必须带项目前缀（`im:auth:*`），禁止宽匹配。
- *为什么*：开发机 6379 常年与别的项目共用一台实例——实测一台 `DBSIZE=321` 里本项目只占 39，
  而且存在与本项目权限键长得极像的 `auth:privileges`；`KEYS *auth*` 会清掉别人的会话和计数器（计数器被清会撞号）。

### 1.9 临时产物必须清干净，且删完要复核

- 自己造的取证文件（`tmp/*.txt`、探针输出、测试沙箱）用完就删；被文档引用的证据文件可留，但要在 CHANGELOG 里点名它是证据。
- **删除工具可能返回 success 却没真删**（实测：同目录 `.json` 一次删成、`.json` 外的媒体文件连续三次假成功），
  删完必须 `Test-Path` 或列目录复核，残留就回退到 `Remove-Item -LiteralPath` 精确删除。
- *为什么*：`.gitignore` 有全局 `*.txt`，残留的临时文本既进不了 git 又占着工作区，最后会被打包流程或下一轮排查当成「现状」。

### 1.10 Redis 命令助手可直接执行，但要先分辨「缓存」与「业务状态」

用户口径原话（2026-11-08）：「关于 Redis 缓存的命令操作，你都可以执行，数据库 MySQL 的不变」。
本条就是那句口径的落地：**MySQL 那条闸门（1.1）不动，Redis 这一侧从「每次问一下」改成「直接做」**，
但「直接做」不等于「随便做」。

- **触发场景**：清了权限缓存验证是否生效、查某个键在不在 / TTL 还剩多久、看在线状态、
  排查降级路径有没有写回、按约定删掉 `im:auth:*`。
- **硬口径**：
  1. **读命令一律自由**：`GET` / `TTL` / `TYPE` / `HGETALL` / `EXISTS` / `DBSIZE` / `INFO` / `SCAN`。
  2. **可再生缓存类键的写命令助手直接做**（删了只是让用户重做一次，库里或应用能重建）：
     `im:auth:perm:*` / `im:auth:role:*`（TTL 30 分钟且回源读库，见 2.4）、
     `im:unread:*`（应用自己就这么 `delete` 失效，TTL 到期自动回源）、
     `im:at:*`（先写库 `markAtFlag` 再写 Redis，代码里明写「写入失败数据库标记仍然有效」）、
     `im:online:*`（心跳重建）、`im:admin:dashboard`（面板重算）、`im:web:search:*`、
     `im:captcha:image|sms|email:*`（验证码本身，删了只是让用户重新收一条）。
  3. ★ **五类键不许助手动手**，它们不是缓存，后果与 MySQL 写等价，**必须输出命令交给用户**：
     ① **发号器** `im:conv:seq:*`——对缺失的键直接 `INCR` 会从 1 开始与历史消息撞号（见 2.5）；
     ② **业务状态** `im:wallet:packet:*`——hash 里存红包 meta 与 splits，`claim()` 直接读它，删了等于抹掉别人没领完的钱；
     ③ **互斥锁** `im:wallet:packet:refund:*`——`setIfAbsent` + TTL 挡住退款与领取并发，删了会双重支出；
     ④ **计数、限流与幂等标记** `im:report:quota:*`（`increment` 出来的当日限额，删了等于给用户重置额度）、
     `im:captcha:sms:limit:*` / `im:captcha:email:limit:*`（`setIfAbsent` + 发送间隔 TTL 的**限流占位**，
     删了等于当场解除验证码频率限制——短信是按条计费的，还能被用来轰炸）；
     `im:msg:idem:*`（`setIfAbsent` + 5 分钟 TTL 的发送占位，提前删等于摘掉重发防护）；
     ⑤ ★ **唯一存储** `im:quick:reply:*`——常用语**没有数据库表**（`im_schema.sql` 里 0 命中），
     Redis 就是正本（代码注释原话：「这是这份清单的实际寿命——没有别的地方存着它」，365 天滑动保留），
     删了不可恢复——**它名字里带 reply 看起来像个缓存，实际是用户数据**。
     - ★ **没在这张表里的键族一律归「不许动手」**（`RedisKeys` 共 **34** 个键族，上面点名 10 + 8，
       余下 **16** 个是 `im:live:*` / `im:pk:*` 共 14 个、`im:report:dedup:*`、`im:file:md5:*`）：
       它们绑着**进行中的**直播与 PK 会话，删了会打断正在线的人。
       **口径里没写不等于允许**——这张表只靠「默认禁止」才是安全的。
  4. **写命令执行前，先把完整键名与理由写在回复里**，让人能中途叫停；模式必须带 `im:` 前缀，
     `FLUSHDB` / `FLUSHALL` 全禁（见 1.8），`KEYS` 只用于自己点名核对。
  5. 键名一律取自 `im-common/src/main/java/com/im/common/constant/RedisKeys.java` 的常量或它的 helper 方法，
     **不凭文档与记忆拼前缀**（同 2.4）。★ 实测两个坑：`im:file:md5:*` 只有常量定义、
     **全仓零使用点**（别照着它去清东西）；而 `RedisKeys.MSG_IDEMPOTENT` / `AUTH_PERMISSION` 这类常量是通过
     `RedisKeys.msgIdempotent(...)` 这种 helper 间接调的，**只 grep 常量名会误判成「没人用」**。
- *为什么*：用户豁免的是「缓存丢了能重算，不必为这个来回沟通」这个**便利**，不是「Redis 里的东西都不重要」。
  这台实例上真实存着红包余额、消息发号器、幂等标记，甚至用户数据（常用语清单），把它们当缓存删掉的
  后果跟改坏库一样，而且**同样不会报错**——看上去只是一次清缓存。
- **反例**：`redis-cli KEYS "*packet*" | ... DEL` 会连红包状态带退款锁一起抹掉，而且这种不带 `im:` 前缀的
  宽匹配在共享实例上还会命中其它项目的键（见 1.8）；
  `--scan | ForEach-Object { redis-cli DEL $_ }` 在 PowerShell 下**静默什么都不删且退出码 0**（见 2.4），
  拿它当「已经清了」继续往下排查，就会一路查到错的方向。

## 二、数据库与缓存

### 2.1 两份全量脚本的定位

- `sql/im_schema.sql`：建库 + **43 张表**（含索引、生成列），**开头带整套 `DROP TABLE IF EXISTS`**
  ⇒ **存量库绝对不可执行**，只用于空库初始化。
- `sql/im_data.sql`：只灌种子（管理员 / 角色 / 权限 101–125 / admin 绑定 6001–6025 / 演示用户 / 礼物 / 钱包 / 协议 1301–1303）。
- `sql/migration_*.sql`、`sql/*_patch.sql`：**只服务存量库升级**，全新库一律不跑（内容已并回上面两份）。

### 2.2 执行方式（PowerShell）

```powershell
mysql -u root -p --default-character-set=utf8mb4 -e "source sql/im_schema.sql"
mysql -u root -p --default-character-set=utf8mb4 im_db -e "source sql/im_data.sql"
```

- **禁止 `<` 重定向或管道导入**：PowerShell 会把中文静默刷成 `?`，数据损坏且**不报错**。必须 `-e "source 文件"` 让 mysql 自己读。
- 第二条命令带库名 `im_db`，因为 `im_data.sql` 不建库。

### 2.3 迁移脚本写法

- 给已有库的变更**新增脚本**，不回头改历史脚本；`ALTER` 要带幂等护栏（先查 `information_schema` 再动，或 `IF NOT EXISTS`）；
  全量种子脚本（`im_data.sql`）用「先 `DELETE` 自身 id 区间再 `INSERT`」的幂等写法；脚本头部必须写清「存量库用途 + 全新库无需执行本文件」。
- 脚本**末尾的回滚段**（`-- DROP TABLE ...` / `-- DELETE FROM ...` / `-- ALTER TABLE ... DROP COLUMN ...`）是给人手工执行的退路，
  **不算本脚本的变更动作**，登记台账时归入「回滚方式」而不是 ★清除。实测：除 `im_data.sql` 外，`sql/` 下的 `DELETE` 基本全是注释态。

### 2.4 权限缓存

- 键模板取自代码常量 `RedisKeys.AUTH_PERMISSION` / `AUTH_ROLE`（`im:auth:perm:{userId}`、`im:auth:role:{userId}`），
  **不要凭文档或记忆拼前缀**。TTL 30 分钟且**登录不刷新** ⇒ 改了权限种子必须清缓存。
- 清缓存三步：① `redis-cli keys "im:auth:*"` 列出；② 全部键名塞进**同一条** `redis-cli DEL "k1" "k2" ...`；③ 再 `keys` 复核应为空。
  第 ③ 步不能省（分两次连接会漏掉中间新写回的键）。
- `--scan | ForEach-Object { redis-cli DEL $_ }` 在 PowerShell 下**静默什么都不删**且退出码 0；`EVAL "lua 串" 0` 会被拆参数报错。
- 清完缓存不需要重启进程（权限每次请求回源读库），但要先只读 `SELECT` 数一下库里的行真的插上了——
  「表不存在」和「权限行不存在」是两回事。

### 2.5 消息 seq 发号器（改库后必看的坑）

- Redis 计数器语义是「最后一个已发出的号」，正常应恒等于库里 `MAX(seq)`；绕过应用直接改库后会落后。
- 修好的实现三件事缺一不可：① 热路径 `incrementIfPresent`（**绝不能对缺失的键直接 INCR**，否则从 1 开始和历史消息撞号）；
  ② 每会话首次发号用 `SELECT MAX(seq)` + `raiseToAtLeast`（Lua，只增不减）校正；③ 降级分支在会话锁内串行取号并尽力回写。
- 手工改库后：**重启后端即自动对齐**，不重启就把计数器 `SET` 到 `MAX(seq)`。

## 三、后端架构

### 3.1 模块与依赖方向

- 跨模块调用一律走 `im-common` 定义的 SPI 接口（`XxxSpi` / `AdminXxxSpi`），**实现方由业务模块提供、调用方不依赖实现**。
  典型：后台管理功能由 `im-admin` 封装控制器，数据查询走 `AdminXxxSpi`，实现在 `im-live` / `im-file` 等模块里。
- *为什么*：这是本项目避免循环依赖的唯一手段；直接依赖实现类会把模块图钉死。

### 3.2 审计类记录用双写

- 关键审计日志（如图片审核命中）**先写 AUDIT 文件再落库**，落库失败 `try/catch` 记 WARN，**不影响主流程**。
- 待查的表：`im_moderation_log`（隔离区图片挂在 `evidence_file_id` → `im_file.id`，`biz_type=moderation_quarantine`）。

### 3.3 部署形态限制

- **当前只支持单实例部署**：WebSocket 连接管理与定时任务都没做分布式协调，多实例会互抢会话与重复触发任务。
- 通话/共享屏幕这类实时功能的信令**必须经后端中继**（`CallSignalingService` 透传字段），前后端信令要闭环；
  改了信令结构**必须重启服务**才生效。

### 3.4 CORS 白名单必须成对配 http 与 https

- `application.yml` 的 `im.cors.allowed-origins` 要同时列 `http://` 与 `https://` 两种 scheme 的每种 host:port 变体。
- *为什么*：Vite dev server 一旦启用自签证书（本仓 `im-ui/certs/server.{pem,key}` 存在即自动 https），
  浏览器 `Origin` 会变成 `https://localhost:5173`，白名单只有 http 就回 **403 Invalid CORS request**；
  且**同源 POST 也带 `Origin` 头**，「同源不用管 CORS」是误区。

### 3.5 接口文档闸门

- 任何 HTTP 接口增改都要同步 knife4j 文档：本地以 **dev profile** 起服务，跑 `python scripts/api-doc-check.py`，**退出码必须为 0**。
- knife4j 分组不是按 `@Tag` 自动生成，而是 `Knife4jConfig` 里每个 `GroupedOpenApi` 的 `pathsToMatch` 前缀切出来的；
  漏配前缀**不报错不警告**，接口只是从文档里消失（2026-09 实测漏了 96 条路径 / 107 个 mapping，注解本身是满的）。
- `prod` profile 把 knife4j 与 springdoc 全关，`/v3/api-docs` 回 404 —— **这是设计如此**，上线检查清单反而要求它 404。

### 3.6 打包产物的主类

- 经 `spring-boot-maven-plugin` 重打包后，`MANIFEST.MF` 的 `Main-Class` 固定是 `JarLauncher`，
  **应用主类看 `Start-Class`**（构建验证脚本据此判断 jar 是否合格）。

## 四、前端与交互

### 4.1 Element Plus 用法

- **嵌套 `el-dialog` 必须显式加 `append-to-body`**（否则层级错或被父级样式裁剪）。已有先例：`GroupSettings`、`ForwardDialog`。
- **整行选择**：内容直接放 `el-checkbox` 默认插槽，**不要手动套 `<label>`**（`v-for` 里会造成 label 套 label 的非法嵌套 + 双触发）。
- **批量写操作成功后要按当前搜索关键字重拉列表**（`fetchFriends(keyword)`），并用 `.catch(() => {})` 包住重拉，
  避免异常盖掉成功反馈。根因：`stores/friend.js` 的 patch 只改 `state.friends` 里现存的行，过滤态下目标行不在里面，标签不刷新。
- `el-link` 的 `underline` 已弃用 boolean 写法，统一写 `underline="never"`（3.0.0 起只认 `'always' | 'hover' | 'never'`）。

### 4.2 弹窗高度：只让 body 滚，且一个弹窗只有一个滚动容器

- 表单长、矮屏会出问题的弹窗，加全局类 **`.im-dialog--fit`**（定义在 `im-ui/src/styles/index.css`）：
  标题页脚钉住，只滚 `.el-dialog__body`，`max-height: calc(100dvh - 230px)`（`vh` 兜底老内核）。
- **不要再在弹窗内部给正文区套第二层滚动容器**（`max-height + overflow-y:auto + overscroll-behavior:contain` 会和外层抢滚轮、
  滚到底又被 `contain` 锁住不上交，用户看到的现象就是「下拉看不到全文」）。
- **反过来，整屏页面必须自己带一层滚动容器**（与上面那条不矛盾：弹窗里是「只能有一层」，
  页面里是「至少得有一层」）。全局 `body { overflow: hidden }`（`im-ui/src/styles/index.css`）会
  按 CSS 规则**向上传播到视口**，所以本项目里**文档级滚动条根本不存在**；长内容页（`/legal/:code`
  这种整屏公示页、以及以后新加的帮助页/活动页/落地页）若不写
  `height:100vh/100dvh` + 中间那一段 `min-height:0; overflow-y:auto`，
  用户看到的就是「内容全排出来了（实测 2900px）却一屏都动不了」。
  四个配套细节一个都不能漏：**flex 项不压 `min-height:0` 则 `overflow-y` 形同虚设**；
  **`align-items` 默认 `normal` 在 flex 里等价于 `stretch`，而滚动容器高度是确定的（`flex:1`），
  会把卡片钉成容器可见高度**（实测卡片 335px 而内容 2838px），现象是「白色背景没盖住下面的文本」，
  得写 `align-items: flex-start` 让卡片高度跟着内容走；
  `@media print` 里要把 `height/overflow` 放开（否则「欢迎打印」的页面会被裁在第一页）；
  同一个组件实例只换路由参数时容器不会自己归零，切内容要显式 `scrollTop = 0`。
- 这类样式**必须写在全局**而不是组件 `scoped`：弹窗带 `append-to-body`，DOM 被传送到组件作用域外，
  `scoped + :deep()` 打不中 `.el-dialog__body`；写在 `el-dialog` 上的 `class` 会落到 `.el-dialog` 根节点
  （同 `FileViewer.vue` 的 `.file-viewer--narrow` 手法）。
- 校验失败必须「喊得响」：`el-form` 加 `scroll-to-error`，并在 `validate()` reject 时取第一条错误发 `ElMessage.warning`
  （见 `Login.vue` 的 `hintInvalid()`）。*为什么*：注册弹窗有 8 个表单项，实测 490px 视口里协议那一行 top=694px 直接在屏幕外，
  内联红字渲在屏外 = 用户点完按钮「什么反应都没有」。

### 4.3 移动端文件输入

- **严禁 `display:none`**（部分手机浏览器/WebView 会直接忽略 `click()`）；用「渲染但不可见」：
  `position:fixed; width:1px; height:1px; opacity:0; pointer-events:none; z-index:-1`，且**不要 `v-if` 掉**。
- 调起优先级：`input.showPicker()` → `input.click()` → DOM Overlay；封装在 `im-ui/src/utils/picker.js` 的 `openFilePicker(input)`。
- 必须在用户手势回调里**同步**调用，`await` 之后再调就失去手势上下文。

### 4.4 通话画面（最终口径，覆盖此前所有版本）

- 默认视角两端统一「中间＝对方、右上＝我自己」，`swapped` 初值 `false`，每通新通话复位也回 `false`；
  点右上角小窗互换，手机端一样可换（**不要**按端分默认布局）。
- 满屏但**不裁切**：`object-fit: cover` 会把异朝向流裁到只剩约 23% 高度，所以用
  背景 `<video class="call-overlay__main-bg">` 挂同一路流（`cover` + `blur(22px) brightness(0.55)` + `scale(1.2)`），
  前景 `.call-overlay__main` 保持 `contain` 居中。
  ★ 两个必踩坑：**背景层必须 `muted`**（同一路流挂两个元素，不静音就是双份声音）；**前景 `background` 必须 `transparent`**
  （否则 `inset:0` 的 `#000` 会把下面那层模糊整个盖掉）。低端手机发烫时把 blur 降到 12px。
- 互换只对 `swappedView = swapped && isVideo` 生效：语音通话不渲染小窗，让互换生效会把远端流挂到不存在的元素上，
  **手机语音直接听不到对方**；声音出口跟着流走（主 `:muted="swappedView"`、小窗 `:muted="!swappedView"`）。
  `swappedView` 必须声明在 `isVideo` **之后**（`attachStreams` 的 watcher 是 immediate，提前读会撞 TDZ，构建不报错运行时才炸）。
- 小窗：默认桌面 270×192、手机 150×111，放大 405×288 / 225×167，手机窄屏规则写在所有基础规则之后；
  最小化后由 `CallFloatWindow.vue` 接管（pointer 拖动、4px 阈值区分点击）；
  浮层用 `opacity:0 + pointer-events:none` 隐藏而**不是卸载**（`display:none` 会让部分移动端浏览器暂停视频解码，语音断）。
- 流绑定采用「固定绑定 + CSS 类切换」：远端流与本地流各永久绑一个 `video`，换视角只切父容器类名（`--main` / `--pip`），
  **不再重新赋值 `srcObject`**（规避 iOS 重复挂载 getUserMedia 流导致白屏/冻结）。

### 4.5 其它交互口径

- **录音**：微信式滑动分区，按横向位移 `dx` 判定 —— `dx ≤ -56` 取消、`dx ≥ +56` 转文字、中间录音，松手时按所在区决定动作；
  `pointercancel`（浏览器接管手势）**一律视为取消并丢弃录音**，绝不能当松开发送；
  计时 `tick` 顶部加 `!pressing || !startedAt` 护栏，防「秒发」。
- **直播**：主播在自己的直播间**不显示**点赞与礼物入口（`isAnchor` 判断）；后端两道硬闸——
  主播给自己点赞的帧**直接丢弃**（不计数不广播）、送礼校验 `senderId == anchorId` 则拒绝并回 `GIFT_SELF_FORBIDDEN`。
- **礼物弹层**：顶部栏固定「🎁 送礼物 + 余额 + ✕」，签到与充值放面板内独立一行；网格 `repeat(auto-fill, minmax(66px,1fr))`；
  `overflow-x:hidden`；`max-width:768px` 时面板高 80%、图标 24px、按钮满宽。
- **表情回应**：只显示 emoji，**不显示计数**。
- **投票 / 接龙**：发起入口只在群聊显示，单聊工具栏隐藏这两个按钮（历史消息仍正常渲染）。
- **名片选择器**：第一位固定是「我的名片」（头像 + 昵称 + 标识），点即发送。
- **常用语**：点击即直接发送；编辑入口是行尾铅笔图标（把内容填入输入框二次编辑）。
- **文件传输助手页**（`FileHelper.vue`）：外层容器 `height:100vh`，消息列表内部 `overflow-y:auto`，底部输入面板固定可见；
  独立路由 `/filehelper` 扫码登录后**原地展示**、不跳 `ChatHome`（与 `/transfer` 分工不同）。
- **可测性**：播放器模式选择逻辑 `pickPlayerMode` 必须作为纯函数放 `im-ui/src/utils/quality.js`，不得内联在 SFC 里。
- **闪照**：语义是「**每人各看一次**」——发送者看不看都不消耗接收者的那次，双方都看过才触发删除；
  删除是逻辑删（`deleted=1`）**且必须全员都看过**，物理字节因秒传去重不删。
  Electron 端防截图用 `win.setContentProtection(true)`（Windows `SetWindowDisplayAffinity`），预览期间开、关闭或切会话时撤销；
  **浏览器和手机端没有任何 Web API 能阻止系统级截屏**，这是边界，不要在前端写伪装的防截图逻辑。
- **通话 HTTPS 预检**：拨号/接听前检查 `navigator.mediaDevices` 是否存在，缺失就 `ElMessage.error`
  提示「当前地址不是 HTTPS/localhost，浏览器禁止使用麦克风/摄像头」并给 `gen:cert` 指引；
  `buildEngine` 取流异常要弹 toast；ICE failed 加 5 秒重连窗口后自动挂断并通知对端。
- **接口失败的文案分四层，各自只说自己那一层的事**（`im-ui/src/api/request.js` 与 `im-admin-ui/src/api/request.js` 同口径，两边不要各自演化）：
  ① 后端业务失败 = **HTTP 200 + `Result`** ⇒ 直接显示 `body.message`；
  ② **非 2xx 且不来自后端**（代理 / 容器层）⇒ 先看 `error.response.data` 是不是 `Result` 形状，
  是就用它那句 message（现在 dev 代理连不上后端就回 502 + `Result`，写明连不上哪个 target 与 errno），
  不是才退到「服务异常（HTTP N）」；
  ③ 有 `error.request` 但没有 `error.response` ⇒ 请求真出去了却没回来（断网 / 后端没起 / 被浏览器挡下）
  ⇒ 「无法连接服务器，请确认后端已启动」；
  ④ **连 `error.request` 都没有** ⇒ 请求在本端就折了、根本没出浏览器
  ⇒ 「请求未能发出（前端错误）：`error.message`」。
  口径：**读得到真因就不许报虚话**。后端所有失败都是 200，所以看到 5xx 就已经不是业务问题了，
  再拼一句「服务异常（HTTP 500）」等于把判断推给用户；而 ④ 混进 ③ 更坏——前端自己的 bug 会伪装成
  「后端没起」，2026-11-08 那次注册报错就被这样带偏过一轮（见本节末条）。
- **请求体里不许直接放 ref / computed 本体**：`<script setup>` 里 `const x = computed(...)` 拿到的是
  `ComputedRefImpl`，`JSON.stringify` 会沿 `dep → Dep.computed` 成环抛
  `TypeError: Converting circular structure to JSON`，axios 因此在发出前就 reject（走到上面 ④）。
  给接口传派生数据必须写 `.value`（或先存成普通变量）；`{ ...form }` 这种浅拷贝**不会**帮你拆 ref。
  排查这类问题的特征是「页面报错但网络面板里一个请求都没有」。
- **清单类接口失败不许静默**：`/api/agreement/list` 是 `silent` 的，拉不到就把勾选行整行隐藏，
  「后端没起」与「后台一份文本都没发布」在页面上长得一模一样。现在 store 把失败原因留在
  `listError`，注册弹窗因此多一行「条款未能加载：… 重试」，`submitRegister` 也不会把注定失败的请求发出去。
- **导出 / 打印成 PDF 一律走浏览器打印，不引 html2canvas + jsPDF**：那样出来的是位图 PDF，
  文本里的字选不中、搜不了，法律文本尤其不该这样留档；且打印路径天然是矢量，中文不用嵌字体。
  与本仓「PDF 预览交浏览器内置查看器、不引 pdf.js」（`FileViewer.vue`）同一口径。
  三条必须同时做对，缺一条就打出一份坏文件：
  ① **全局 `@media print` 要放开 `html, body, #app` 的 `height` 与 `overflow`**——屏幕上的防误滚基线是
  `body{overflow:hidden}`（见 4.2），不放开的话整份长文被当成一个一屏高的滚动区，只打出第一页；
  ★ 这一层只能写在全局 CSS，页面自己的 `@media print` 救不到 `html/body` 上；
  ② **打印态要在打印容器上重定义颜色变量**（`--im-text` / `--el-text-color-primary` 等）：外观可选深色，
  `settings` store 往 `<html>` 上挂 `.dark`，那些变量此时是「浅字」，直接印到白纸上就是白底白字；
  ③ **纸上那几层不要用 flex**（改 `display:block`）：弹性容器里子项分页在部分内核上不可靠，
  而纸张不需要「居中」与「等分高度」；`break-before/after: page` 与老内核的 `page-break-*` 两套都写。
  ★ 分页本身在自动化里量不到（`window.print()` 只能打桩），交付时必须写明「待人工 Ctrl+P 复核」；
  要采「导出中」这种一闪而过的 UI 态，得先重载页面清掉模块级缓存，再把 XHR 人为延迟，否则请求在 15ms 内就完。

## 五、构建、部署与命令行工具经验

### 5.1 构建与发布

- 标准流程：`mvn -B -ntp -DskipTests clean package` → 验 `MANIFEST.MF` 的 `Start-Class` →
  复制 `im-bootstrap/target/im-server.jar` 到 `Docker/app/` → `docker buildx build` 推 GHCR，**tag 与 pom 版本对齐**；
  内网改用 `docker save/load`。
- 产物命名模板：`Veytalk-<端>-<渠道>-<版本>-<平台架构>.<ext>`
  （如 `Veytalk-Desktop-Setup-1.0.0-win-x64.exe`、`Veytalk-Mobile-Capacitor-1.0.0-arm64-v8a.apk`）；
  版本号统一用项目主版本，**文件名只用 ASCII**，禁止中文与空格。
- `mvn clean` 在 Windows 报 `Failed to delete ...\target：另一个程序正在使用此文件`：子文件其实已删净，只是**根目录被 IDE 的
  JDT LS / 资源管理器 / 杀软的 watch 句柄占着**。根治是根 pom 的 `pluginManagement` 里给 `maven-clean-plugin`
  配 `<failOnError>false</failOnError>`（对全部模块生效）；**不要为解锁去杀 IDE 的 java 进程**。

### 5.2 Dockerfile

- `RUN` 的多行 shell 里，**禁止在行尾 `\` 之前加行内注释**：续行符吞掉换行后，注释会把后面的整条命令吞掉，
  表现为 `command not found`。注释要么放在整个 `RUN` 块之前，要么单独成行。

### 5.3 PowerShell 三条硬经验

- 导入含中文的 SQL：必须 `-e "source 文件"`（见 2.2）。
- `ForEach-Object { ... }` 脚本块里**不能直接写 `if` 语句**（报 `CommandNotFoundException`），
  用三元 `(...) ? 'a' : 'b'` 或改用 `Where-Object`。
- `>` 重定向会把外部命令输出写成 **UTF-16LE** 且中文按控制台代码页降级；要保真就先
  `[Console]::OutputEncoding = [Text.Encoding]::UTF8`，或用 Python `subprocess` + `stdout=open(file,'wb')` 原样落盘。
- 本条命令环境是 PowerShell 5.1，**不支持 `&&`**，多条语句用 `;` 分隔。
- 写 `.ps1` 时避免文件里出现中文（PowerShell 5.1 按 ANSI 读无 BOM 的 UTF-8，正则里的中文会碎成非法模式）；
  非要有中文，用 `[char]0x4E2D` 这类码位表达或改走 `.py`。

### 5.4 数据恢复（ROW binlog）

- 误 `DELETE`/`UPDATE` 可用 `mysqlbinlog -vv --base64-output=DECODE-ROWS` 的**行前像**反向恢复，不必整库 PITR。
- 注意：`### WHERE` 里是 `@N`，要用 `information_schema.COLUMNS` 的 `ordinal_position` 映射回列名；
  **生成列不能出现在 INSERT 列表**（ERROR 3135），`DEFAULT_GENERATED` 是函数默认值不是生成列；
  mysqlbinlog 打印的字符串已按反斜杠转义，**要原样透传**；回灌用 `INSERT IGNORE` + 事务包起来。
- 唯一键会让「同一身份重注册」插不回去：要把旧雪花 ID 映射到现存新 ID、同步改写引用列与业务键，
  再处理库里孤儿引用，否则恢复出来的子表全指向不存在的主键。
- 恢复后必须重新对账：外键悬挂、会话内 seq 重复、Redis 计数器水位（见 2.5）。

### 5.5 HLS 延迟优化的代价顺序

- ① 先调 `hls.js` 的 `liveSyncDurationCount` 3→2→1（一行配置、回滚即时，代价是网络抖动时更容易卡）；
  ② 再把 ffmpeg 切片 2s→1s（生产头与轮询周期各减半，代价是关键帧变密 +10-20% 码率、PUT 频率翻倍）；
  ③ LL-HLS 与换协议（SRS / WebRTC / HTTP-FLV）只在必须 sub-5s 时才考虑，属于架构级改造。
- 监控 `BUFFER_STALLED_ERROR`：卡顿明显上升就退回更大的 `liveSyncDurationCount`。

## 六、文档体系纪律

### 6.1 三份根文档的分工

- `README详细开发指南.md` = 描述性长文档，**功能实现后的同步一律改它**。
- `README.md` = GitHub 门面，默认不动；用户点名改门面（排版 / 目录 / 徽章 / 截图 / 链接）时照做，不算违规。
- `CONTRIBUTING.md` = 协作细则唯一出处，**与 README 冲突时以 CONTRIBUTING 为准**；新增/修改流程类约定要同步改它。

### 6.2 README.md 的两段式结构与手写目录

- 结构：开头一组**无编号** `##` meta 节（特性 / 截图·Demo / 快速开始 / 文档 / 许可证 / 开发指南与贡献 / 路线图 / 社区 / 贡献者 / 致谢），
  再用一级标题 `# 详细开发内容` 分隔，其后才是**中文数字编号**的 `## 一` ~ `## 十七` 技术章节。
  新增项目级 meta 节进无编号区，新增技术章节才编号。
- GitHub 渲染器**不认 `[TOC]` 占位符**，所以「## 目录」是**手写两级锚点**，覆盖全部 `##` / `###`：
  **增删改任何标题都必须同步维护这份目录**。slug 规则：转小写 → 删掉除字母/数字/空格/连字符之外的所有字符
  （emoji、全角标点、`、`、`/`、全角括号全删）→ 空格逐个换连字符且**不 trim**
  （故 emoji 标题的锚点以 `-` 开头；`截图 / Demo` → `#截图--demo`；`五、Tag 与版本号` → `#五tag-与版本号`）。
- 校验用一次性脚本反推比对，**脚本必须跳过围栏代码块**，否则模板里的 `## 动机` 会报假阳性。
- 用户会手动重排 `README.md`（去编号、上移、加 h1 分隔），所以**每轮编辑前先 grep `^#{1,2}\s` 确认当前标题与行号**，
  不要沿用上一轮的行号。

### 6.3 `.github` 模板

- `PULL_REQUEST_TEMPLATE.md`：五段（动机 / 改动点 / 影响范围 / 验证方式 / 数据库变更）+ 自检清单。
- `ISSUE_TEMPLATE/bug_report.yml`（11 字段 5 必填）、`feature_request.yml`（7 字段 3 必填）、
  `config.yml`（保留空白 issue + 4 条联系链接，含安全漏洞私报入口）。
- 两条 GitHub 的脾气：① `labels` 里的标签必须仓库里已存在，否则**静默不打**；
  ② issue form 的 YAML 语法错了是**整份模板静默不显示**，改完必须本地 js-yaml 解析一遍。
  `render` 一旦设置，那个输入框就**不能拖附件**（所以「复现步骤」故意不设 `render`，只有「相关日志」用 `render: shell`）。

### 6.4 版本号现状

- `pom.xml` 的 `<im.version>` = `1.0.0`，**仓库至今没有任何 git tag**，历史 CHANGELOG 的版本标题用的是**日期**。
- 下版起标题改 `## [1.1.0] - 2026-11-01`；tag 一律 annotated（`git tag -a v1.1.0 -m ...`），tag 名 = `v` + 版本号，
  与 `im.version` 严格一致，且**打 tag 与改版本号在同一次提交**。
- 注意：`md/SQL变更文档.md` 里的版本号（起始 `1.0.0`）**只描述数据库脚本**，与代码版本、发布版本彼此独立。

### 6.5 提交纪律

- commit / PR 标题用 `type(scope): 中文描述`；**没有配 commitlint，也没有 CI workflow**，全靠自觉。
- 不提交：`target/`、`node_modules/`、`dist/`、`electron/release/`、`*.log`、`.env`、被控端 `config.properties`、
  模型文件（`im-ui/public/models/**`）。提交前 `git status --short` 扫一眼。
- ⚠ `.gitignore` 有一条**全局 `*.txt`**：新增 `.txt` 时 `git add` 会**静默跳过**且不报错
  （现有 `md/待开发功能.txt`、`md/综合.txt` 都是 `git add -f` 强推的）。写新文档优先 `.md`。
- 不把「一次改 300 个文件的格式化」和「一个功能」放同一个 commit。

### 6.6 文档只写必要描述：一条三要素，不超 3 行

用户口径原话（2026-11-08）：「以后在进行增加、修改文档操作时，只增加必要文字描述，不然大部分都是无效信息」。
本条就是这句口径的量化：**文档的职责是索引与取舍，不是过场记录**。

- **触发场景**：写 `md/CHANGELOG.md` 条目、往描述性文档里补一段、或改本规范以外的任何文档。
- **硬口径（一条 = 三要素，不超 3 行）**：
  1. **改了什么**（一句，带模块或入口名）；
  2. **为什么**（一句：取舍理由或根因，这是旧条目里最值钱、也最常被删掉的那一句）；
  3. **涉及文件路径**（一行，逗号分隔；多文件只列主要的 3~4 个，其余写「等 N 个文件」）。
- ★ **六类无效信息，不进文档**（实测占比最高的就是它们）：
  ① 验证过程叙述（跑了几次、`EXIT=0`、浏览器里怎么采的、探针与采样方法）；
  ② 一次性取证数字（`scrollTop` 900、像素 17px、字符 2911、某段 7575px 这类与下一轮无关的量）；
  ③ 自证型描述（「本轮零代码零 SQL」「零新依赖」同一句在不同子项里说三遍）；
  ④ 把源码注释或代码片段搬进日志（注释已在原地写清了理由，日志里再搬一份就成了第二处真相）；
  ⑤ 同一事实在同一条里换说法复述；
  ⑥ 工具链报错本身（PowerShell 语法、编辑工具写坏中文等），那些进第八节或记忆，不进变更日志。
- **细节的去处（只写一处，最多在本条里给一句「详见 X」）**：技术实现细节 →
  `README详细开发指南.md`；踩坑与根因 → `md/已踩坑.md`；长期口径 → 本文件；实测数字基线 → 本文件第八节；
  SQL 变更 → `md/SQL变更文档.md`。
- ★ **例外：这四类不是废话，必须留**——① DDL / 要用户执行的 SQL 及其影响；② **不重启 / 不重新打包就不生效**
  这类操作性提醒（漏了直接造成「改了没生效」）；③ 新增环境变量、配置键、接口路径这类下游要引用的清单；
  ④ 不可逆的数据处理与回滚入口。
- **结构纪律**：一个版本区内 `### 新增 Added` / `### 变更 Changed` / `### 修复 Fixed` **各只允许出现一次**，
  新条目插到既有分组下（顶部）；不要另起一组。`md/CHANGELOG.md` 的 Unreleased 区现存 6 个重复分组标题，
  属历史遗留，**按用户本轮口径历史条目一律不动**，只要求以后不再新增。
- *为什么*：`md/CHANGELOG.md` 实测 **487 KB / 971 行 / 154 条**，平均行长 **286 字**，其中子项展开行 **688 行**（占正文 71%）。
  写日志只为了一个用途：让半年后的人能在 30 秒内定位「这件事是哪轮改的」。
  过程叙述对读者零价值——它证明的是「我当时验过」而不是「现在是什么」，却把索引信号淹没；
  而细节本来已在详细指南 / 已踩坑里各有一份，出现第三处就开始了漂移。
- **反例**：一条改动写 8 行，其中 5 行是「怎么测的、测了几次、before/after 各多少」；
  或者同一条里先写「零新依赖」又写「本轮零代码零 SQL」——这两句不改变任何事实，删了不损失信息。

## 七、排查与验证方法论

1. **先证后端健康，再怀疑前端**。用**空体探针**（`POST {}`）打目标接口：
   参数校验（`@Valid`）在 AOP 与业务之前失败 ⇒ 回 `code:1008` 既**零写库**也不消耗 `@RateLimit` 配额；
   直连后端端口与经 vite 代理各打一次，就能把「后端挂了 / 代理挂了 / 前端没发请求」三种情况分开。
2. **区分「请求没发出」和「请求发了但报错」**：看 Network 里有没有那条 POST，比看 toast 可靠。
3. **矮视口是复现不了的常见根源**：`document.documentElement.clientHeight` 只有 490 时，
   弹窗里靠下的元素会整体在屏幕外，于是「点了没反应」——量一下元素的 `getBoundingClientRect().bottom` 再下结论。
4. **国产定制浏览器（荣耀 / 华为 / 小米 WebView）文件交互异常**：建**零依赖隔离测试页**（纯 HTML 的可见
   `<input type="file">` + JS `click()` 两组），同一 dev server 提供，问题浏览器与微信内浏览器各访问一次。
   表现一致 ⇒ 代码层问题；仅问题浏览器失效 ⇒ **站点级风控拦截**（多与访问过自签 HTTPS 有关），
   代码绕不过，解法是清站点数据 / 换端口 / 换浏览器。探针 toast 可确认点击事件与 JS 是否正常执行。
5. **前端地址回落三层**：`%APPDATA%\im-desktop\server-config.json` → 环境变量 `IM_SERVER_BASE` → 内置默认 `http://localhost:8080`。
   桌面端「无法连接服务器」先按这三层查；Web 部署同源走 vite 代理，**不产生 CORS**。
6. **前端路由是 hash 模式**：`/legal/terms` 这种 history 形式会被路由守卫弹回登录页，必须走 `#/legal/terms`。
   测页面时给错形式会误判成「页面挂了」。
7. **改完要真验证**：前端 `npm run build`（`im-ui`），后端 `mvn -pl <模块> clean package -DskipTests`；
   项目**没有自动化测试**，验收靠手动串测清单（见 `README详细开发指南.md` 的「验证清单」）。
8. **改了 CSS 但没在真机上验的部分，回复时要如实标出**（例如同意弹窗需要一个「有待签条款」的登录态才好实测）。
9. **dev 期「整个 `/api` 都 500 / 都连不上」九成不是代码问题，而是后端那个时刻没人监听 8080**。
   先走第 0 步：**网络面板里根本没有这条请求 ⇒ 不要查后端**，请求在本端就折了（见 4.5 的四层划分
   与「请求体不许放 ref/computed」那条）；请求发出去了才接着往下筛。
   30 秒定性三步：① 看后端日志的 `Started ImApplication` / `Graceful shutdown` 时间 vs 报错时间
   （日志目录由键 `im.log.home` 定，默认 `D:/rizi1/IM`，本机实测就在这个路径下拿 `info.log` / `error.log`）；② `curl -s http://localhost:8080/接口` 直连一次；
   ③ `curl -k https://localhost:5173/接口` 经代理再打一次。两条都 200 就是当时那个空窗，不用改代码。
   实测补一句：`localhost` 在本机 Node 下解成 `127.0.0.1`（`dns.resolve('localhost')` 实测），
   所以 `target: 'http://localhost:8080'` 不存在 IPv6/IPv4 错配，不要往这个方向白排查。

## 九、已废弃口径与冲突清单

以下旧说法**已作废**，遇到就按右列执行（这一节的意义是防止同一份规范被两个历史版本来回拉扯）：

| 作废口径 | 现状口径 |
|---|---|
| 「`im_schema.sql` 建 34 张表，另有 8 个 `migration_*.sql`」 | **43 张表、21 份增量脚本**（2026-11-08 实测） |
| 「maven-clean-plugin 的配置对全部 12 模块生效」 | **14 个模块** |
| 「通话主画面两端 `object-fit: cover` 铺满」（曾短暂实施） | 改为**背景同流 cover + blur 填充、前景 contain 居中**（cover 直铺会把异朝向流裁到约 23% 高度） |
| 「切换视角时先解绑 `srcObject`、`pause()`、再挂新流并 `load()`」 | 改为**固定绑定 + 只切 CSS 类**（不再重新赋值 `srcObject`），见 4.4 |
| 「语音通话也参与 `swapped` 互换」 | **互换只在 `isVideo` 时生效**（`swappedView = swapped && isVideo`），否则手机语音听不到对方 |
| 「协议 / 隐私 / 条款正文区自己做 `max-height + overflow + overscroll-behavior:contain`」 | 撤掉内层滚动，**一个弹窗只有一个滚动容器**（`.im-dialog--fit`），见 4.2 |
| 「校验失败只靠表单内联红字提示」 | 内联 + `scroll-to-error` + **`ElMessage.warning` 三件套**，见 4.2 |
| 「`el-link` 用 `:underline="false"`」 | 用 `underline="never"` |
| 「dev 期后端没起时页面只报「服务异常（HTTP 500）」/「无法连接服务器」」 | vite 代理改为回 **502 + `Result` 形状 JSON**（写明连不上哪个 target 与 errno），`request.js` 优先显示那句 message，见 4.5 与七.9 |
| 「`request.js` 把没有 `error.response` 的错误一律报成「无法连接服务器」」 | 已拆为两层：有 `error.request` 才叫连不上；连 `request` 都没有则报「请求未能发出（前端错误）：…」，见 4.5 四层 |
| 「点注册报「无法连接服务器」就先查后端 / 重启后端」 | **先看网络面板有没有这条请求**。一个都没有就是本端失败：本次真因是 `agreements: consentItems` 漏了 `.value`（computed 本体进了请求体），见 4.5 |
| 「文档里可以引用 `application.yml` 的行号 / 总行数」 | 只写键名与段名，见 1.6 |
| 「开发库 Redis 可以 `FLUSHDB`」 | 一律禁止，只 `DEL` 明确键，见 1.8 |

## 十、维护责任

- **只有用户改这份文件来立规矩**；助手若发现某条规矩与代码/文档现状不符，**先实测取证**再改，改完在 CHANGELOG 写明「原写 X，实测 Y」。
- 助手侧的长期记忆只保留「指向本文件」的入口 + 本文件不便承载的操作细节；
  若记忆与本文件冲突，**以本文件为准，并回头修记忆**。
- 每次新增规则要带：触发场景、硬口径（可判定的那条线）、为什么、反例或前科。四样缺一样，规则就只是愿望。
- 本文件超过 600 行就该考虑把某个专题（如直播、桌面端打包）拆成子文档，并在上面的边界表里登记位置。

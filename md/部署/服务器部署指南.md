# 服务器部署指南（生产环境要装哪些软件 + 从零到可访问）

本文面向**把这套系统部署到服务器对外提供服务**的场景：先给出一份「装什么、不装什么、为什么」的清单，
再按顺序走完 Linux 上的落地步骤（数据库初始化 → jar → systemd → Nginx → HTTPS → 自检），
最后是按功能的追加部署、运维流程与常见故障。

> **口径**：本文的每一个默认值、端口、开关都从仓库里读出来的，不是通用惯例——
> 版本取自根 `pom.xml`，端口与开关取自 `im-bootstrap/src/main/resources/application.yml`（983 行）与 `application-prod.yml`，
> 表结构取自 `sql/im_schema.sql`（37 张表）。改这些文件时请同步改本文。
> 命令以 **Linux（Ubuntu 22.04 / Debian 12 / CentOS 通用写法差异会标注）** 为主，Windows Server 见第十节。

## 〇、先看结论

**一台服务器上，最小可跑通全部业务功能的组合只有五个：**

| # | 软件 | 版本 | 少了会怎样 |
|---|---|---|---|
| 1 | **JDK** | **21**（不是 17、不是 8） | 编译与运行都起不来：根 pom `java.version=21`，且 `spring.threads.virtual.enabled: true` 依赖虚拟线程 |
| 2 | **MySQL** | **8.0+**（实测 8.4.10） | 起不来且建表就失败：`sql/im_schema.sql` 用了虚拟生成列与 `DEFAULT CHARSET = utf8mb4`，业务代码用了 `JSON_SET` |
| 3 | **Redis** | 5 / 6 / 7 均可（推荐 7.x） | **后端启动直接失败**——Sa-Token 会话、验证码、在线状态、消息序号都落在这里 |
| 4 | **Nginx** | 1.20+ | 严格说不是「起不来」，而是没有可用入口：静态站、`/api` 反代、`/ws` 的 WSS 升级、HTTPS 证书都得有人干 |
| 5 | **MinIO**（或显式改成 `local`） | 任意近期 RELEASE | ★ **这是个坑**：`im.file.storage` 的默认值是 `minio`（`application.yml` L370），而 `MinioFileStorage` 连不上桶会抛 `IllegalStateException` **让启动 fail-fast**。不装 MinIO 就必须显式 `IM_FILE_STORAGE=local` |

前端三份（`im-ui` / `im-admin-ui` / `im-website`）在服务器上是**纯静态文件**，跑起来不需要 Node——
只有在「服务器上现场构建 dist」或「用 `electron/live-media-server.js` 顶替 Nginx 做直播媒体面」时才需要 Node.js。

**当前只能单实例部署后端**，不要一上来就摆两台：WebSocket 推送只认本进程的连接表（`PushSpiImpl`），
跨节点扇出在代码注释里被明确列为「同一道待办」，12 个 `@Scheduled` 任务也没有任何分布式锁（仓库里没有 ShedLock）。
详见第七节。

> 本文是**裸机口径**（apt 装服务 + systemd 拉起）。如果这台机器上的服务打算跑在容器里，
> 直接看同一目录的 [`Docker部署指南.md`](Docker部署指南.md)（Ubuntu 24.04 + docker compose）：
> 软件清单与业务约束完全沿用本文，**变的是四个值（`MYSQL_HOST` / `REDIS_HOST` / `MINIO_ENDPOINT` / 路径类变量）与三条假设（127.0.0.1 是本机、防火墙能挡端口、loopback 谁都摸得到）**。
> 两份冲突时，容器相关口径以 Docker 那份为准。

### 端口清单（谁监听、是否对外）

| 端口 | 协议 | 谁在用 | 能否对公网开放 | 依据 |
|---|---|---|---|---|
| 80 / 443 | TCP | Nginx | ✅ 唯一应该开放的 | — |
| 8080 | TCP | 后端 HTTP + WebSocket | ❌ 只让 Nginx 走 `127.0.0.1` | `server.port: ${SERVER_PORT:8080}` |
| 8081 | TCP | Actuator（health/info/prometheus/metrics） | ❌ **默认就只绑 127.0.0.1** | `management.server.address: ${MANAGEMENT_ADDRESS:127.0.0.1}` |
| 3306 | TCP | MySQL | ❌ 内网 | `MYSQL_PORT` |
| 6379 | TCP | Redis | ❌ 内网，且必须设密码 | `REDIS_PORT` |
| 9000 / 9001 | TCP | MinIO API / 控制台 | ❌ 内网（9001 控制台尤其别露） | `MINIO_ENDPOINT` |
| 8088 | TCP | 直播推流口（主播 PUT 分片） | ⚠ 只放行主播出口 IP，其余 `deny all` | `md/直播.md` §10.4 |
| 3478 | TCP+UDP | coturn STUN/TURN | ✅ 只在跨 NAT 通话时开 | `IM_CALL_STUN_URLS` / `IM_CALL_TURN_URLS` |
| 8947 | **UDP** | 远控 UDP 打洞的地址反射服务 | ✅ 仅在 `IM_DIRECT_ENABLED=true` 时需要 | `im.direct.punch-port` |
| 18923 | TCP | Agent 本机识别码只读接口 | ❌ **不在这台机器上**，Agent 跑在被控桌面且只绑 127.0.0.1 | `md/远程控制Agent使用说明.md` §五 |

> **注意 8947 是 UDP**，不是 TCP。Linux 上用 `ufw allow 8947/udp`，Windows 上 `netsh advfirewall` 要写 `protocol=UDP`（`application.yml` L817 的注释里就是这个命令）。开成 TCP 的表现是「打洞永远失败、永远回落中继」，而中继是通的，所以从功能上看不出问题——只有流量账单和延迟会告诉你没生效。

## 二、软件清单

### 2.1 必需（五个，见第〇节）

安装（Ubuntu/Debian）：

```bash
# 1) JDK 21
sudo apt install -y openjdk-21-jre-headless
java -version          # 必须显示 21.x

# 2) MySQL 8
sudo apt install -y mysql-server
# 3) Redis 7
sudo apt install -y redis-server
# 4) Nginx
sudo apt install -y nginx
```

MinIO 用官方单文件（Linux）：

```bash
wget https://dl.min.io/server/minio/release/linux-amd64/minio -O /usr/local/bin/minio
chmod +x /usr/local/bin/minio
```

CentOS/RHEL 把 `apt install -y` 换成 `dnf install -y`，JDK 包名是 `java-21-openjdk-headless`。

### 2.2 按功能选装

| 软件 | 什么时候必须要 | 说明 |
|---|---|---|
| **Node.js ≥ 20** | ① 在服务器上现场构建前端 dist；② 用 `node electron/live-media-server.js` 顶替 Nginx 做直播媒体面（局域网自测形态） | 生产更推荐「构建机出 dist → 拷到服务器」，服务器上就只需要 nginx |
| **certbot**（或自备证书） | 对外用 HTTPS | ★ 不只是「加密」：浏览器的 `getUserMedia`（语音/视频通话、摄像头）只在**安全上下文**里可用，http 打开的页面点通话会直接拿不到媒体权限。见 `md/手机真机调试HTTPS配置指南.md` |
| **coturn** | 公网跨 NAT 的语音/视频通话、远控需要中继 | 配 `use-auth-secret`，其密钥必须与 `IM_TURN_SECRET` **逐字一致**（服务端按「过期时间戳:userId」生成临时凭据） |
| **Prometheus + Grafana**（可选） | 要监控告警 | Actuator 已经配好独立端口与只暴露 4 个端点，照抄 `md/监控告警部署指南.md` 即可 |
| **邮件服务 / 短信服务**（不是软件） | 邮箱验证码、短信验证码 | 只有环境变量：`MAIL_USERNAME` + `MAIL_PASSWORD`（QQ 邮箱的 **SMTP 授权码**，不是登录密码），`IM_SMS_PROVIDER` |

### 2.3 明确**不要**装到服务器上

| 东西 | 为什么不 |
|---|---|
| Maven | 可以在构建机/CI 上打包再把 jar 拷过来，服务器不需要编译器。要装也行（`apt install maven`），但别在服务器上跑 `mvn`：那是把构建依赖与网络抖动引进生产 |
| ffmpeg | 直播推流与远控 H.264 编码都发生在**客户端**：Electron 桌面端已内置（`electron/bin`）。服务器上「一个媒体字节都不碰」是这套架构的既定分工（`md/直播.md` §4） |
| `im-remote-agent` | 被控端程序，需要**图形环境**（`java.awt.Robot` 截屏 + Swing 界面），明确要求不能 `-Djava.awt.headless=true`；无显示器的服务器不适合作为被控端 |
| Electron / Tauri / Capacitor / Android Studio | 客户端打包工具链，属于开发机 |

### 2.4 版本相关的三个坑

1. **Redis 5 也能跑，不用改代码。** `application.yml` L34-36 排除了 Sa-Token 官方的 `SaTokenDaoForRedisTemplate`（它在写回会话时下发 `SET ... KEEPTTL XX`，KEEPTTL 要 Redis 6.0+），换成 `im-common` 的 `SaTokenDaoForLegacyRedis`（PTTL + SET XX 两步等价实现）。那个类的注释写明「本实现在 Redis 6/7 上同样正确，代价只是把一条命令换成同一连接上的两条」——所以**推荐直接上 Redis 7**，这条 exclude 留着即可，不要因为「看起来是为 Redis 5 写的」就以为要动代码。
2. **MySQL 的 `max_connections` 要和 Hikari 一起算。** `application-prod.yml` 把 `maximum-pool-size` 抬到 50、`minimum-idle` 10。约束是 **50 × 实例数 必须明显小于 `max_connections`**，否则连接池会先把数据库连接抢光、新实例启动直接连不上。单实例 + 默认 `max_connections=151` 是安全的。另外 `max-lifetime: 1800000`（30 分钟）必须**小于** MySQL 的 `wait_timeout`（默认 8 小时）——只改一边会留下一批「看着健康、一用就 Communications link failure」的死连接。
3. **MinIO 桶名与自动建桶。** 桶不存在时启动阶段会自动创建，无需手工建桶；但桶名要符合 S3 规范（≥3 字符、只允许小写字母/数字/点/连字符），填 `im` 这种过短名会被 SDK 拒绝**导致启动失败**。默认桶名 `im-files` 是合法的。

## 四、初始化数据库（先分清全新库和存量库）

### 4.1 ★ 一句话结论

| 你的库 | 该跑什么 |
|---|---|
| **全新环境**（还没有 `im_db`） | 只跑 `sql/im_schema.sql` + `sql/im_data.sql`，**14 份 `migration_*.sql` 一份都不许跑** |
| **存量库**（早期版本建的，要升级） | **绝不能跑 `im_schema.sql`**，只按第六节的 migration 顺序补增量 |

为什么必须钉死这两句：

- 全部 14 份 migration 的产物**早就并回那两份全量脚本了**（2026-10-27 做过逐表逐列逐索引 + 逐行种子的对账，结论见 `md/数据库表解析.md` §14.10）。新库再跑一遍 migration 属于纯冗余。
- `sql/im_schema.sql` 的第 24-60 行是 **37 条 `DROP TABLE IF EXISTS`**（它靠这个实现幂等重建）。存量库跑它 = **清库重建**，真实账号、聊天记录、会话、好友关系全没。

### 4.2 全新库

```bash
# 建库建表（脚本头部自带 CREATE DATABASE IF NOT EXISTS im_db ... utf8mb4，无需先手工建库）
mysql -u root -p --default-character-set=utf8mb4 -e "source /opt/im/sql/im_schema.sql"
# 灌种子数据（角色权限、演示账号、演示会话、礼物目录）
mysql -u root -p --default-character-set=utf8mb4 im_db -e "source /opt/im/sql/im_data.sql"
```

`--default-character-set=utf8mb4` **不要省**：不带它，脚本里的中文表注释、列注释和礼物名会按连接的默认字符集处理成乱码，而注释坏掉从前端完全看不出来。
同理不要用 `Get-Content xxx.sql | mysql`（Windows 侧）——管道编码会把中文刷成 `?`。

**验证建满 37 张表**：

```sql
SELECT COUNT(*) FROM information_schema.TABLES WHERE TABLE_SCHEMA='im_db';
```

### 4.3 ★ 生产环境要不要跑 `im_data.sql`

`im_data.sql` 的头部注释写得很清楚：它灌的是**演示数据**，包含 `admin / 123456`、`alice / 123456`、`bob / 123456` 等账号（密码是 Argon2 密文，明文就是这串），以及演示好友关系、会话、历史消息、4 场面试会话。

两种正确做法，选一种：

- **A（推荐）**：跑它，然后**立刻**改掉 `admin` 密码并用不上的演示账号逻辑删除。好处是 RBAC 的四角色 22 个权限点、礼物目录 8 条种子一次到位，后台开箱可用。
- **B**：只跑 `im_schema.sql`，然后自己补 RBAC 种子（`im_role` 4 行 + `im_permission` 22 行 + `im_role_permission` 32 行 + `im_gift` 8 行，都在 `im_data.sql` 里，按 `id` 段挑出来单独执行）与一个真实管理员账号。

把一个 `admin/123456` 挂在公网域名上，等价于把后台交给第一个扫到 `/api/auth/login` 的人。这条要进上线检查清单（第八节）。

好消息是 `im_data.sql` 的清理段**只规整自己的种子 ID 段**（`1~9999` 与 `2300~9399`），不会碰运行期写入的 19 位雪花 ID 数据，所以对已有真实数据的库也可以安全重跑——但它会重灌那批演示账号。

## 五、后端：构建、配置、systemd

### 5.1 构建

在构建机上（需要 JDK 21 + Maven 3.9+）：

```bash
mvn clean package -DskipTests
```

产物只有一个 jar 要带走：

```
im-bootstrap/target/im-server.jar        # 可执行 fat jar，主类 com.im.bootstrap.ImApplication
```

拷到服务器 `/opt/im/bin/im-server.jar`。

> 如果只在服务器上更新某一个模块，构建命令是 `mvn -q -pl im-bootstrap -am package -DskipTests`。
> **别在服务器上直接跑 `mvn spring-boot:run`**：跨模块依赖从本地仓库 `~/.m2` 解析，改了 `im-common` 而不 `install`，跑的是旧 jar 且**不报错**。

### 5.2 环境变量（写进一个文件，权限 600）

`/opt/im/conf/im.env`：

```bash
# ===== 必填 =====
SPRING_PROFILES_ACTIVE=prod                 # dev 会在响应里回显验证码明文
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DATABASE=im_db
MYSQL_USER=im
MYSQL_PASSWORD=<你的库密码>
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=<你的 redis 密码>
IM_JWT_SECRET=<换掉内置开发用长串>            # Sa-Token JWT 签名密钥
IM_TICKET_SECRET=<换掉内置开发用长串>          # WS 连接票据 / 文件访问票据签名密钥
IM_LOG_HOME=/var/log/im                      # ★ 默认是 D:/rizi1/IM，Linux 下不改就是「日志静默丢失」
IM_UPLOAD_TMP_DIR=/opt/im/upload-tmp         # 分片先落本地临时目录，合并后才写存储

# ===== 文件存储：二选一，不许「两个都不管」=====
# 形态 A：装 MinIO（推荐，多实例/CDN 友好）
IM_FILE_STORAGE=minio
MINIO_ENDPOINT=http://127.0.0.1:9000
MINIO_ACCESS_KEY=<改掉 minioadmin>
MINIO_SECRET_KEY=<改掉 minioadmin>
MINIO_BUCKET=im-files
# 形态 B：不装 MinIO，用本地磁盘
# IM_FILE_STORAGE=local
# IM_FILE_DIR=/data/im-files

# ===== 按需 =====
IM_AI_KNOWLEDGE_DIR=/opt/im/knowledge        # 默认 D:/资料/知识库/面试官（Windows 路径，Linux 必须覆盖）
ALI_BABA_API_KEY=<百炼 Key，不设则仅面试功能不可用>
IM_SMS_PROVIDER=aliyun                       # 默认 mock：只写日志、不发真短信，用户永远收不到码
MAIL_USERNAME=you@qq.com                     # 邮箱验证码发件人（不配则邮箱登录/找回不可用）
MAIL_PASSWORD=<QQ 邮箱的 SMTP 授权码，不是 QQ 登录密码>
IM_LIVE_SIGN_SECRET=<与 Nginx secure_link_md5 的 secret 逐字一致>
IM_LIVE_PUSH_BASE_URL=http://127.0.0.1:8088/live
IM_LIVE_PLAY_BASE_URL=https://live.example.com/live
IM_CALL_STUN_URLS=stun=<公网IP>:3478
IM_CALL_TURN_ENABLED=true
IM_CALL_TURN_URLS=turn=<公网IP>:3478?transport=udp
IM_TURN_SECRET=<与 coturn 的 use-auth-secret 逐字一致>
IM_DIRECT_ENABLED=true                       # 远控直连（要同时放行 UDP 8947 与设 IM_DIRECT_PUNCH_HOST）
IM_DIRECT_PUNCH_HOST=<服务器对外可达的公网 IP>
MANAGEMENT_ADDRESS=127.0.0.1                 # Prometheus 在别的机器时改成内网地址并配防火墙白名单
```

```bash
sudo chmod 600 /opt/im/conf/im.env && sudo chown im:im /opt/im/conf/im.env
```

三个「不改就出事」的默认值，单独拎出来：

| 变量 | 代码里的默认值 | 不改的后果 |
|---|---|---|
| `IM_FILE_STORAGE` | **`minio`**（`application.yml` L370） | 装了 MinIO 却想走本地磁盘 / 没装 MinIO 又没设 `local`：`MinioFileStorage` 桶初始化失败抛 `IllegalStateException`，**进程直接起不来**（这是刻意的 fail-fast，不是 bug） |
| `IM_LOG_HOME` | `D:/rizi1/IM` | 目录不可写时 logback **只打一条 status 错误、不拦启动** → 日志静默丢失，出事时没线索 |
| `IM_AI_KNOWLEDGE_DIR` | `D:/资料/知识库/面试官` | Linux 上这个路径不存在，面试知识库检索空转（不报错，只是永远查不到东西） |

`IM_WALLET_MOCK` 保持默认 `false`：设成 `true` 会注册模拟支付桩，**等于无限白送积分**（本项目没有接真实支付通道）。

### 5.3 systemd 单元

`/etc/systemd/system/im-server.service`：

```ini
[Unit]
Description=IM Instant Messaging Server
After=network-online.target mysql.service redis-server.service minio.service
Wants=network-online.target

[Service]
Type=simple
User=im
Group=im
```

```bash

curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/api/auth/me   # 期望 200 + body 里 code=1002（未登录），不是 404
```

### 5.5 Nginx 站点（核心样板）

`/etc/nginx/conf.d/im.conf`：

```nginx
# ---- 聊天端 im-ui ----
server {
    listen 443 ssl http2;
    server_name im.example.com;

    ssl_certificate     /etc/letsencrypt/live/im.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/im.example.com/privkey.pem;

    client_max_body_size 110m;          # 与 spring.servlet.multipart.max-request-size(110MB) 对齐，小了会被 Nginx 先 413

    root /var/www/im-ui;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;   # SPA history 路由回退，少了它刷新子页面全 404
    }
    location ~* \.(js|css|png|jpg|svg|woff2)$ {
        expires 7d;
        add_header Cache-Control "public";
    }

    # ★ WebSocket：必须显式给 Upgrade 头并拉长读超时，否则长连接 60s 就被默认 send_timeout 掐断
    location /ws {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host       $host;
        proxy_set_header X-Real-IP  $remote_addr;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }

    location /api {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;           # 大文件合并、AI 流式回答都可能较慢
    }
}

# ---- 管理后台 im-admin-ui：与聊天端分开一个 server 块，别共用 root ----
server {
    listen 443 ssl http2;
    server_name admin.example.com;
    # ...证书同法
    root /var/www/im-admin-ui;
    location / { try_files $uri $uri/ /index.html; }
    location /api { proxy_pass http://127.0.0.1:8080; proxy_set_header Host $host; }
    # 后台不建长连接也不播流，因此不需要 /ws 与 /hls 代理（与 im-admin-ui/vite.config.js 的口径一致）
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

**两个站点的 `/api` 都指向同一个后端**，鉴权由 Sa-Token 按权限点分开，不需要两个后端进程。
后台侧还有一条运维红线：**不要**用 `admin.example.com` 暴露 `/doc.html`（`prod` profile 已经把 knife4j 与 springdoc 全关，`/doc.html` 回 404，这是设计如此，别在 Nginx 上再给它开洞）。

### 5.7 ★ 换域名必须动的第二处：CORS 白名单

后端 `im.cors.allowed-origins`（`application.yml` L638-681）是一份**写死的字面列表**
（`localhost:5173/4173/5273/4273/4373` 的 http+https 两套、`tauri://localhost`、`capacitor://localhost`、`http://*.*.*.*:5173` 四段通配），
**没有 `${}` 占位符**，所以它**不能靠环境变量改**。部署到真实域名后有两条路：

- **A（推荐，不动 jar）**：外挂一份生产配置覆盖它。`/opt/im/conf/application-prod-extra.yml`：

  ```yaml
  im:
    cors:
      allowed-origins:
        - https://im.example.com
        - https://admin.example.com
        - https://www.example.com
  ```

  然后在 systemd 的 `ExecStart` 追加：

  ```
  --spring.config.additional-location=/opt/im/conf/application-prod-extra.yml
  ```

- **B**：直接改 `application.yml` 后重新 `mvn package`。

不改的表现是所有浏览器请求回 `403 Invalid CORS request`，而 `curl` 一切正常——很容易误判成后端或 Nginx 的问题。
同一份 CORS 判定还参与 WebSocket 握手（`WebSocketConfig` 用 `setAllowedOriginPatterns("*")` + `WsOriginNormalizeFilter` 兜同源），
所以聊天端的跨域问题会同时出现在 HTTP 与 WS 两条通道上。

## 六、存量库升级：migration 执行顺序

**顺序 = 功能上线的时间顺序**。每份脚本都带只读预检段（先跑预检，已经命中就不用跑），且写操作幂等。

| 序 | 脚本 | 干了什么 | 跑完要清缓存吗 |
|---|---|---|---|
| 1 | `migration_quote_message.sql` | `im_message` 加 `quote_msg_id` 列 + 索引 | 否 |
| 2 | `migration_message_favorite.sql` | 新建 `im_message_favorite` | 否（★ 不跑会**消息列表整片 500**，不是「只有收藏不好用」） |
| 3 | `migration_report.sql` | 新建 `im_report` | 否（不跑则一进后台看板就 `Table 'im_db.im_report' doesn't exist`） |
| 4 | `migration_linkmic_gift.sql` | 新建 `im_user_wallet` / `im_gift` / `im_gift_record` / `im_wallet_transaction` + 8 条礼物种子 | 否 |
| 5 | `migration_missing_tables.sql` | 汇总补齐：表情回应 / 投票 / 群精简 / 入群审批 / 群机器人 等「只更新了全量脚本、没留增量」的表与列 | 否 |
| 6 | `migration_admin_phase2.sql` | 零 DDL，加 4 个细粒度权限点（108~111）+ moderator/operator 两个示范角色 + admin 绑定 | ✅ **要清 `im:auth:*`** |
| 7 | `migration_admin_phase3.sql` | 零 DDL，加权限点 112~115 | ✅ |
| 8 | `migration_user_ban_duration.sql` | 本批唯一 DDL：`im_user.disable_until` + 索引 | 否 |
| 9 | `migration_admin_config.sql` | 零 DDL，权限点 116 `system:config` | ✅ |
| 10 | `migration_admin_remote.sql` | 零 DDL，权限点 117 `system:remote` | ✅ |
| 11 | `migration_admin_system_config.sql` | **建三张表** `im_config` / `im_sensitive_word` / `im_announcement` + 权限点 118 | ✅ |
| 12 | `migration_admin_wallet_interview_group_message.sql` | 零 DDL，权限点 119~122 + admin 绑定 6019~6022 | ✅ |
| 13 | `migration_gift_icon_width.sql` | 把存量库 `im_gift.icon` 从 `varchar(64) NOT NULL` 加宽到 `VARCHAR(512) NULL`，与 `im_schema.sql` 对齐 | 否 |

### ★ 铁律：新开或收掉权限点，跑完 SQL 必须清权限缓存

`PermissionProviderImpl` 把 `im:auth:perm:{userId}` / `im:auth:role:{userId}` 在 Redis 里缓存 **30 分钟**，
而**登录动作不会刷新它**。所以只跑 SQL 不清缓存的表现是：数据库里权限已经有了，人还是 403，
而且「等半小时自己就好了」——这条最容易在验收时被误判成代码没生效。

```bash
# 正确姿势：先列后删，两条命令（★ 不要写 redis-cli --scan | xargs redis-cli DEL，也不要拼 EVAL 字符串）
redis-cli -a "$REDIS_PASSWORD" --scan --pattern 'im:auth:*' > /tmp/authkeys.txt
redis-cli -a "$REDIS_PASSWORD" DEL $(cat /tmp/authkeys.txt)
# 复核残留必须为 0
redis-cli -a "$REDIS_PASSWORD" --scan --pattern 'im:auth:*' | wc -l
```

> Windows PowerShell 下这两条要**分两次执行**：把 `keys` 的结果管道给 `del` 会静默什么都不删（实测踩过：10 个键全在）。

纯 DDL 与纯业务表的 migration（加列、建表）不需要清缓存——清了也无害，只是白刷一次缓存命中率。

## 七、扩容与多实例（现在不行，原因在这里）

**结论：当前请单实例部署后端。** 三条已核实的依据：

1. **WebSocket 推送只认本进程的会话表**。`PushSpiImpl` / `WsSessionManager` 的注释直说：用户连在另一个节点上时本节点推不到；
   通话信令（`CallSignalingService`）、群通话（`GroupCallSignalingService`）、连麦（`LiveLinkSignalingService`）三处都写着「跨节点扇出与消息推送是**同一道待办**」。
   做会话保持（sticky session）也没用——HTTP 请求会均衡到别的节点，而发送消息的那个节点找不到用户的连接。
2. **12 个 `@Scheduled` 定时任务没有任何分布式锁**（仓库内无 ShedLock 依赖，也没有别的选主机制）。
   起两个实例 = 每个任务跑两遍：`RedPacketRefundTask` 靠「`refund` 流水行本身当幂等锁」侥幸安全，但
   `ChunkUploadServiceImpl` 的过期分片清理、`MessageExpireCleanTask`、`LiveCheckTask`、`WsIdleCheckTask` 都是白干两遍。
3. **本地缓存 L1（Caffeine 120s）的失效只作用于本节点**，多实例靠 TTL 收敛（`md/多端入口与缓存全链路图.md` 已把这条写成已知取舍）。这条只影响「最长 120 秒的脏读窗口」，是可以接受的；前两条不是。

真要横向扩容，先做的三件事（按投入产出排序）：

1. 给定时任务加 ShedLock（改依赖 + 12 个方法上各一个 `@SchedulerLock`，业务逻辑不动）；
2. 给 WS 扇出加 Redis pub/sub（`convertAndSend` + 每节点订阅），或改成「按 userId 一致性哈希路由到固定实例」；
3. 数据库侧：`im.file.storage` 必须已经是 `minio`（本地磁盘在多实例下会把同一个用户的文件写到不同机器上）。

多实例期间的 Hikari 上限要按 `50 × 实例数 < max_connections` 重新算（见 §2.4）。

## 九、日常运维

### 9.1 日志

`IM_LOG_HOME` 下的实际布局（定义在 `im-common/src/main/resources/logback-spring.xml`，**活动文件名固定、跨天才滚成带日期的归档**）：

```
/var/log/im/info.log                       当天主日志；跨天滚成 info-yyyy-MM-dd.N.log（单文件超 50MB 滚序号，留 30 天，总量上限 5GB）
/var/log/im/warn.log                       同上规则
/var/log/im/error.log                       错误档，留 60 天（量最小、复盘最想翻）
/var/log/im/DEBUG.log                       只收 DEBUG：prod 下 `com.im` 是 INFO，这一档基本为空
/var/log/im/SQL/slow-sql.log                单条语句超 im.log.slow-sql-millis（默认 100ms）才进来
/var/log/im/SLOW-API/slow-api.log           慢接口告警
/var/log/im/MODERATION/moderation.log       内容审核命中记录（事后追责用，不是排障用）
/var/log/im/stdout.log                      systemd 收的 stdout/stderr
```

三条相关的运维口径：

- **`SQL/`、`MODERATION/` 两档按敏感数据对待**：慢 SQL 文件里是**完整 SQL 文本与真实参数值**，可能含手机号等个人信息，目录权限要按这个前提设（`md/数据库表解析.md` 与 logback 头部注释都写了这句）。
- 那三个专用通道都是 `additivity=false`：不设的话同一条慢 SQL 会既进 `SQL/`、又进 `info.log`，重复打印。
- **老环境里可能残留 `im-server.log` / `im-server-error.log`**：那是历史配置的产物，当前 logback 不再写这两个名字，清理磁盘时按过期文件对待。

`prod` profile 把 `logging.level.com.im` 钉在 `info`：**不要**在生产开 DEBUG——
`WebLogAspect` 在 DEBUG 下会输出完整出入参，消息正文与手机号会落进日志文件，那是隐私数据。

### 9.2 备份

```bash
# 数据库：每天一次，逻辑备份（37 张表体量小，mysqldump 足够）
mysqldump -u im -p"$MYSQL_PASSWORD" --single-transaction --default-character-set=utf8mb4 im_db | gzip > /backup/im_db_$(date +%F).sql.gz

```

保留期之外要留的东西：`im.env`（脱敏后归档进密钥管理，不进 git）、Nginx 配置、证书、以及数据库备份本身。

### 9.3 升级与回滚

```bash
# 1. 备份数据库（必做，即使这次「只是改前端」）
mysqldump ... > pre_upgrade.sql
# 2. 存量库按第六节顺序跑新增的 migration（每份都带只读预检段，先跑预检）
# 3. 换 jar
sudo systemctl stop im-server
cp /opt/im/bin/im-server.jar.new /opt/im/bin/im-server.jar
sudo systemctl start im-server
# 4. 自检（§8 里那三条 curl）+ 若这次动了权限点，清 im:auth:*
# 5. 前端 dist 直接替换目录内容，无进程需要重启
```

回滚时**只回 jar 不回 SQL** 是常见做法，但要注意：加列/建表类改动向后兼容（旧 jar 不认识新列，不报错），
而 `migration_admin_phase2/3`、`_config`、`_remote`、`_system_config`、`_wallet_interview_group_message` 这批**权限点行是配套的**
——旧 jar 里没有那些控制器，多几行权限点无害；反过来「新 jar + 没跑 SQL」会 500/403，所以顺序永远是 SQL 在前。

## 十、按功能的追加部署

### 10.1 直播（im-live）

控制面在 Java 里（房间状态、播放地址签名、弹幕 WS），**媒体面是独立的**，一个媒体字节都不经过后端。
媒体面两形态选一个：

| 形态 | 怎么起 | 适用 |
|---|---|---|
| **Nginx 双口**（生产） | 推流口 `listen 8088` + `dav_methods PUT DELETE` + `limit_except PUT { deny all; }`；播放口 `listen 443` + `secure_link` + CORS + 缓存分层 | 正式对外。完整配置直接抄 `md/直播.md` §10.4 / §10.5，本文不重抄一遍 |
| **Node 脚本**（自测） | `node electron/live-media-server.js`（默认 8088，`PORT` 可覆盖） | 局域网多机观看；★ **它不校验签名**，防盗链只靠路径里不可猜的 `streamKey`，不能当生产用 |

三处必须一致，否则一定 404/403：

1. **URL 前缀**：`im.live.play-base-url` / `push-base-url` 的最后一段，与 Nginx 的 `location` 名，与磁盘目录名。
   生产约定用 `/live`（`md/直播.md` §10.3：`root /data` ⇒ URI `/live/...` → `/data/live/...`），
   而 yml 默认值是 `/hls`（那是配 `live-media-server.js` 的 `URL_PREFIX='/hls'` 用的）。**上生产显式设成 `/live` 并让 location 跟着改**，别指望默认值。
2. **签名密钥**：`IM_LIVE_SIGN_SECRET` 与 Nginx `secure_link_md5 "${uri}${arg_expire}<secret>"` 里的 secret **逐字一致**，且签名**只加在主清单 `index.m3u8`**——
   变体清单与分片不签（hls.js 从主清单按相对路径拉变体，不会带上 `?expire=&sign=`；这里也签就全 403）。签名编码是 **base64url，不是十六进制**。
3. **回放保留期**：`IM_LIVE_REPLAY_RETENTION_DAYS`（后端侧，默认 **1 天**）与媒体机上的清理逻辑**必须是同一个数**，
   两边不一致的表现是「后台列表有这条回放、点进去 404」。默认只留 1 天是有意的磁盘护栏，想要更久必须两边一起调大。

推流端不在服务器上：主播用 Electron 桌面端（内置 ffmpeg），`ffmpeg` 不需要装在服务器上。

### 10.2 语音/视频通话与远控直连（WebRTC）

信令走已有的 WS 长连接，**媒体点对点直连，一个媒体字节都不经服务器**（所以服务器带宽几乎不受通话影响）。
需要装软件的是「跨 NAT 打不通」那一档：

- **STUN**：`IM_CALL_STUN_URLS=stun=<公网IP>:3478`（coturn 自带 STUN 能力，不必单独装 csstun）。留空 = 只做局域网直连，公网两端连不上。
- **TURN**：`IM_CALL_TURN_ENABLED=true` + `IM_CALL_TURN_URLS` + `IM_TURN_SECRET`（与 coturn `use-auth-secret` 一致）。
  服务端按「过期时间戳:userId」生成临时凭据（TTL 86400s），`secret` 留空则**不下发 TURN**。
  ★ TURN 是流量放大器：所有走中继的音视频都算服务器出口带宽，先估容量再开。
- **远控直连**：`IM_DIRECT_ENABLED` 默认 `false`（全程中继，功能完整，只是延迟高）。打开时要设 `IM_DIRECT_PUNCH_HOST`
  （服务器对外可达地址，这个值服务端猜不出来）并放行 **UDP 8947**。该反射接口无状态无鉴权，有 `punch-rate-limit=20`/60s 限流兜住被当放大器的风险。
- 群通话是 **mesh 不是 SFU**，服务端硬夹在 `[2,6]` 人（`IM_CALL_GROUP_MAX_SLOTS` 填 10 也只按 6 生效）——
  人数上限受的是**每个参会者的上行带宽**，不是服务器。要十几人会议得另立项目引 SFU。

### 10.3 AI 面试官与全网检索

只需要 `ALI_BABA_API_KEY`（百炼 DashScope，模型名走 `AI_MODEL_NAME` / `AI_ASR_MODEL_NAME` / `AI_TTS_MODEL_NAME` / `AI_TTS_VOICE`）。
不设 Key 时只有面试相关功能回「未配置」，其余功能照常。音色名必须落在所配 omni 模型的音色表里
（实测 `qwen3-omni-flash` 不认 `Tina`，默认女声是 `Cherry`）。

### 10.4 验证码通道（短信 / 邮箱）

`prod` profile 关掉了**一切**回显：`expose-sms-code` / `expose-image-code` / `expose-email-code` 全是 `false`，
并且 `mock-mail-when-unconfigured: false`——SMTP 没配就直接报 `MAIL_NOT_CONFIGURED`，**不降级成「只写日志」**（刻意如此：
降级会让「忘配环境变量」变成「找回密码静默失效」，而且日志里带明文验证码）。
短信侧相反：不设 `IM_SMS_PROVIDER` 会退回 `mock`，只写日志不发真短信，用户永远收不到码（失败方向是「发不出去」，不是「绕过校验」）。
所以上线前必须把它换成真实服务商。

### 10.5 监控告警

单独一份文档：`md/监控告警部署指南.md`（Actuator 端点保护、`prometheus.yml` 抓取片段、`alert.rules.yml` 样例、Grafana 一页盘、慢接口告警的三条消费路径）。
本文只强调一条默认口径：**8081 只绑 127.0.0.1 且只暴露 `health,info,prometheus,metrics` 四个端点**，
`env` / `configprops` / `heapdump` / `loggers` 全部不暴露（那些能泄配置、能改运行态）。

## 十一、Windows Server 上的差异

如果服务器是 Windows（本项目的开发机就是 Windows，`md/MySQL启动.md` / `md/Redis自启动.md` / `md/自启动miniio.md` / `md/windos开发环境指南.md` 全是 Windows ZIP + NSSM 的部署口径，可直接复用），差异集中在五点：

1. **服务注册**：后端没有官方 Windows service，用 **NSSM** 把 `java -jar im-server.jar` 注册成服务（三个基础件的 NSSM 步骤已在上述四份文档里写全，同一套工具）。
2. **路径类环境变量必须覆盖**：`IM_LOG_HOME`（默认 `D:/rizi1/IM`）、`IM_FILE_DIR`、`IM_UPLOAD_TMP_DIR`、`IM_AI_KNOWLEDGE_DIR`。
3. **Nginx for Windows 不适合生产**（官方明确说明其 Windows 版在性能与稳定性上受限）。要么用 **IIS ARR** 反代 + 静态站，要么在这台机器前挂一台 Linux Nginx/负载均衡。
4. **防火墙**用 `netsh advfirewall firewall add rule name="..." dir=in action=allow protocol=TCP localport=443`（UDP 那条写 `protocol=UDP`）。
5. **PowerShell 的三个已实测坑**（本仓库反复踩过，写在各 migration 脚本头部）：
   裸词 `-p$env:MYSQL_PASSWORD` **不展开变量**（要整体加引号 `"-p$env:MYSQL_PASSWORD"`）；
   `<` 重定向在 PS 5.1 不可用、`Get-Content | mysql` 会把中文刷成 `?`（用 `-e "source 文件"`）；
   `>` 输出是 UTF-16。

## 十二、常见故障速查

| 现象 | 最可能的原因 | 怎么确认 |
|---|---|---|
| 后端起不来，日志 `IllegalStateException: MinIO 存储桶初始化失败` | 没装 MinIO / endpoint 或凭据不对，而 `IM_FILE_STORAGE` 是默认的 `minio` | 装 MinIO，或显式 `IM_FILE_STORAGE=local`（§5.2） |
| 启动报 `NoUniqueBeanDefinitionException`（SaTokenDao） | 有人删了 `SaTokenDaoForLegacyRedis` 类但留着 exclude，或反过来去掉了 exclude | 两者**成对存在**，改一处必须改另一处 |
| 登录/续期/多端登记全部 500，`ERR syntax error` | 用了 Redis 6+ 的官方 DAO（exclude 被去掉）而服务端是 Redis 5 | `SET ... KEEPTTL XX` 要 Redis ≥ 6 |
| 重启后全员掉线、多实例互不认登录态 | Sa-Token 退回了内存实现（只有 exclude、没有那个类） | 它**不报任何错**，只看启动日志有没有「Redis 5 兼容模式」那一行 |
| 浏览器全部请求 `403 Invalid CORS request`，curl 正常 | 换了域名但 CORS 白名单还是仓库里那份字面列表 | §5.7，两条路任选 |
| 后台新页面 403，数据库里权限明明有 | 跑完带权限点的 SQL 没清 `im:auth:*`（缓存 30 分钟，登录不刷新） | 第六节铁律；等 30 分钟「自己好了」是同一件事的另一面 |
| `/api/xxx` 回 404 | jar 是旧的（服务器上没有那个控制器）；注意 `1002` 才是「活着但没登录」 | `curl -w "%{http_code}"`；对比 `git log` 与 jar 打包时间 |
| 上传大图 413 | Nginx `client_max_body_size` 小于后端的 110MB | §5.5 |
| 上传报 `MaxUploadSizeExceededException` 而不是业务错误码 | 只调了 `im.file.max-size`，没同步调 `spring.servlet.multipart.max-file-size`（两个值必须一起改） | `application.yml` L98-105 的注释 |
| WS 连上一两分钟就断，前端反复重连 | Nginx `/ws` 没配 `proxy_read_timeout`（默认 60s） | §5.5 那段必须有 `proxy_http_version 1.1` + `Upgrade` |
| 手机能打开页面但点通话没反应 / 远控画面一闪即断 | 不是 HTTPS，或 HTTPS 证书的 SAN 不覆盖当前访问的 IP/域名（`fetch` 能绕过，`wss` 握手被浏览器静默丢弃，服务端一行日志都没有） | `md/手机真机调试HTTPS配置指南.md`；开发机另有 `npm run gen:cert` |
| 消息列表整片 500 | 存量库没跑 `migration_message_favorite.sql` | 第六节第 2 条 |
| 一进后台看板 `Table 'im_db.im_report' doesn't exist` | 没跑 `migration_report.sql` | 第六节第 3 条 |
| 直播观众全 403 | `IM_LIVE_SIGN_SECRET` 与 Nginx secret 不一致，或**给变体清单也加了签名** | §10.1 三处一致 |
| 回放列表有点进去 404 | 后端保留期与媒体机清理的 `IM_LIVE_REPLAY_RETENTION_DAYS` 两边不一致 | §10.1 第 3 条 |
| 日志目录里没有文件 | `IM_LOG_HOME` 还是 Windows 默认值 / 目录不可写，logback 只打一条 status 错误不拦启动 | §5.2、§9.1 |
| 定时任务重复执行、消息被推两遍 | 起了两个实例 | 第七节 |

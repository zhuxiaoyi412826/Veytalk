# 二进制部署手册（全组件宿主机原生 · Ubuntu 24.04 · 无 Docker）

> 覆盖五个功能：**群聊/单聊、音视频通话、远程控制、直播、AI**——与 `真实服务器部署手册.md`（Docker 版）功能等价，区别是**每个组件都用宿主机原生进程跑**（systemd 常驻），不依赖任何容器运行时。
> 适用场景：不想装 Docker、要更细的资源控制、或环境对容器有限制。**能上 Docker 就优先用 Docker 版**（编排/回滚/隔离更省心），本手册是等价替代，不是升级。
> 执行纪律同 Docker 版：**一行一等输出，别整块粘贴**（网页控制台会吞行把两条糊成一条）。除标「构建机(Windows)」的命令外，全部在**服务器**上跑（普通用户 + sudo）。
> 变量约定：全文用你自己的公网 IP 和域名替换示例里的 `120.78.126.132` / `im.dsaol.asia` / `admin.dsaol.asia` / `www.dsaol.asia`。

---

## 0. 先看清和 Docker 版的三点根本差异（不符就全盘照抄会踩坑）

| 维度 | Docker 版 | 二进制版（本手册） | 影响 |
|---|---|---|---|
| 中间件地址 | 服务名（`MYSQL_HOST=mysql`、`REDIS_HOST=redis`、`MINIO_ENDPOINT=http://host.docker.internal:9000`） | 全部改 **`127.0.0.1`** | `im.env` 里这几行必须换，否则连不上 |
| nginx 反代后端 | `proxy_pass http://im-server:8080`（容器网络 DNS） | `proxy_pass http://127.0.0.1:8080` | `im.conf` 渲染时要替换这一处 |
| nginx worker 身份 | 容器内 uid=101(`nginx`) | 宿主 **`www-data`**（Ubuntu 默认） | `/data/live` 属主、`client_body_temp_path` 权限按 www-data 算 |
| **UFW 是否生效** | 经 compose 发布的端口走 DOCKER 链，**绕过 UFW** | 原生进程监听宿主端口，**UFW 真拦得住** | ★ 二进制版 3306/6379/8080/8081/9000/9001 **绝不能 `ufw allow`**；coturn 的 UDP 反而**必须** `ufw allow` |

**组件对照（容器 → 原生）**

| 组件 | Docker | 二进制装法 | 监听 |
|---|---|---|---|
| JDK 21 | 镜像内置 | `apt install openjdk-21-jre-headless` | — |
| 后端 | `im-server` 容器 | `java -jar` + `im-server.service` | 127.0.0.1:8080 / 8081 |
| MySQL | `mysql` 容器 | `apt install mysql-server` | 127.0.0.1:3306 |
| Redis | `redis` 容器 | `apt install redis-server` | 127.0.0.1:6379 |
| MinIO | 官方二进制 systemd | **同 Docker 版**（本来就不是容器） | 127.0.0.1:9000/9001 |
| Nginx | `nginx` 容器 | `apt install nginx`（需 dav+secure_link 模块） | 0.0.0.0:80/443/8088 |
| 前端三站 | 挂进 nginx 容器 | 拷进 `/usr/share/nginx/html/<站>`（原生默认根，路径不变） | 由 nginx 提供 |
| coturn | host 网络容器 | `apt install turnserver` | :3478 / UDP 中继段 |

**端口矩阵（★ 二进制版 UFW 这列不再是「不必」，而是「默认关死」**）

| 端口 | 协议 | 用途 | 云安全组 | UFW | 监听方 |
|---|---|---|---|---|---|
| 80 / 443 | TCP | 三站 + `/api` + `/ws` + 直播播放 | 放行 | `ufw allow` | nginx |
| 8088 | TCP | 直播推流（明文 PUT，只写不读） | ★开直播才放行 | 开直播才 `ufw allow 8088/tcp` | nginx |
| 3478 | UDP | STUN / TURN | 开通话才放行 | 开通话才 `ufw allow 3478/udp` | turnserver |
| 49160-49200 | UDP | TURN 中继端口段 | 开通话才放行 | 同步 `ufw allow .../udp` | turnserver |
| 8947 | UDP | 远控 UDP 打洞反射 | 开直连才放行 | 开直连才 `ufw allow 8947/udp` | im-server |
| 9000 / 9001 | TCP | MinIO API / 控制台 | ★绝不放开 | ★不 allow（绑 127.0.0.1） | minio |
| 3306 / 6379 / 8080 / 8081 | TCP | 内部 | ★不放开 | ★不 allow（全部绑 127.0.0.1） | mysql/redis/im-server |

**启动顺序红线**：① MinIO 先起（否则 im-server 连不上桶 fail-fast 反复重启）；② MySQL/Redis 先起；③ 建库数表（期望 **43**）早于首次登录；④ nginx 的 `im.conf` 渲染出来后再 `nginx -t`；⑤ im-server 起来后 nginx 才 reload（否则 `/api` 全 502）。

## 1. DNS 解析 + 云安全组 + UFW

DNS A 记录全指向公网 IP：`im` / `admin` / `www`（`live` 可留空，播放面挂 im 域 `/live`）。

```bash
dig +short im.dsaol.asia          # 回你的公网 IP 才算通
```

云安全组先放行 `TCP 22 / 80 / 443`；`8088`、`3478`、`49160-49200`、`8947` 到对应功能章节再开。

```bash
sudo ufw allow 22,80,443/tcp
sudo ufw enable                    # ★ 二进制版务必开：8080/8081/3306/6379/9000 靠它 + 绑 127.0.0.1 双重收口
sudo ufw status verbose            # 默认应是 deny (incoming)
```

## 2. 装基础依赖（JDK / MySQL / Redis / Nginx / certbot / node）

```bash
sudo apt update
sudo apt install -y openjdk-21-jre-headless mysql-server redis-server \
                    nginx curl gnupg openssl certbot python3-certbot-dns-cloudflare nodejs
```

★ **Nginx 模块校验（直播的硬前提）**：`im.conf` 用到 `dav_methods PUT`（`ngx_http_dav_module`）和 `secure_link`（`ngx_http_secure_link_module`）。

```bash
nginx -V 2>&1 | tr ' ' '\n' | grep -E 'http_dav_module|http_secure_link_module'
# 期望输出两行都出现。缺 secure_link（Ubuntu 的 nginx-core 有时不带）就换装带全模块的包：
sudo apt install -y nginx-extras && nginx -V 2>&1 | grep -o secure_link_module
```

> 不装 nginx-extras 的替代：加 nginx.org 官方 apt 源装 stable 版（默认编入两模块）。二选一即可，别混装。

## 4. MinIO（官方二进制 + systemd，必须先起来）

> 与 Docker 版同一套（MinIO 本来就不在容器栈里）。详细见 `md/MinIO部署指南.md` 三/四节。

```bash
# ① 下官方二进制
sudo curl -fsSL https://dl.min.io/server/minio/release/linux-amd64/minio \
     -o /usr/local/bin/minio && sudo chmod +x /usr/local/bin/minio
sudo useradd -r minio-user 2>/dev/null || true

# ② 凭据与数据目录（★ MINIO_VOLUMES = 下面 .env 的 MINIO_DATA_DIR；凭据 = §5 的 MINIO_ROOT_USER/PASSWORD，逐字一致）
sudo mkdir -p /data/minio && sudo chown minio-user:minio-user /data/minio
sudo tee /etc/default/minio >/dev/null <<'EOF'
MINIO_VOLUMES="/data/minio"
MINIO_OPTS="--address 127.0.0.1:9000 --console-address 127.0.0.1:9001"
MINIO_ROOT_USER=zhuxiaoyi
MINIO_ROOT_PASSWORD=换成与§5一致的强口令
EOF
sudo chmod 600 /etc/default/minio

# ③ systemd 单元
sudo tee /etc/systemd/system/minio.service >/dev/null <<'EOF'
[Unit]
Description=MinIO object storage
After=network.target
[Service]
User=minio-user
Group=minio-user
EnvironmentFile=-/etc/default/minio
ExecStart=/usr/local/bin/minio server $MINIO_OPTS $MINIO_VOLUMES
Restart=always
RestartSec=5
LimitNOFILE=65535
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now minio

# ④ 探活（★ 绑 127.0.0.1：公网碰不到，只有同机 im-server 能连）
systemctl is-active minio && curl -sf http://127.0.0.1:9000/minio/health/live && echo " MinIO OK"
```

> 桶不存在时 im-server 启动阶段会自动建（`MINIO_BUCKET=im-files`），无需手建。桶名须符合 S3 规范（≥3 字符、小写），填 `im` 会被 SDK 拒并让后端起不来。

## 5. 部署变量清单（先集中定值，后面多处引用）

在 `/opt/im/deploy.env` 落一份「单一事实源」（不进版本库，权限 600）：

```bash
sudo tee /opt/im/deploy.env >/dev/null <<'EOF'
IM_SERVER_URL_IP=120.78.126.132
IM_DOMAIN=im.dsaol.asia
ADMIN_DOMAIN=admin.dsaol.asia
WEBSITE_DOMAIN=www.dsaol.asia
LIVE_DOMAIN=live.dsaol.asia
MYSQL_ROOT_PASSWORD=换成强口令
MYSQL_PASSWORD=换成强口令
REDIS_PASSWORD=换成强口令
MINIO_ROOT_USER=zhuxiaoyi
MINIO_ROOT_PASSWORD=换成与§4一致
IM_JWT_SECRET=换成≥32位随机
```

## 6. 后端 im-server（jar + systemd + im.env）

### 6.1 拿 jar

**路线 A（CI 产物，推荐）**：仓库 Actions 的 `build-and-package` 在 push main 时已 `mvn package` 出 `im-server.jar`（artifact）。构建机下载后上传：

```powershell
# 构建机（Windows，仓库根目录）
scp im-bootstrap\target\im-server.jar <user>@120.78.126.132:/opt/im/app/
```

**路线 B（本地打）**：构建机 `mvn -DskipTests package` → `im-bootstrap/target/im-server.jar` → 同上 scp。名字来自 `im-bootstrap/pom.xml` 的 `<finalName>`，不带版本号。

### 6.3 systemd 服务

```bash
sudo tee /etc/systemd/system/im-server.service >/dev/null <<'EOF'
[Unit]

After=network-online.target mysql.service redis-server.service minio.service
Wants=network-online.target

```

## 7. CORS 外挂配置（换域名必做，否则接口全 403）

`application.yml` 里 `im.cors.allowed-origins` 是字面列表、没有 `${}` 占位符，环境变量改不动，只能靠外挂覆盖，且 Spring 绑 List 是**整体替换不是追加**（客户端的 tauri/capacitor/localhost 那几条要一并抄全）。

```bash
sudo tee /opt/im/conf/application-prod-extra.yml >/dev/null <<'EOF'
im:
  cors:
    allowed-origins:
      # ---------- 你的站点 ----------
      - https://im.dsaol.asia
      - https://admin.dsaol.asia
      - https://www.dsaol.asia
      # ---------- 桌面端 Tauri ----------
      - http://tauri.localhost
      - tauri://localhost
      # ---------- 移动端 Capacitor ----------
      - https://localhost
      - http://localhost
      - capacitor://localhost
      # ---------- 联调 vite dev/preview（纯生产可删，删了本地就联调不了线上后端）----------
      - http://localhost:5173
      - http://127.0.0.1:5173
      - http://localhost:4173
      - http://127.0.0.1:4173
      - https://localhost:5173
      - https://127.0.0.1:5173
      - https://localhost:4173
      - https://127.0.0.1:4173
      - http://localhost:5273
      - http://127.0.0.1:5273
      - http://localhost:4273
      - http://127.0.0.1:4273
      - https://localhost:5273
      - https://127.0.0.1:5273
      - https://localhost:4273
      - https://127.0.0.1:4273
EOF
sudo chown im:im /opt/im/conf/application-prod-extra.yml
# 把三个域名换成 deploy.env 的真值：
set -a; . /opt/im/deploy.env; set +a
sudo sed -i -e "s|https://im.dsaol.asia|https://${IM_DOMAIN}|" \
            -e "s|https://admin.dsaol.asia|https://${ADMIN_DOMAIN}|" \
            -e "s|https://www.dsaol.asia|https://${WEBSITE_DOMAIN}|" \
            /opt/im/conf/application-prod-extra.yml
```

> 改错的表现：站点能打开、**接口全 403 `Invalid CORS request`**（curl 不发 Origin 头所以 curl 一切正常，别被骗）。改完 `systemctl restart im-server` 生效。

## 8. 前端三站（dist 拷进 nginx 默认根）

构建机各站先 `npm ci && npm run build`（★ 默认模式，别用 `build:electron`），再拷 **dist 里的内容**（不是 dist 目录本身）：

```powershell
# 构建机（Windows）
scp -r im-ui\dist\*       <user>@120.78.126.132:/usr/share/nginx/html/im-ui/
scp -r im-admin-ui\dist\* <user>@120.78.126.132:/usr/share/nginx/html/im-admin-ui/
scp -r im-website\dist\*  <user>@120.78.126.132:/usr/share/nginx/html/im-website/
```

服务器上先建目录并放开读权限：

```bash
sudo mkdir -p /usr/share/nginx/html/{im-ui,im-admin-ui,im-website}
sudo chown -R www-data:www-data /usr/share/nginx/html
```

> 二进制版前端就是普通静态文件：覆盖即生效，**不用 reload/restart**，用户侧 Ctrl+F5 硬刷拿新 `index.html`。空目录＝站点 403（首次起 nginx 前就得放好）。

## 9. MySQL 建库建用户 + 导入（期望 43 张表）

```bash
sudo systemctl enable --now mysql
sudo mysql                      # Ubuntu 默认 root 走 auth_socket，本机 sudo 免密进

# 进 mysql shell 后逐条执行（★ 密码换成 deploy.env 的真值）
```

```sql
CREATE DATABASE IF NOT EXISTS im_db DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER IF NOT EXISTS 'im'@'localhost' IDENTIFIED BY '取自deploy.env的MYSQL_PASSWORD';
GRANT ALL PRIVILEGES ON im_db.* TO 'im'@'localhost';
FLUSH PRIVILEGES;
SET GLOBAL time_zone = '+08:00';   -- 与 im.env 的 TZ=Asia/Shanghai 对齐，两边只设一个会出现两种时钟
EXIT;
```

导入建库脚本（★ 一律 `source`，**别用管道 `mysql < x.sql`**：中文/emoji 会静默刷成 `?` 而命令返回 0）：

```bash
# 构建机先把两个 sql 传上来
# scp sql/im_schema.sql <user>@120.78.126.132:/opt/im/sql-init/01_im_schema.sql
# scp sql/im_data.sql   <user>@120.78.126.132:/opt/im/sql-init/02_im_data.sql
```

## 12. TLS 证书（三域名各一张，certbot DNS-01）

> ★ nginx 每个 443 server 块各读**自己域名**的 `/etc/letsencrypt/live/<域名>/{fullchain,privkey}.pem`。一张多 SAN 只有一个目录，另两域缺文件 → `[emerg] cannot load certificate` → nginx 起不来。

```bash
# ① Cloudflare API Token（Edit zone DNS 模板，不是 Global API Key）
sudo nano /root/cf.ini          # dns_cloudflare_api_token = <你的 Token>
sudo chmod 600 /root/cf.ini

# ② 三域各签一张
set -a; . /opt/im/deploy.env; set +a
for d in "${IM_DOMAIN}" "${ADMIN_DOMAIN}" "${WEBSITE_DOMAIN}"; do
  sudo certbot certonly --dns-cloudflare --dns-cloudflare-credentials /root/cf.ini \
    -d "$d" --cert-name "$d" --non-interactive --agree-tos -m 你的邮箱
done

# ③ 签完再校验并加载
sudo nginx -t && sudo systemctl reload nginx
```

自动续期（deploy-hook 让续期后自动 reload）：

```bash
sudo tee /etc/letsencrypt/renewal-hooks/deploy/im-nginx.sh >/dev/null <<'HOOK'
#!/bin/sh
systemctl reload nginx
HOOK
sudo chmod 755 /etc/letsencrypt/renewal-hooks/deploy/im-nginx.sh
sudo certbot renew --dry-run
```

> 用云厂商免费 DV 证书也行：三域各下一套 Nginx 格式，放到 `/etc/letsencrypt/live/<域名>/` 并改名 `fullchain.pem`/`privkey.pem`（与模板路径对齐），再 `nginx -t && reload`。

## 14. 直播开闸（8088 推流口 + 签名三处一致 + retention 定时）

**① 签名密钥三处逐字一致**（`im.env` 的 `IM_LIVE_SIGN_SECRET` = nginx `im.conf` 的 `secure_link_md5`，同源于 deploy.env 的 `LIVE_SIGN_SECRET`）：

```bash

grep 'secure_link_md5' /etc/nginx/conf.d/im.conf
# 两行里的密钥一模一样才算过
```

**② 放开 8088**（云安全组 + UFW）：

```bash
sudo ufw allow 8088/tcp
ss -lntp | grep 8088          # 要看到 nginx
```

**③ 回放清理改 systemd timer**（Docker 版是 live-retention 容器，二进制版用 node 脚本 + timer）：

```bash
# 构建机：scp electron/live-retention.js <user>@ip:/opt/im/scripts/
sudo mkdir -p /opt/im/scripts
sudo tee /etc/systemd/system/im-live-retention.service >/dev/null <<'EOF'
[Unit]
Description=IM live replay retention
[Service]
Type=oneshot
User=www-data
ExecStart=/usr/bin/node /opt/im/scripts/live-retention.js --root=/data/live --days=1
EOF
sudo tee /etc/systemd/system/im-live-retention.timer >/dev/null <<'EOF'
[Unit]
Description=Run IM live retention hourly
[Timer]
OnBootSec=5min
OnUnitActiveSec=1h
[Install]
WantedBy=timers.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now im-live-retention.timer
```

> ★ `--days` 必须与 `im.env` 的 `IM_LIVE_REPLAY_RETENTION_DAYS` 同一个数，否则「后台有回放入口、点进去 404」。
> 预演清理（不动手）：`sudo -u www-data node /opt/im/scripts/live-retention.js --root=/data/live --days=1 --dry-run`

**④ 六条 curl 验收**（服务器自测打 127.0.0.1，公网 8088 真能进要在主播机另跑）：

```bash
set -a; . /opt/im/deploy.env; set +a
SECRET="${LIVE_SIGN_SECRET}"
KEY=$(openssl rand -hex 12)
URI="/live/999999/$KEY/index.m3u8"
R() { printf '%-22s %s\n' "$1" "$(curl -s -o /dev/null -w '%{http_code}' "${@:2}")"; }
R "1 PUT8088 期望201" -X PUT --data-binary '#EXTM3U' "http://127.0.0.1:8088$URI"
R "2 GET8088 期望403" "http://127.0.0.1:8088$URI"
R "3 443无签 期望403" --resolve im.dsaol.asia:443:127.0.0.1 "https://im.dsaol.asia$URI"
EXP=$(( $(date +%s) + 600 ))
SIGN=$(printf '%s' "${URI}${EXP}${SECRET}" | openssl dgst -md5 -binary | base64 | tr '+/' '-_' | tr -d '=')
R "4 443有签 期望200" --resolve im.dsaol.asia:443:127.0.0.1 "https://im.dsaol.asia$URI?expire=$EXP&sign=$SIGN"
sudo -u www-data rm -rf /data/live/999999
```

## 18. 改配置怎么生效（systemd 版对照）

| 改了什么 | 生效方式 |
|---|---|
| `conf/im.env`（任何一行） | `sudo systemctl restart im-server`（systemd 每次 start 重读 EnvironmentFile） |
| `conf/application-prod-extra.yml`（CORS） | `sudo systemctl restart im-server` |
| `application-prod.yml` 打进 jar 的东西 | 换 jar → `sudo systemctl restart im-server`（见 §19） |
| `/etc/nginx/conf.d/im.conf` | `sudo nginx -t && sudo systemctl reload nginx`（新建文件/目录才 restart nginx） |
| 改了模板 `im.conf.example` | 重跑 §11.2 的 sed 渲染 → `nginx -t` → reload |
| 换域名 / 换 `LIVE_SIGN_SECRET` | 重跑 §11.2 渲染 + §7 CORS 生成 + `restart im-server` + `reload nginx` |
| 三站前端源码 | 构建机 `npm run build` → 拷 dist 内容覆盖 `/usr/share/nginx/html/<站>/` → 完事（不用 reload） |
| MySQL / Redis / MinIO 配置 | 各自 `systemctl restart mysql|redis-server|minio`，再 `restart im-server` |

### 18.1 应急：停 / 起 / 看日志

```bash
sudo systemctl stop im-server            # 单停后端（维护）
sudo systemctl start im-server
sudo systemctl restart nginx
journalctl -u im-server -n 100 --no-pager        # stdout（INFO+）
journalctl -u im-server --since "10 min ago" -f
tail -f /opt/im/data/logs/error.log              # 慢SQL/慢接口/审核命中只在文件里，journalctl 看不到
```

> ★ 后端日志七档落在 `/opt/im/data/logs/`（info/warn/error + SQL/ + SLOW-API/ + MODERATION/）。后三档 prod 不进 stdout，`journalctl` 里一条都没有，只能读文件。
> ★ 目录空＝没写权限，`chown -R im:im /opt/im/data`。

## 19. 改了代码怎么发版

1. 构建机升版 + 打 jar（或走 CI 出 artifact）：`mvn -DskipTests package` → `im-bootstrap/target/im-server.jar`。
2. 上传替换：`scp im-bootstrap/target/im-server.jar <user>@ip:/opt/im/app/`。
3. 后端重启：`sudo systemctl restart im-server` → `curl -s http://127.0.0.1:8081/actuator/health`。
4. 前端同版要发：各站 `npm run build` → 拷 dist 内容覆盖 `/usr/share/nginx/html/<站>/`。
5. 回滚：留好上一版 jar（`im-server.jar.bak.<时间戳>`），覆盖回去再 `restart im-server`。

> ★ 二进制版没有「换 tag」那套镜像约束，jar 直接覆盖即可；但**发版前务必先 `backup.sh mysql` 备库**（DDL 迁移一旦翻车能回前像）。

## 20. 备份（systemd timer，别和库同盘）

```bash
# 每天 03:30 mysqldump（--single-transaction 不锁表）
sudo tee /usr/local/bin/im-backup.sh >/dev/null <<'EOF'
#!/bin/bash
set -euo pipefail
. /opt/im/deploy.env
DEST=/opt/im/backup; mkdir -p "$DEST"
TS=$(date +%F_%H%M)
mysqldump -uroot --single-transaction --routines --triggers im_db | gzip > "$DEST/im-$TS.sql.gz"
# 异地同步（BACKUP_SYNC_DIR 非空才拷，留空＝和库同盘，盘挂了等于没备）
[ -n "${BACKUP_SYNC_DIR:-}" ] && cp -n "$DEST/im-$TS.sql.gz" "$BACKUP_SYNC_DIR/" || true
# 保留 14 天
find "$DEST" -name 'im-*.sql.gz' -mtime +14 -delete
EOF
sudo chmod 750 /usr/local/bin/im-backup.sh
sudo tee /etc/systemd/system/im-backup.timer >/dev/null <<'EOF'
[Unit]
Description=Daily IM MySQL backup
[Timer]
OnCalendar=*-*-* 03:30:00
Persistent=true
[Install]
WantedBy=timers.target
EOF
sudo systemctl daemon-reload && sudo systemctl enable --now im-backup.timer
sudo /usr/local/bin/im-backup.sh        # 先手工跑一次，确认 backup/im-*.sql.gz 不是极小空包
```

> MinIO 对象存储的备份另算：`/data/minio` 整目录纳入你的磁盘快照或 `mc mirror` 到异地（本脚本只备 MySQL）。

## 21. 故障速查（二进制特有）

| 症状 | 第一嫌疑 | 处置 |
|---|---|---|
| im-server 起不来，日志 `Communications link failure` | MySQL 没起 / `im` 用户密码与 im.env 不一致 | `systemctl status mysql`；§9 建用户密码与 deploy.env 对齐 |
| im-server 连不上桶 fail-fast 反复重启 | MinIO 没起 / 凭据不一致 | `systemctl is-active minio`；§4 凭据 = §5 |
| 站点能开、接口全 403 `Invalid CORS request` | 域名改了没重生成 extra.yml | §7；`restart im-server` |
| 公网能直连 8080/8081/3306/6379/9000 | 没绑回环或 UFW 没开 | 确认 `--server.address=127.0.0.1`、Redis/MySQL bind 127.0.0.1、`ufw enable` |
| `nginx -t` 报 `unknown directive "24}/webm/…"` | location 正则 `{24}` 没加双引号 | 整条正则加引号（模板已带，别手改） |
| 主播 PUT 500 | `/data/live` 或 `/tmp/nginx_body` 不属 www-data | §11.3 chown |
| 观众 403 黑屏 | 签名两处密钥不一致 | §14 ① 两条 grep 对齐 |
| 通话只在局域网通、公网 401 | `TURN_SECRET` ≠ `IM_TURN_SECRET` 或 UDP 没放 UFW | §15 |
| 中文/emoji 全刷成 `?` | 用了管道导 sql | §9 一律 `--default-character-set=utf8mb4 ... SOURCE` |
| 改了 im.env 没反应 | 只 reload nginx 没重启后端 | `systemctl restart im-server` |
| 慢 SQL / 审核命中在 journalctl 找不到 | 这三档 prod 不进 stdout | 读 `/opt/im/data/logs/` 文件 |

## 附：与 Docker 版的取舍

- **选 Docker**：要编排隔离、一键回滚、换机复现快、CI 直接产镜像。
- **选二进制（本手册）**：宿主机资源受限、不允许容器、要 systemd 统一纳管、或想直接 `apt` 拿安全更新。
- 两者功能面完全一致，配置项一一对应（差异就是 §0 那四条）。混用不推荐：同一台机别既跑 compose 栈又跑原生，端口会抢。

# 公网正式部署手册（120.78.126.132 · dsaol.asia）

> 从第一步到最后一步的可复制 runbook。速记版见 `md/综合.txt`，每步的展开原理与故障口径见 `md/部署/Docker部署指南.md`（本手册是它的「照抄可跑」精简版，写死了本机器的 IP 与域名）。
> **除标注「构建机(Windows)」的 scp 外，所有命令都在服务器上跑**（Ubuntu 24.04，普通用户 + sudo）。
> **三条顺序红线，倒了必炸**：① 宿主 MinIO 二进制早于 `up -d`（否则 im-server 连不上桶 fail-fast 反复重启）；② `bootstrap.sh` 早于 `up -d`（否则 nginx 缺配置 `[emerg]` 启动即退出）；③ 建库数表(43) 早于首次登录（空库不影响任何 healthcheck，只炸在第一次登录）。

## 2. 装 Docker + compose 插件（Ubuntu 24.04）

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-v2 ca-certificates curl
sudo systemctl enable --now docker
sudo usermod -aG docker $USER          # 免 sudo 用 docker；★ 执行后必须重新登录一次 shell 才生效
docker compose version                 # 必须是 v2.x（v1 不支持本项目的 depends_on.condition）
```

日志限额（不设的话容器 stdout 无上限，迟早撑爆 `/var/lib/docker`）：

```bash
sudo tee /etc/docker/daemon.json >/dev/null <<'JSON'
{ "log-driver": "json-file", "log-opts": { "max-size": "50m", "max-file": "3" } }
JSON
sudo systemctl restart docker
```

## 3. 装 MinIO 二进制（对象存储，★ 不在 compose 栈里，必须先起来）

完整步骤见 `md/MinIO部署指南.md` 三/四节。三个必对齐点：

- 官方二进制 + systemd unit 常驻（`MINIO_VOLUMES` 指向数据目录）；
- `/etc/default/minio` 的 `MINIO_VOLUMES` **必须 = `.env` 的 `MINIO_DATA_DIR`**（默认 `/data/minio`），否则「备份成功但里面没数据」；
- `MINIO_ROOT_USER/PASSWORD` 与 `.env` **逐字一致**；★ 公网别用 `minioadmin`，且 `PASSWORD ≥ 8 位`（不足 8 位 MinIO 自己拒启）。

验收（通了才算前置完成）：

```bash
systemctl is-active minio && curl -sf http://127.0.0.1:9000/minio/health/live && echo " MinIO OK"
```

## 5. 配 .env + 跑 bootstrap（服务器上）

```bash
cd /opt/im-docker
cp .env.example .env && chmod 600 .env    # 600=仅属主可读写，里面是明文密码与两把签名密钥
vi .env                                    # 填下面「.env 必改项」
```

> ★ **`conf/im.env` 不用手动 `cp`**：它由 bootstrap 第④步从 `conf/im.env.example` 生成，并把根 `.env` 的 7 项密码/密钥（MYSQL_PASSWORD、REDIS_PASSWORD、MINIO_ACCESS_KEY、MINIO_SECRET_KEY、IM_JWT_SECRET、IM_TICKET_SECRET、IM_LIVE_SIGN_SECRET）自动同步进去；你只在 bootstrap 跑完后手填下面「conf/im.env 必填值」（那几项它不替你填、漏了只 warn 不 die）。

`.env` 必改项（★ 密码/密钥在 example 里是 **dev 真值不是 `<...>`**，bootstrap 只拦尖括号占位符、**抓不到这些**，公网必须逐个换）：

```ini
IM_DOMAIN=im.dsaol.asia
ADMIN_DOMAIN=admin.dsaol.asia
WEBSITE_DOMAIN=www.dsaol.asia
LIVE_DOMAIN=live.dsaol.asia

MYSQL_ROOT_PASSWORD=<强口令>
MYSQL_PASSWORD=<强口令>
REDIS_PASSWORD=<强口令>
MINIO_ROOT_USER=<非 minioadmin>
MINIO_ROOT_PASSWORD=<≥8位，且与 §3 的 /etc/default/minio 一致>
IM_JWT_SECRET=<≥32位随机>       # 泄露=任何人能自签 token
IM_TICKET_SECRET=<≥32位随机>    # 泄露=任何人能签文件下载票据

BACKUP_KEEP_DAYS=14
BACKUP_SYNC_DIR=<异地目录 或 user@host:/path>   # ★ 留空=备份和库同盘，盘挂了等于没备份
```

生成一条强随机串：`openssl rand -base64 24 | tr -d '=+/' | head -c 32; echo`

conf/im.env 必填值（★ bootstrap 生成后手填；这些它不从 .env 同步，漏填只 warn 不 die）

```ini
# ① 邮件验证码——填真凭据 或 关健康检查，二选一必须做：
#    占位符 <发件邮箱> 会被拿去认证 QQ → 535 → mail 健康检查 DOWN → im-server 永远 unhealthy → nginx 起不来

MANAGEMENT_HEALTH_MAIL_ENABLED=false   # 不发邮件就靠这行关健康检查；填了真凭据也建议加（每 30s 认证一次会被 QQ 限流）

# ② 直播推流地址（IM_LIVE_ENABLED 默认 true 就要填；<公网IP或域名> 换成真值，端口 8088 与 nginx 一致）
IM_LIVE_PUSH_BASE_URL=http://<公网IP或域名>:8088/live

# ③ 通话 / TURN（只有公网跨 NAT 通话、且部署了 coturn 才需要；不开通话整段不填）
IM_CALL_STUN_URLS=stun=<公网IP>:3478
IM_CALL_TURN_URLS=turn=<公网IP>:3478?transport=udp
IM_TURN_SECRET=<与coturn逐字一致>

# ④ AI 面试官（不用可留空；留空只有面试功能回「未配置」，其余照常）
ALI_BABA_API_KEY=<百炼Key，可留空>
```

```bash

bash scripts/bootstrap.sh      # 生成 conf/im.env、nginx/conf.d/im.conf、app/extra/application-prod-extra.yml、30天自签证书占位
```

> ★ **CORS 白名单不用手改**：bootstrap 会把 `.env` 的三个域名渲染进 `app/extra/application-prod-extra.yml`（连同 tauri/capacitor/localhost 客户端变体），并自动打开 `conf/im.env` 里的 `SPRING_CONFIG_ADDITIONAL_LOCATION`。域名填对 → CORS 就对。改错/漏改的表现是站点能开、**接口全 403 `Invalid CORS request`**。

## 8. 真证书（★ 三个域名各签一张独立证书）

> **为什么签三张而不是一张多 SAN**：nginx 每个 443 server 块各读**自己域名**的证书路径（`certs/live/<域名>/fullchain.pem`）。一张多 SAN 证书只生成一个 `live/im.dsaol.asia/` 目录，`admin`/`www` 的路径就缺文件 → nginx `[emerg] cannot load certificate` → 整栈起不来。
> **两条路线、落点相同**：最终都是把文件摆到 `/opt/im-docker/certs/live/<域名>/{fullchain.pem,privkey.pem}`，reload 与验收动作完全一样。**路线 A 腾讯云免费证书**＝本项目推荐（DNS 在国内腾讯云托管，控制台申请＋自动 DNS 验证，不依赖服务器 80/443、不停容器）；**路线 B certbot DNS-01**＝DNS 在 Cloudflare 等海外时的备选。

### 路线 A：腾讯云免费 DV 证书（推荐）

1. **申请（三次）**：腾讯云控制台 → SSL 证书 → 申请免费证书，分别填 `im.dsaol.asia`、`admin.dsaol.asia`、`www.dsaol.asia`（免费 DV 单域名、一证一域，正对应节首「签三张」约定）；验证方式选**自动 DNS 验证**——域名 DNS 在腾讯云（DNSPod）时控制台自动加、自动清 TXT 记录，分钟级签发；DNS 还在别处就选手工验证，按页面提示自己加 TXT。
2. **下载（Nginx 包）**：签发后在证书列表下载 → 选 **Nginx**，每个域名一个 zip，解开得 `<域名>.crt`（全链：叶子＋中间）与 `<域名>.key`；三套都上传到服务器 `~/ssl/`（zip 内若多一层目录，下一步路径自行调整）。
3. **放进容器挂载位**（★ 三套证书都到齐服务器后再执行；此步同时清掉 bootstrap 自签占位与 certbot 残留）：

```bash
cd /opt/im-docker/certs
sudo rm -rf live                                    # 清自签占位/旧残留，别新旧混在一层
for d in im admin www; do
  sudo mkdir -p live/$d.dsaol.asia
  sudo cp ~/ssl/$d.dsaol.asia.crt live/$d.dsaol.asia/fullchain.pem   # 腾讯云 .crt 即全链，改名为本项目约定
  sudo cp ~/ssl/$d.dsaol.asia.key live/$d.dsaol.asia/privkey.pem
done
sudo chmod -R a+rX /opt/im-docker/certs && sudo chmod 600 live/*/privkey.pem
file live/im.dsaol.asia/fullchain.pem               # 要输出 "PEM certificate"
docker compose exec nginx nginx -t && docker compose exec nginx nginx -s reload
```

4. **验收**（★ issuer 应是 TrustAsia / DNSPod 一类公共 CA，且 issuer ≠ subject；仍等于 subject 就说明还在用那张自签）：

```bash
echo | openssl s_client -connect im.dsaol.asia:443 -servername im.dsaol.asia 2>/dev/null | openssl x509 -noout -issuer -dates
# 域名解析还没恢复时在服务器本机改用 -connect 127.0.0.1:443
```

5. **续期**：免费 DV 有效期以控制台页面为准（现为 3 个月档），**控制台不会把新证书推到你服务器** → 到期前设日历提醒，重新下载并重复第 2–4 步；要无人值守就改用 `acme.sh --dns dns_tencent`（腾讯云 API 密钥、授 DNSPod 权限）自动签发续期，hook 思路同路线 B 的 deploy-hook（先拷再 reload）。

### 路线 B：certbot DNS-01（DNS 在 Cloudflare 等海外时的备选）

> **为什么必须 DNS-01**：本项目 HTTP-01 天生不通——`im.conf` 虽留了 acme-challenge location，但 nginx 容器没挂 `/var/www/acme`，宿主机写的 challenge 文件容器里读到空目录 → 永远 404；`--standalone` 又要抢已被容器占用的 80。DNS-01 不碰 80、不停容器。

```bash
sudo apt install -y certbot python3-certbot-dns-cloudflare     # ★ DNS 插件按你的域名服务商换（见下方备选）
nano ~/cf.ini && chmod 600 ~/cf.ini                            # 内容：dns_cloudflare_api_token = <你的API token>；600 否则等于把凭据放公网
sudo certbot certonly --dns-cloudflare --dns-cloudflare-credentials ~/cf.ini \
  -d im.dsaol.asia --cert-name im.dsaol.asia \
  --non-interactive --agree-tos -m zhuxiaoyizxy2022@163.com --dry-run   # 先干跑测试环境、不占生产配额，通过再跑下面正式循环
for d in im admin www; do
  sudo certbot certonly --dns-cloudflare --dns-cloudflare-credentials ~/cf.ini \
    -d $d.dsaol.asia --cert-name $d.dsaol.asia \
    --non-interactive --agree-tos -m zhuxiaoyizxy2022@163.com
done
sudo certbot certificates && sudo ls /etc/letsencrypt/live/   # 申请验收：三个 cert-name、三个目录、各剩 ~90 天
```

> **DNS 服务商不是 Cloudflare**：阿里云/腾讯云没有 apt 官方插件 → 改用 `acme.sh`（`--dns dns_ali` / `dns_tencent`，同样能自动续），或把域名 NS 免费托管到 Cloudflare 再用上面的命令。

把证书放进容器挂载位（★ 必须 `-L`：certbot 的 `live/` 是指向 `archive/` 的软链接，容器只挂了 `certs` 这一层，`cp -r` 会拷成悬空链接）：

```bash
sudo rm -rf /opt/im-docker/certs/live                          # 清掉 bootstrap 的自签占位，别新旧混在一层
sudo cp -rL /etc/letsencrypt/live /opt/im-docker/certs/ && sudo chmod -R a+rX /opt/im-docker/certs
file /opt/im-docker/certs/live/im.dsaol.asia/fullchain.pem      # 要输出 "PEM certificate"；出现 "symbolic link" = 漏了 -L
docker compose exec nginx nginx -t && docker compose exec nginx nginx -s reload
```

验收（★ issuer 必须是 Let's Encrypt；仍是 `CN=<域名>` 就说明还在用那张自签）：

```bash
echo | openssl s_client -connect im.dsaol.asia:443 -servername im.dsaol.asia 2>/dev/null | openssl x509 -noout -issuer -dates
```

**自动续期 deploy-hook**（★ 续期只更新宿主机 `/etc/letsencrypt`，容器里那份是副本不会自己变；必须「先拷再 reload」，只写 reload 等于没配——不报错，但新证书永远不生效）：

```bash
sudo mkdir -p /etc/letsencrypt/renewal-hooks/deploy
sudo tee /etc/letsencrypt/renewal-hooks/deploy/im-nginx.sh >/dev/null <<'HOOK'
#!/bin/sh
cp -rL /etc/letsencrypt/live /opt/im-docker/certs/
chmod -R a+rX /opt/im-docker/certs
docker compose -f /opt/im-docker/docker-compose.yml exec -T nginx nginx -s reload
HOOK
sudo chmod 755 /etc/letsencrypt/renewal-hooks/deploy/im-nginx.sh   # 没执行权限的 hook 会被静默跳过
systemctl list-timers | grep certbot                               # 确认续期定时器在排
sudo certbot renew --dry-run                                       # 验「能不能续」；★ dry-run 走测试环境、不触发 hook
```

## 9. SSL 证书使用全过程（挂载到容器 + 清理多余证书）

> **与 §8 的分工**：§8 管「把证书签出来/下载回来」，本节管「签回来之后怎么让 nginx 用上、以及把不再需要的旧证书清干净」。两条路线（腾讯云 DV / certbot）的挂载与清理动作完全相同，因为最终落点只有一个：`/opt/im-docker/certs/live/<域名>/{fullchain.pem,privkey.pem}`。

### 9.1 证书在哪、谁在引用它（三层路径，改证书前先看懂）

| 层 | 路径 | 说明 |
|---|---|---|
| 宿主机落点 | `/opt/im-docker/certs/live/<域名>/{fullchain.pem,privkey.pem}` | 唯一事实源；compose `./certs:/etc/letsencrypt:ro`（docker-compose.yml L173）只读挂进容器 |
| 容器内路径 | `/etc/letsencrypt/live/<域名>/…` | im.conf 三个 443 server 块各写自己域名的 `ssl_certificate`/`ssl_certificate_key` 两行（L38-39 / L106-107 / L133-134）；★ 证书路径只写在 server 块里 |
| 协议片段 | 仓库 `Docker/nginx/snippets/ssl.conf` → 宿主机 `/opt/im-docker/nginx/snippets/ssl.conf` → 容器 `/etc/nginx/snippets/ssl.conf`（L169 挂载 :ro） | 只管协议版本/套件/session 缓存/stapling off/HSTS，**不含证书路径**；被 im.conf L40/L108/L135 三处 include |

- ★ **换证书不需要动 ssl.conf、不需要重跑 bootstrap**：ssl.conf 是常驻文件不是 bootstrap 生成物（im.conf 才是）；bootstrap 的自签逻辑是「`fullchain.pem` 不存在才签」，真证书在位时重跑只会跳过。
- ★ 三个域名三条 server 块各读各的目录，所以**永远三套文件一起换**；只换 im 会让 admin/www 继续用旧证书（不报错，但到期那天一起爆）。

### 9.2 挂载上容器（全过程，腾讯云 .crt 与 certbot 产物通用）

```bash
cd /opt/im-docker/certs
sudo rm -rf live                                    # ① 清掉 bootstrap 30 天自签占位/上一轮证书，别新旧混在一层
for d in im admin www; do                           # ② 摆新证书（腾讯云：~/ssl/$d.dsaol.asia.{crt,key}；certbot：见 §8 路线 B 的 cp -rL）
  sudo mkdir -p live/$d.dsaol.asia
  sudo cp ~/ssl/$d.dsaol.asia.crt live/$d.dsaol.asia/fullchain.pem
  sudo cp ~/ssl/$d.dsaol.asia.key live/$d.dsaol.asia/privkey.pem
done
sudo chmod -R a+rX /opt/im-docker/certs && sudo chmod 600 live/*/privkey.pem   # ③ 目录可读、私钥仅 root
file live/im.dsaol.asia/fullchain.pem               # ④ 要输出 "PEM certificate"；"symbolic link" = 拷成了软链接（certbot 源漏 -L）
docker compose exec nginx nginx -t && docker compose exec nginx nginx -s reload  # ⑤ 先 t 再 reload：reload 热加载证书、不断连接；★ 别用 restart/整栈 up -d 代替
echo | openssl s_client -connect im.dsaol.asia:443 -servername im.dsaol.asia 2>/dev/null | openssl x509 -noout -issuer -dates   # ⑥ 验收：issuer 为公共 CA、dates 为新证有效期
docker compose exec nginx nginx -T 2>/dev/null | grep ssl_certificate             # ⑦ 确认容器真正加载的路径就是 /etc/letsencrypt/live/<域名>/…，没有旧路径残留
```

> ⑥ 在域名解析没恢复时在服务器本机改用 `-connect 127.0.0.1:443`。⑦ 的 `nginx -T` 是「容器当前生效配置」全量 dump，grep 出来的路径＝实际在用的证书，比看宿主机目录更准。 ★ 本块逐行粘贴执行：网页控制台整块粘贴吞行断在半途＝「旧证已删、新证没落」中间态，nginx 重启即 [emerg] 进循环（外网症状：443 TCP 通但 TLS 握手被 reset、浏览器报「缺少证书」）；补救＝按本块补齐文件后 `docker compose up -d nginx`。 另：替换若涉及首次新建域名目录（目录原先不存在），把 reload 改为 `docker compose restart nginx`——`:ro` bind mount 下新目录项 reload 可能看不见（scripts/push-cert.sh 的约定注记）；已存在目录的替换则 reload 足够。

### 9.3 清理多余证书（★ 私钥多留一份＝多一个泄露面）

```bash
rm -rf ~/ssl                                        # ① 宿主机中转件：腾讯云 zip/crt/key 用完即删（certbot 路线同样删 ~/ssl 与任何手工副本）
sudo rm -rf /opt/im-docker/certs/live.bak-*         # ② 替换前的备份目录：验收通过后删（留着＝私钥明文躺盘）
sudo find /opt /root /home -xdev \( -name '*.key' -o -name 'privkey.pem' \) 2>/dev/null   # ③ 全盘私钥盘点：只应剩 certs/live/*/privkey.pem 三把；多出来的逐个确认来源后删
sudo rm -f /etc/letsencrypt/renewal-hooks/deploy/im-nginx.sh                              # ④ certbot 残留（只用腾讯云路线时）：先删 deploy-hook 再卸载，否则 renew 定时器空转报错
sudo apt purge -y certbot python3-certbot-dns-cloudflare && sudo apt autoremove -y
sudo rm -rf /etc/letsencrypt                        # ★ 宿主机这个目录与容器挂载无关（容器那份来自 ./certs），删了不影响 nginx
grep -rni 'copy.*cert' --include='Dockerfile' .     # ⑤ 镜像自检：证书从不进镜像，此命令应无输出
```

- ★ **`/opt/im-docker/certs` 与宿主机 `/etc/letsencrypt` 是两回事**：容器里的 `/etc/letsencrypt` 来自 compose 的 `./certs` 挂载（L173），不是宿主机同名目录；所以卸 certbot、删宿主机 `/etc/letsencrypt` 都不会碰掉 nginx 在用的证书。反过来：certbot 路线续期更新的是宿主机 `/etc/letsencrypt`，必须靠 §8 的 deploy-hook「先拷进 ./certs 再 reload」才生效。
- ★ 客户端侧不需要装任何根证书：腾讯云/certbot 都是公共信任链，与 dev 自签那套 `ca.pem`（手机/桌面壳才需要）无关。

### 9.4 续期与巡检

- 腾讯云免费 DV 有效期以控制台页面为准（现档 3 个月）：**控制台不会推送到服务器** → 到期前重新下载、重复 §9.2 ①–⑦；要无人值守改 `acme.sh --dns dns_tencent`，hook 思路同 §8 路线 B（先拷再 reload）。
- 每月巡检一条命令（三个域名各跑一次）：`echo | openssl s_client -connect im.dsaol.asia:443 -servername im.dsaol.asia 2>/dev/null | openssl x509 -noout -enddate`；剩 < 20 天就启动换证。

### 9.5 实战复盘：换证铁律与快速诊断

> 以下铁律全部来自 2026-11 三域真证换发实战（www → im/admin 两轮），每条都有事故背书，不是假想风险。

**七条铁律（按执行顺序）：**

1. **逐行粘贴或封脚本**：网页控制台整块粘贴吞行在本项目实战中发生五次，制造过「旧证已删、新证没落」与「证书落了、私钥没落」两种中间态。多步操作要么逐行粘贴、每行等输出，要么封成 `.sh` scp 上传后 `bash x.sh 2>&1 | tee x.log` 执行（被吞也能 cat 日志捞回）。
2. **全绝对路径**：工作目录停在 `/opt/im-docker/certs` 时写 `certs/live/…` 会造出嵌套的 `certs/certs/live/…`，文件对容器不可见、nginx `[emerg]`。cp/ls 一律写 `/opt/im-docker/certs/live/…`。
3. **落盘先验再动 nginx**：cp 后三验——`ls -l` 看文件在、`openssl x509 -issuer` 看内容对、配对 md5 看证书私钥相配（命令见下）；三验齐才进 reload。
4. **磁盘≠生效（幽灵证）**：nginx 把证书读进内存后不再看磁盘，磁盘文件全删浏览器仍能握到内存旧证（`ERR_CERT_AUTHORITY_INVALID`）。磁盘到生效之间唯一的桥是一次成功的 reload/restart；`docker compose ps` 显示 Running ≠ 证书健康。
5. **新建目录 restart、覆盖目录 reload**：`:ro` bind mount 下 reload 可能看不见新建的目录项（scripts/push-cert.sh 的约定注记）；已存在目录只换文件则 reload 足够。
6. **`-t` 是保险不是流程**：`nginx -t` 不过（如 `key values mismatch`）会拒掉 reload、线上继续旧证——不会 outage 但也不会生效；遇到先查配对，别强 restart 带病上线。
7. **验收后清中转件**：私钥在服务器多留一份＝多一个泄露面；验收通过后 `rm -rf /root/ssl`（含其中的脚本与日志）。

**配对校验命令（证书公钥==私钥公钥，每域两行 md5 必须相同）：**

```bash
sudo openssl x509 -in /opt/im-docker/certs/live/<域名>/fullchain.pem -noout -pubkey | md5sum
sudo openssl pkey  -in /opt/im-docker/certs/live/<域名>/privkey.pem  -pubout | md5sum
```

**浏览器症状快诊表：**

| 症状（浏览器/安全面板） | 根因 | 第一步动作 |
|---|---|---|
| 连接被 reset / 「缺少证书」（握手不完） | 证书文件缺失、nginx 容器 `[emerg]` 循环；或线路层 SNI 干扰（换网络对比可区分） | 服务器 `ls` 三域目录 + `docker compose logs --tail 20 nginx` |
| `ERR_CERT_AUTHORITY_INVALID`（不受信任） | 自签占位仍在生效，或内存幽灵证（reload 没跑） | `s_client -connect 127.0.0.1:443 -servername <域名>` 看 issuer |
| `ERR_CERT_COMMON_NAME_INVALID`（主机名不匹配） | 证书挂错域目录（SAN 不含该域） | `openssl x509 -ext subjectAltName` 看 SAN |
| 无痕绿锁、普通窗口仍旧告警 | 浏览器缓存旧证书判定 | 以无痕窗口为准 |

**本次档案（2026-11-13）：** 三域真证均为阿里云免费 DV（issuer=TrustAsia DV TLS RSA CA 2024，90 天档），统一到期 **2027-02-10**，续期提醒设 2027 年 1 月下旬；续期时按 9.2 三套文件一起换、各归各目录。若某域仍显示自签，按上面快诊表定位，不要重跑全流程。

# 公网正式部署手册（120.78.126.132 · dsaol.asia）

> 从第一步到最后一步的可复制 runbook。速记版见 `md/综合.txt`，每步的展开原理与故障口径见 `md/部署/Docker部署指南.md`（本手册是它的「照抄可跑」精简版，写死了本机器的 IP 与域名）。
> **除标注「构建机(Windows)」的 scp 外，所有命令都在服务器上跑**（Ubuntu 24.04，普通用户 + sudo）。
> **三条顺序红线，倒了必炸**：① 宿主 MinIO 二进制早于 `up -d`（否则 im-server 连不上桶 fail-fast 反复重启）；② `bootstrap.sh` 早于 `up -d`（否则 nginx 缺配置 `[emerg]` 启动即退出）；③ 建库数表(43) 早于首次登录（空库不影响任何 healthcheck，只炸在第一次登录）。

## 1. 域名解析 + 云安全组（先做，certbot 与访问都依赖它）

**DNS A 记录**（在你的域名服务商后台加，全部指向 `120.78.126.132`）：

```
im.dsaol.asia     A  120.78.126.132
admin.dsaol.asia  A  120.78.126.132
www.dsaol.asia    A  120.78.126.132
live.dsaol.asia   A  120.78.126.132   # 可选，暂不开直播可先不加
```

生效验证（回 `120.78.126.132` 才算通；解析没通 certbot 也能签，但用户访问不了）：

```bash
dig +short im.dsaol.asia        # 或 nslookup im.dsaol.asia
```

**云安全组**（阿里云控制台 → 该 ECS → 安全组 → 入方向）：只放行 `22 / 80 / 443`。★ `9000/9001`(MinIO)、`3306`(MySQL)、`6379`(Redis) **一律不对公网放行**（compose 也没发布它们，安全组再兜一层）。

**机器防火墙**：

```bash
sudo ufw allow 22,80,443/tcp
sudo ufw enable
```

## 2. 装 Docker + compose 插件（Ubuntu 24.04）

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-v2 ca-certificates curl
sudo systemctl enable --now docker
sudo usermod -aG docker $USER          # 免 sudo 用 docker；★ 执行后必须重新登录一次 shell 才生效
docker compose version                 # 必须是 v2.x（v1 不支持本项目的 depends_on.condition）
```

日志限额（不设的话容器 stdout 无上限，迟早撑爆 `/var/lib/docker`）：

```bash
sudo tee /etc/docker/daemon.json >/dev/null <<'JSON'
{ "log-driver": "json-file", "log-opts": { "max-size": "50m", "max-file": "3" } }
JSON
sudo systemctl restart docker
```

## 3. 装 MinIO 二进制（对象存储，★ 不在 compose 栈里，必须先起来）

完整步骤见 `md/MinIO部署指南.md` 三/四节。三个必对齐点：

- 官方二进制 + systemd unit 常驻（`MINIO_VOLUMES` 指向数据目录）；
- `/etc/default/minio` 的 `MINIO_VOLUMES` **必须 = `.env` 的 `MINIO_DATA_DIR`**（默认 `/data/minio`），否则「备份成功但里面没数据」；
- `MINIO_ROOT_USER/PASSWORD` 与 `.env` **逐字一致**；★ 公网别用 `minioadmin`，且 `PASSWORD ≥ 8 位`（不足 8 位 MinIO 自己拒启）。

验收（通了才算前置完成）：

```bash
systemctl is-active minio && curl -sf http://127.0.0.1:9000/minio/health/live && echo " MinIO OK"
```

## 4. 上部署包（构建机 Windows 跑 scp；仓库根目录执行）

先在**服务器**建部署目录：

```bash
sudo mkdir -p /opt/im-docker && sudo chown $USER:$USER /opt/im-docker
```

构建机把 `Docker/` 内容 + 建库脚本 + 三站 dist 拷过去（`<user>` 换成你的登录名）：

```powershell

scp -r Docker/* <user>@120.78.126.132:/opt/im-docker/
# ★ 上一条的 * 不匹配点开头文件，.env.example 要单独拷，否则服务器上 cp 不出 .env
scp Docker/.env.example <user>@120.78.126.132:/opt/im-docker/

# ② 建库脚本按顺序名进 sql-init/（★ 只拷 Docker/ 时 bootstrap 的第⑥步找不到 ../sql 会静默跳过，必须手动给）
scp sql/im_schema.sql <user>@120.78.126.132:/opt/im-docker/sql-init/01_im_schema.sql
scp sql/im_data.sql   <user>@120.78.126.132:/opt/im-docker/sql-init/02_im_data.sql

# ③ 三站前端产物：构建机各站先 npm ci && npm run build（★ 默认模式，别用 build:electron），再拷 dist 里的内容
scp -r im-ui\dist\*        <user>@120.78.126.132:/opt/im-docker/web/im-ui/
scp -r im-admin-ui\dist\*  <user>@120.78.126.132:/opt/im-docker/web/im-admin-ui/
scp -r im-website\dist\*   <user>@120.78.126.132:/opt/im-docker/web/im-website/
```

> 后端镜像走 §6 的 `docker compose pull`（GHCR），**无需拷 jar**；只有拉不到镜像时才用 §7 末的本地构建。

## 5. 配 .env + 跑 bootstrap（服务器上）

```bash
cd /opt/im-docker
cp .env.example .env && chmod 600 .env    # 600=仅属主可读写，里面是明文密码与两把签名密钥
vi .env                                    # 填下面「.env 必改项」
```

> ★ **`conf/im.env` 不用手动 `cp`**：它由 bootstrap 第④步从 `conf/im.env.example` 生成，并把根 `.env` 的 7 项密码/密钥（MYSQL_PASSWORD、REDIS_PASSWORD、MINIO_ACCESS_KEY、MINIO_SECRET_KEY、IM_JWT_SECRET、IM_TICKET_SECRET、IM_LIVE_SIGN_SECRET）自动同步进去；你只在 bootstrap 跑完后手填下面「conf/im.env 必填值」（那几项它不替你填、漏了只 warn 不 die）。

`.env` 必改项（★ 密码/密钥在 example 里是 **dev 真值不是 `<...>`**，bootstrap 只拦尖括号占位符、**抓不到这些**，公网必须逐个换）：

```ini
IM_DOMAIN=im.dsaol.asia
ADMIN_DOMAIN=admin.dsaol.asia
WEBSITE_DOMAIN=www.dsaol.asia
LIVE_DOMAIN=live.dsaol.asia

MYSQL_ROOT_PASSWORD=<强口令>
MYSQL_PASSWORD=<强口令>
REDIS_PASSWORD=<强口令>
MINIO_ROOT_USER=<非 minioadmin>
MINIO_ROOT_PASSWORD=<≥8位，且与 §3 的 /etc/default/minio 一致>
IM_JWT_SECRET=<≥32位随机>       # 泄露=任何人能自签 token
IM_TICKET_SECRET=<≥32位随机>    # 泄露=任何人能签文件下载票据

BACKUP_KEEP_DAYS=14
BACKUP_SYNC_DIR=<异地目录 或 user@host:/path>   # ★ 留空=备份和库同盘，盘挂了等于没备份
```

生成一条强随机串：`openssl rand -base64 24 | tr -d '=+/' | head -c 32; echo`

conf/im.env 必填值（★ bootstrap 生成后手填；这些它不从 .env 同步，漏填只 warn 不 die）

```ini
# ① 邮件验证码——填真凭据 或 关健康检查，二选一必须做：
#    占位符 <发件邮箱> 会被拿去认证 QQ → 535 → mail 健康检查 DOWN → im-server 永远 unhealthy → nginx 起不来
MAIL_USERNAME=<发件邮箱>
MAIL_PASSWORD=<SMTP授权码，不是登录密码>
MANAGEMENT_HEALTH_MAIL_ENABLED=false   # 不发邮件就靠这行关健康检查；填了真凭据也建议加（每 30s 认证一次会被 QQ 限流）

# ② 直播推流地址（IM_LIVE_ENABLED 默认 true 就要填；<公网IP或域名> 换成真值，端口 8088 与 nginx 一致）
IM_LIVE_PUSH_BASE_URL=http://<公网IP或域名>:8088/live

# ③ 通话 / TURN（只有公网跨 NAT 通话、且部署了 coturn 才需要；不开通话整段不填）
IM_CALL_STUN_URLS=stun=<公网IP>:3478
IM_CALL_TURN_URLS=turn=<公网IP>:3478?transport=udp
IM_TURN_SECRET=<与coturn逐字一致>

# ④ AI 面试官（不用可留空；留空只有面试功能回「未配置」，其余照常）
ALI_BABA_API_KEY=<百炼Key，可留空>
```

跑 bootstrap（幂等，可重复跑；改过域名要重跑加 `--force`）：

```bash
docker compose config -q       # 先验 compose 插值/缩进/卷引用，错在这一步就报出来
bash scripts/bootstrap.sh      # 生成 conf/im.env、nginx/conf.d/im.conf、app/extra/application-prod-extra.yml、30天自签证书占位
```

> ★ **CORS 白名单不用手改**：bootstrap 会把 `.env` 的三个域名渲染进 `app/extra/application-prod-extra.yml`（连同 tauri/capacitor/localhost 客户端变体），并自动打开 `conf/im.env` 里的 `SPRING_CONFIG_ADDITIONAL_LOCATION`。域名填对 → CORS 就对。改错/漏改的表现是站点能开、**接口全 403 `Invalid CORS request`**。

## 6. 建库（先只起 mysql，空卷首启自动导）

```bash
docker compose pull            # 拉 mysql/redis/nginx/im-server 镜像；GHCR 包私有时先 docker login ghcr.io（PAT 只勾 read:packages）
docker compose up -d mysql
docker compose logs -f mysql   # 看得见 01_im_schema.sql / 02_im_data.sql 被执行的过程才算真导入（Ctrl-C 退出跟随）
```

> ★ 种子文件已自带 `SET NAMES utf8mb4;`（`sql/im_schema.sql` / `sql/im_data.sql` 头部各一行），空卷首启自动导入不会双重编码乱码（会话列表标题乱成 `æ–‡…` 那种）；前提是 `sql-init/01_`、`02_` 拷自这份已修复的仓库 sql（bootstrap 第⑥步 `cp ../sql/*` 或 §4 手动 scp）。

数表（★ 期望 **43**，不是 0；这比只看 `ps` 四个绿可靠得多）：

```bash
docker compose exec mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -N -e "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema=\"im_db\""'
```

> 若卷已非空（不是第一次起），`initdb.d` **不会再跑**，改用 `bash scripts/import-sql.sh`（`cp` 进容器再 `-e "source"`）。★ 任何情况都别用管道 `mysql ... < x.sql`，中文/emoji 会静默刷成 `?` 而命令返回 0。

## 8. 真证书（certbot DNS-01，★ 三个域名各签一张独立证书）

> **为什么必须 DNS-01**：本项目 HTTP-01 天生不通——`im.conf` 虽留了 acme-challenge location，但 nginx 容器没挂 `/var/www/acme`，宿主机写的 challenge 文件容器里读到空目录 → 永远 404；`--standalone` 又要抢已被容器占用的 80。DNS-01 不碰 80、不停容器。
> **为什么签三张而不是一张多 SAN**：nginx 每个 443 server 块各读**自己域名**的证书路径（`/etc/letsencrypt/live/<域名>/fullchain.pem`）。一张多 SAN 证书只生成一个 `live/im.dsaol.asia/` 目录，`admin`/`www` 的路径就缺文件 → nginx `[emerg] cannot load certificate` → 整栈起不来。

```bash
sudo apt install -y certbot python3-certbot-dns-cloudflare     # ★ DNS 插件按你的域名服务商换（见下方备选）
nano ~/cf.ini && chmod 600 ~/cf.ini                            # 内容：dns_cloudflare_api_token = <你的API token>；600 否则等于把凭据放公网

for d in im admin www; do
  sudo certbot certonly --dns-cloudflare --dns-cloudflare-credentials ~/cf.ini \
    -d $d.dsaol.asia --cert-name $d.dsaol.asia \
    --non-interactive --agree-tos -m <你的邮箱>
done
```

> **DNS 服务商不是 Cloudflare**：阿里云/腾讯云没有 apt 官方插件 → 改用 `acme.sh`（`--dns dns_ali` / `dns_tencent`，同样能自动续），或把域名 NS 免费托管到 Cloudflare 再用上面的命令。

把证书放进容器挂载位（★ 必须 `-L`：certbot 的 `live/` 是指向 `archive/` 的软链接，容器只挂了 `certs` 这一层，`cp -r` 会拷成悬空链接）：

```bash
sudo rm -rf /opt/im-docker/certs/live                          # 清掉 bootstrap 的自签占位，别新旧混在一层
sudo cp -rL /etc/letsencrypt/live /opt/im-docker/certs/ && sudo chmod -R a+rX /opt/im-docker/certs
file /opt/im-docker/certs/live/im.dsaol.asia/fullchain.pem      # 要输出 "PEM certificate"；出现 "symbolic link" = 漏了 -L
docker compose exec nginx nginx -t && docker compose exec nginx nginx -s reload
```

验收（★ issuer 必须是 Let's Encrypt；仍是 `CN=<域名>` 就说明还在用那张自签）：

```bash
echo | openssl s_client -connect im.dsaol.asia:443 -servername im.dsaol.asia 2>/dev/null | openssl x509 -noout -issuer -dates
```

**自动续期 deploy-hook**（★ 续期只更新宿主机 `/etc/letsencrypt`，容器里那份是副本不会自己变；必须「先拷再 reload」，只写 reload 等于没配——不报错，但新证书永远不生效）：

```bash
sudo mkdir -p /etc/letsencrypt/renewal-hooks/deploy
sudo tee /etc/letsencrypt/renewal-hooks/deploy/im-nginx.sh >/dev/null <<'HOOK'
#!/bin/sh
cp -rL /etc/letsencrypt/live /opt/im-docker/certs/
chmod -R a+rX /opt/im-docker/certs
docker compose -f /opt/im-docker/docker-compose.yml exec -T nginx nginx -s reload
HOOK
sudo chmod 755 /etc/letsencrypt/renewal-hooks/deploy/im-nginx.sh   # 没执行权限的 hook 会被静默跳过
systemctl list-timers | grep certbot                               # 确认续期定时器在排
sudo certbot renew --dry-run                                       # 验「能不能续」；★ dry-run 走测试环境、不触发 hook
```

## 9. 上线收尾（正式环境每条都对应一个具体故障）

```bash
bash scripts/guard-sql-init.sh        # 把 sql-init/ 的建库脚本挪进 sql-init.disabled/ + 落 .disabled 标记：卷被重建时不再静默清库（im_schema.sql 开头有 43 条 DROP TABLE）。★ 锁是本机状态、不随仓库走
bash scripts/backup.sh mysql          # 先手工备一次，确认 backup/ 里生成的 im-*.sql.gz 不是极小空包
bash scripts/backup.sh --install-cron # 装每天 03:30 自动备份（--single-transaction 不锁表）；异地靠 .env 的 BACKUP_SYNC_DIR，留空等于没备份
```

- **开机自启**：把 `im-docker.service` 的 `WorkingDirectory` 改成 `/opt/im-docker` 后 `systemctl enable --now im-docker`（详见 `Docker部署指南.md` §11.2）。★ 它的 `ExecStop` 刻意**没有 `-v`**——`down -v` 会把 `mysql-data`/`redis-data` 两个卷一起删。
- **改演示账号密码**：`im_data.sql` 里是 `admin / 123456`，上线务必改（业务侧红线，与容器无关）。

## 10. 验收（客户端浏览器，DNS 已解析无需 hosts）

| 站点 | 地址 | server_name | 磁盘目录 |
|---|---|---|---|
| 聊天端 | `https://im.dsaol.asia/` | `im.dsaol.asia` | `web/im-ui` |
| 管理后台 | `https://admin.dsaol.asia/` | `admin.dsaol.asia` | `web/im-admin-ui` |
| 静态官网 | `https://www.dsaol.asia/` | `www.dsaol.asia` | `web/im-website` |

- 地址栏应是**绿锁**，证书颁发者 = Let's Encrypt；三站打开的是**不同页面**（都是同一个站 = `server_name` 没匹上，本栈 80/443 无 `default_server`）。
- CORS 自查（带域名 Origin 不该 403，进业务层回 `code:1002`/参数错都算正常）：

```bash
curl -si -X POST https://im.dsaol.asia/api/auth/login -H 'Origin: https://im.dsaol.asia' -H 'Content-Type: application/json' -d '{}' | head -12
```

- 三站都不通时先 `curl -s http://127.0.0.1/healthz`（应回 `ok`），把「nginx 没起」与「server_name 没匹上」分开。

## 可选模块（用到才开，详见 `Docker部署指南.md` §9）

- **直播回放清理 `live-retention`**（§9.1）：开直播就得起，否则盘上分片没人删（一场 2 小时约 8~10GB）；`--days` 要与 `IM_LIVE_REPLAY_RETENTION_DAYS` 同一个数，否则「后台有回放、点进去 404」。放开还需 compose 里 `8088` 推流口与 `.env` 的 `LIVE_SIGN_SECRET`。
- **TURN**（§9.2）：公网 NAT 下语音/视频打洞，放开 compose 的 coturn 段 + `.env` 的 `TURN_SECRET`（要与 `conf/im.env` 的 `IM_TURN_SECRET` 一致）。
- **AI 面试官知识库**（§9.3）：`IM_AI_KNOWLEDGE_DIR=/app/knowledge` 并**真的放文件**，否则默认值在 Linux 上不存在也不报错、检索永远空转。

## 改了配置怎么生效（最容易搞反的一条）

```bash
docker compose up -d              # 改了 .env / conf/im.env / docker-compose.yml / 换镜像 tag → 必须重建容器（restart 不重读 env_file）
docker compose restart im-server  # ★ 只改了挂载进去的文件（app/extra/*.yml）时用；对它跑 up -d 反而没用（compose 认为配置没变、不重建）
```

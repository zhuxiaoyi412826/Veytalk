## 一、全景：两个维度，四条链路

系统里「过滤违规内容」这件事被拆成**两个正交的维度**，一共四条链路：

| 维度 | 过滤什么 | 判定在哪 | 命中怎么处理 | 用什么技术 |
|---|---|---|---|---|
| **文字** | 骂人 / 敏感词 | **服务端** | **遮蔽成 `*`，消息照常送达** | DFA 字典树（Trie） |
| **图片** | 色情 / 血腥 / 暴力 | **发送端浏览器** | **命中即拒发，图片字节不上传** | 神经网络本地推理 |

五个能力落点：

```
文字维度（服务端 SensitiveWordFilter，一套 Trie 四处复用）
  ├─ ① 聊天文本消息      TextContentHandler      → content 遮蔽
  ├─ ② 图片内 OCR 文字    AttachmentContentHandler → extra.ocrText 遮蔽
  ├─ ③ 文件名            AttachmentContentHandler → extra.fileName 遮蔽
  └─ ④ 直播弹幕          LiveModerationService   → 广播前遮蔽（与聊天同一口径，前面还压两层主播规则）

图片维度（发送端 nsfw.js 多模型编排层，一套判定表两个模型）
  ├─ ⑤a 色情            nsfwjs + TensorFlow.js（MobileNetV2 五类，随包内置）
  └─ ⑤b 血腥 / 暴力      ViT-Base int8 ONNX + onnxruntime-web（默认关闭，需投放模型）
        └─ 图内文字另经 ① 的 OCR 链路（ocr.js 取文 → 服务端过敏感词）
```

**为什么两个维度的判定位置相反？**

- **文字放服务端**：敏感词库 730KB / 约 4 万条，是运营资产，不该下发到每个客户端；
  且文字遮蔽是「改写后照常投递」，必须在落库前由服务端做，客户端改不动。
- **图片放发送端**：一张原图几 MB，判定要过神经网络。放服务端意味着每张图都要上传后再算，
  既有「先传上去再删」的隐私窗口，又要占服务端 CPU/GPU。放发送端则**违规图根本不离开本机**，
  内网无外网出口也能跑（模型随构建产物离线分发）。代价是——**客户端判定可被绕过**（见第六节）。

## 二、文字过滤（骂人 / 敏感词）

### 2.1 词库

- 生效文件：`im-common/src/main/resources/wordlists/sensitive_words.txt`（约 730KB，切出约 4.2 万个 token）
- 装载后的真实条数（以启动日志那一行为准）：**生效 19643 条、丢弃 22570 条**——被丢弃的是单字词、带正则元字符的条目
  与非「汉字 + 小写字母 + 数字」字符集的噪声，而开关为开但 `ready=false` 时一个词都不遮
- ★ **这份词库不在版本库里**：`.gitignore` 的全局 `*.txt` 把它（与下面那个源文件）一起排除了，所以从干净克隆
  打包的 jar 没有词库——部署时要确认资源文件存在；好处是仓库内（代码注释与文档）**不出现任何敏感词原文**
- 源文件：`md/txt/关键词屏蔽41326.txt`（同源，改词库时从这里整理后覆盖到 resources 下）
- 分隔符：中文顿号 `、`、中英文逗号 `，,`、换行，混用都能切
- 打包进 jar，运行期从 classpath 读，**不下发前端**

### 2.2 核心：DFA 字典树 `SensitiveWordFilter`

位置：`im-common/src/main/java/com/im/common/sensitive/SensitiveWordFilter.java`

这是整条文字链路的唯一算法核心，`TextContentHandler` 与 `AttachmentContentHandler` 都注入它。
选 DFA（确定性有限状态自动机，即字典树 Trie）而不是正则或 `String.contains`：
四万条词一次建树，匹配时对文本**只扫一遍**，复杂度 O(文本长度)，与词库大小无关。

**（1）启动装载：清洗 + 建 Trie**

```java
private static final Pattern SEPARATORS = Pattern.compile("[、，,\\r\\n]+");
/** 合法词条：至少 2 个字符，仅汉字与小写字母数字（入库前已折叠大小写） */
private static final Pattern VALID_WORD = Pattern.compile("^[\\p{IsHan}a-z0-9]{2,}$");
private static final String WORDLIST_PATH = "wordlists/sensitive_words.txt";

private static final class Node {
    final Map<Character, Node> children = new HashMap<>(2); // 多数节点只有 1~2 个出边，容量给 2 省内存
    boolean end;
}

@PostConstruct
public void init() {
    enabled = imProperties.getMessage().isSensitiveFilterEnabled();
    try (InputStream in = SensitiveWordFilter.class.getClassLoader().getResourceAsStream(WORDLIST_PATH)) {
        if (in == null) { log.warn("[敏感词] 未找到词库 {}，过滤器保持关闭", WORDLIST_PATH); return; }
        String raw = decode(in.readAllBytes());          // 编码自适应，见下
        int added = 0;
        for (String token : SEPARATORS.split(raw)) {
            String word = fold(token.trim());            // 全角转半角 + 转小写
            if (word.isEmpty()) continue;
            if (VALID_WORD.matcher(word).matches() && insert(word)) added++;  // 合法且首次入树才计数
            // 不合法的（单字、带正则元字符、乱码）直接丢弃
        }
        ready = added > 0;
    } catch (Exception e) {
        log.error("[敏感词] 词库装载失败，过滤器保持关闭", e);   // 装载失败不阻断启动
    }
}
```

几个刻意的设计：

- **只收 ≥2 字符的词**：单字词（如「了」「人」）在正常聊天里误伤率远超收益，全丢。
- **只收「汉字 + 字母 + 数字」**：`词A.{0,6}词B` 这类正则条目不属于字典树的表达能力，丢弃。
- **装载失败不阻断启动**：`ready=false` 时 `mask()` 原样返回——**宁可放行也不能把全服聊天打挂**。
- **编码自适应**：词库来自外部整理，编码没保证。先严格 UTF-8（跳 BOM）解码，失败再按 GB18030 兜底：

```java
private static String decode(byte[] bytes) throws CharacterCodingException {
    int offset = 0;
    if (bytes.length >= 3 && (bytes[0]&0xFF)==0xEF && (bytes[1]&0xFF)==0xBB && (bytes[2]&0xFF)==0xBF) offset = 3; // 跳 BOM
    CharsetDecoder decoder = StandardCharsets.UTF_8.newDecoder()
            .onMalformedInput(CodingErrorAction.REPORT).onUnmappableCharacter(CodingErrorAction.REPORT);
    try {
        return decoder.decode(ByteBuffer.wrap(bytes, offset, bytes.length - offset)).toString();
    } catch (CharacterCodingException e) {
        return new String(bytes, offset, bytes.length - offset, Charset.forName("GB18030")); // 国内 Windows 导出的兜底
    }
}
```

**（2）匹配遮蔽：`mask()` 的 DFA 扫描**

这是全文最关键的算法。它做到两件普通 `contains` 做不到的事：**① 最长匹配；② 原地跳过干扰字符**。

```java
/** 命中即遮：每个被命中的字符（含词内干扰符）替换为等长的 '*'，未命中原文返回 */
public String mask(String text) {
    if (!ready || !enabled || text == null || text.isEmpty()) return text;  // 降级 / 关闭时原样返回
    char[] chars = text.toCharArray();
    int len = chars.length, i = 0;
    boolean changed = false;
    while (i < len) {
        char first = normalize(chars[i]);       // 全角转半角 + 小写
        if (isNoise(first)) { i++; continue; }  // 起始位置的噪声直接跳过
        Node state = root;
        int j = i, matchedEnd = -1;
        while (j < len) {
            char c = normalize(chars[j]);
            if (isNoise(c)) {
                if (state == root) break;       // 还没匹配任何有效字符时的噪声，交给外层推进
                j++; continue;                  // ★ 匹配途中的噪声「原地跳过」，不中断
            }
            Node next = state.children.get(c);
            if (next == null) break;            // Trie 走不下去，本起点匹配结束
            state = next; j++;
            if (state.end) matchedEnd = j;      // ★ 记最长匹配：后面可能更长，继续走
        }
        if (matchedEnd > 0) {
            for (int k = i; k < matchedEnd; k++) chars[k] = '*';  // 命中区间连同中间干扰符一起遮
            changed = true;
            i = matchedEnd;                     // 从命中结尾之后继续扫
        } else {
            i++;
        }
    }
    return changed ? new String(chars) : text;
}

/** 全角 ASCII 转半角后统一小写：词库里有 'ＵＲ' 这种全角写法，不折叠则发送 'ur' 漏检 */
private static char normalize(char c) {
    if (c >= '\uFF01' && c <= '\uFF5E') c = (char) (c - 0xFEE0);
    return Character.toLowerCase(c);
}
/** 字母与数字之外都视为可跳过的干扰符（空白、标点、符号、零宽字符） */
private static boolean isNoise(char c) { return !Character.isLetterOrDigit(c); }
```

**「原地跳干扰字符」是 IM 场景的命门**：用户为规避过滤会把词拆开写——
同一个词写成 `字1*字2~字3`、`字1 字2 字3` 这类夹标点夹空格的变体。判定「干扰」用「非字母且非数字」一刀切（`isNoise`），
比维护一份干扰符白名单更稳：任何新冒出来的花式分隔符天然被跳过，命中后连中间的干扰符一起遮成 `*`。

**遮蔽而不是拒发**（见 `TextContentHandler` 类注释）：阻断式过滤会让一句无心的口头禅把整条消息吞掉，
用户既不知原因也无法补救；遮蔽后消息照常送达，**语义保留、冒犯性去除**。

### 2.3 四个接入点（一套 Trie 复用四处）

**① 聊天文本消息** — `im-message/.../handler/TextContentHandler.java`

```java
@Override
public void normalize(MessageSendCmd cmd) {
    int maxLength = imProperties.getMessage().getMaxTextLength();
    String cleaned = TextUtil.sanitize(cmd.getContent());   // 先 XSS 清洗
    BusinessException.throwIf(TextUtil.isBlank(cleaned), ResultCode.MESSAGE_CONTENT_ILLEGAL);
    BusinessException.throwIf(cleaned.length() > maxLength, ResultCode.MESSAGE_CONTENT_ILLEGAL);
    cleaned = sensitiveWordFilter.mask(cleaned);            // ★ 再遮蔽敏感词
    cmd.setContent(cleaned);
    cmd.setExtra(null);
}
```

顺序有讲究：**先 `sanitize` 去标签，再 `mask` 遮词**——遮词看到的已是去毒文本，
不会被 `<b>傻</b>逼` 这种标签形态拆开绕过。

**② 图片内 OCR 文字 + ③ 文件名** — `im-message/.../handler/AttachmentContentHandler.java`

```java
// ③ 文件名遮蔽后再入库：否则「发个带脏字文件名的文件」就能绕过整条过滤链路
extra.setFileName(sensitiveWordFilter.mask(file.getOriginalName()));

// ② 图片 OCR 文字（normalizeFlashAndOcr 内）
if (TextUtil.isNotBlank(extra.getOcrText())) {
    String cleaned = TextUtil.sanitize(extra.getOcrText().trim());
    if (cleaned.length() > OCR_TEXT_MAX_LENGTH) cleaned = cleaned.substring(0, OCR_TEXT_MAX_LENGTH); // 限长 2000
    extra.setOcrText(sensitiveWordFilter.mask(cleaned));    // ★ 与文件名同一套遮蔽口径
} else {
    extra.setOcrText(null);
}
```

注意：`ocrText` 只对图片消息生效，且**闪照不跑 OCR**（见 2.4）——否则图内文字成了「阅后即焚」销毁后还能看到的后门。

**④ 直播弹幕** — `im-live/.../service/LiveModerationService.java`（由 `LiveDanmakuHandler.onDanmaku` 调用）

弹幕不进 `im_message` 发送链路（它是房间广播帧，不落库、不走 handler 分派），所以 Trie 在这里被**独立调了第二次**，而且前面还压了两层主播自己的规则：

```
禁言名单（拒发）→ 房间屏蔽词（拒发，主播自定义）→ 全局敏感词遮罩（mask，与聊天同一口径）
```

- 前两层是**拒发**、第三层是**遮蔽后照常广播**；判定位置与语义都不同，所以不复用同一个方法，只在遮罩那一步调 `sensitiveWordFilter.mask`。
- 主播豁免前两层，但**全局遮罩对主播自己同样生效**（平台底线不由主播豁免）。
- 屏蔽词比对不用 Trie：那是主播手打的几十条词，直接 `contains`，匹配前做一次 `fold()`（全角转半角 + 小写 + 去空白）；拒发时不回传命中了哪个词，防止逐条试探倒推词表。
- 遮罩开关 `im.live.danmaku-sensitive-mask`；两层主播规则的存储与判定链细节见 `md/直播.md` §13。

### 2.4 前端 OCR 取文（图内文字怎么进来的）

位置：`im-ui/src/utils/ocr.js`。服务端只会遮词，**图里的字得先被识别成文本**——这一步在发送端做：

```js
const OCR_WORKER_PATH = '/tesseract/worker.min.js'  // 三个本地静态目录，对应 vite public 下的拷贝产物
const OCR_CORE_PATH = '/tesseract'
const OCR_LANG_PATH = '/tessdata'
const OCR_TEXT_MAX = 2000                            // 与服务端 OCR_TEXT_MAX_LENGTH 对齐

export async function ocrImageText(file) {
  if (typeof window === 'undefined' || !file || !file.type?.startsWith('image/')) return ''
  let worker
  try { worker = await getWorker() } catch { return '' }         // 加载失败 → 空串，不阻断
  try {
    const { data } = await withTimeout(worker.recognize(file), 'recognize')
    const text = (data?.text || '').replace(/[ \t]*\n[ \t]*/g, '\n').replace(/[ \t]{2,}/g, ' ').trim()
    return text.length > OCR_TEXT_MAX ? text.slice(0, OCR_TEXT_MAX) : text
  } catch { /* 超时 / 异常 → 终止 worker，返回空串 */ return '' }
}
```

要点：

- 基于 **tesseract.js 本地识别**（`chi_sim` 中文包），**全离线**：worker、wasm 核心、语言包都在 `public/tesseract`、`public/tessdata` 下，内网无外网也能用。不把用户图片转给任何第三方识别服务。
- **降级优先**：加载失败、识别超时、语言包缺失等任何异常都只返回空串（图片照常发送），绝不阻断上传主流程。
- worker 空闲 30s 自动回收，避免聊天页长期占上百 MB 内存。
- 识别结果随图片消息的 `extra.ocrText` 上传，**服务端再过一遍敏感词**（2.3 的 ②）后落库；接收端右键「图内文字」查看。

## 三、图片过滤（色情 / 血腥 / 暴力）

### 3.1 两个模型，一套编排

图片判定跑在**发送端浏览器**。因为 nsfwjs 那个模型只认五类（`Drawing/Hentai/Neutral/Porn/Sexy`），
**里面根本没有血腥与暴力**，所以血腥 / 暴力必须另接一个模型，不是调阈值能补出来的。
两个模型、两套推理后端，但评分最后汇进**同一张判定表**、由**同一份后端阈值**驱动：

| | 色情 | 血腥 / 暴力 |
|---|---|---|
| 模型 | MobileNetV2（nsfwjs） | ViT-Base int8 ONNX |
| 推理后端 | TensorFlow.js + WebGL | onnxruntime-web（wasm） |
| 输出类别 | 5 类，违规类 `Porn/Hentai/Sexy` | 2 类，违规类只有 `Violent` |
| 体积 | 约 3.5MB，**base64 内置在 npm 包里** | 约 83MB + 13.6MB wasm，**模型不入库需投放** |
| 默认 | **开**（配了 `Porn/Hentai` 阈值） | **关**（`thresholds` 里没 `Violent` 就整个不加载） |
| 代码 | `nsfw.js` 的 `scoreNsfw` | `violence.js` 的 `scoreViolence` |
| 热态耗时 | 几十毫秒 | 单张约 1.1~1.3s（单线程 wasm） |

> **血腥和暴力在模型里是同一个类** `Violent`：它的训练集（Kaggle「Real Life Violence Situations」）
> 就是真实斗殴 / 伤害 / 血迹照片，分不开，也别指望它看懂卡通打斗。

### 3.2 编排层 `nsfw.js`

位置：`im-ui/src/utils/nsfw.js`。它是「多模型编排层」——不直接推理，而是**按后端阈值决定激活哪些模型、
逐个跑、命中即早退、单个模型挂了不拖垮另一个**。

**（1）检测器注册表 + 激活规则**

```js
const MODELS = [
  { id: 'nsfw',     blockable: ['Porn', 'Hentai', 'Sexy'], score: scoreNsfw },
  { id: 'violence', blockable: ['Violent'], optional: true,
    async score(canvas) {                       // 懒到真正要跑才 import：未启用时连 chunk 都不请求
      const { scoreViolence } = await import('./violence')
      return scoreViolence(canvas)
    } }
]

/** 这个检测器有没有被配置点名：任一违规类有一条有效阈值就算点名 */
function detectorRequested(detector, thresholds) {
  return detector.blockable.some((label) => validThreshold(thresholdOf(thresholds, label)))
}
function validThreshold(value) { return typeof value === 'number' && value > 0 && value <= 1 }
```

两道防线藏在 `blockable` 与 `validThreshold` 里：

- **`blockable` 白名单**：只有「违规类」能拦图。模型输出必然带 `Neutral`/`NonViolent` 这类反向标签，
  有人把阈值写成 `NonViolent: 0.9` 时，不加白名单就会把每张正常照片都拦下。
- **激活规则 = 零新增后端字段**：`thresholds` 是自由 Map，前端用「该检测器的违规类里存在至少一条有效阈值」
  决定是否加载模型。**没配 `Violent` 就 `await import('./violence')` 根本不执行**，省下 96MB 下载。

**（2）判定主流程 `inspectImage`**

```js
export async function inspectImage(file) {
  if (typeof window === 'undefined' || !file || !file.type?.startsWith('image/'))
    return { skipped: true, reason: 'not-image' }
  let policy
  try { policy = await getPolicy() } catch { return { skipped: true, reason: 'policy-error' } }
  if (!policy.enabled) return { skipped: true, reason: 'disabled' }
  if (!policy.thresholds || !Object.keys(policy.thresholds).length)
    return { skipped: true, reason: 'no-threshold' }         // 一条阈值都没有＝只审计不拦截，模型都不必加载
  const active = MODELS.filter((d) => detectorRequested(d, policy.thresholds))
  if (!active.length) return { skipped: true, reason: 'no-active-model' }  // 多半是类别名写错了

  let canvas = null
  try { canvas = await toSquareCanvas(file) }                // 统一缩到 224x224、白底、拉伸
  catch (error) { return { skipped: true, reason: error?.message || 'decode-error' } }

  const scores = [], failures = []
  for (const detector of active) {
    try {
      const part = await detector.score(canvas)
      scores.push(...part)                                   // 两个模型的评分拼进同一张表
      const violation = matchViolation(part, policy.thresholds, detector)
      if (violation) return { skipped: false, violation: true, model: detector.id, ...violation, scores }  // ★ 命中即早退
    } catch (error) {
      failures.push(`${detector.id}:${error?.message || 'error'}`)   // 单模型挂掉不影响另一个，继续
    }
  }
  if (failures.length === active.length)
    return { skipped: true, reason: failures.join(' | '), scores }   // 全挂了才降级放行，带上原因
  return { skipped: false, violation: false, scores, degraded: failures }
}
```

`toSquareCanvas` 把原图先缩到 224×224（白底垫透明区、拉伸而非裁切）再喂模型：
一张 4000×3000 的图直接解码是 36MB 像素张量，先缩能省内存，且模型看到的形状已对、跳过内部 resize。

**（3）命中判定 `matchViolation`**

```js
function matchViolation(scores, thresholds, detector) {
  for (const score of scores) {                              // 评分已按概率降序，第一个命中就是最有把握那一路
    if (!detector.blockable.includes(score.className)) continue   // 白名单
    const threshold = thresholdOf(thresholds, score.className)    // 忽略大小写取阈值
    if (!validThreshold(threshold)) continue
    if (score.probability >= threshold)
      return { hitClass: score.className, hitProbability: score.probability, threshold }
  }
  return null
}
```

**（4）发送前的闸门 `guardImage`**

```js
export async function guardImage(file, options = {}) {
  const result = await inspectImage(file)
  if (result.skipped || !result.violation) return { pass: true, result }   // 未判定 / 通过 → 放行
  const policy = await getPolicy().catch(() => FALLBACK_POLICY)
  if (policy.auditEnabled) {                                  // 拦与报是两件事：关审计仍照旧拒发
    reportModerationHit({                                     // 尽力而为，失败不重试不提示
      scene: options.scene, hitClass: result.hitClass, hitProbability: result.hitProbability,
      threshold: result.threshold, fileName: file.name, fileSize: file.size,
      conversationId: options.conversationId,
      scores: (result.scores || []).map((s) => ({ className: s.className, probability: s.probability }))
    }).catch(() => {})
  }
  return { pass: false, message: CONTENT_UNSAFE_MESSAGE, result }   // '图片含违规内容，已拒发'
}
```

> `scores` 上报**不按 TOP_K 截断**：两个模型的评分是拼在一起的，截前五个会把后一个模型的证据全丢；
> 条目上限交给服务端 `max-score-entries`（默认 16），两个模型合计最多 7 条。

### 3.3 色情模型（nsfwjs + MobileNetV2）

```js
async function getModel() {
  if (!modelPromise) {
    const task = (async () => {
      const [{ load }, { MobileNetV2Model }] = await Promise.all([
        import('nsfwjs/core'),                        // 走 core，不走默认入口
        import('nsfwjs/models/mobilenet_v2')
      ])
      return withTimeout(load('MobileNetV2', { modelDefinitions: [MobileNetV2Model], size: IMAGE_SIZE }), 'load', LOAD_TIMEOUT_MS)
    })()
    modelPromise = task
    task.catch(() => { if (modelPromise === task) modelPromise = null })  // 失败置空，否则整个会话拿同一个 rejection
  } else { resetIdleTimer(await modelPromise) }
  return modelPromise
}

async function scoreNsfw(canvas) {
  const model = await getModel()
  const scores = await withTimeout(model.classify(canvas, TOP_K), 'classify', INFER_TIMEOUT_MS)
  return scores                                       // [{ className, probability }] 五类降序
}
```

关键：nsfwjs 默认入口会**静态引入三个模型（合计约 39MB）**，所以刻意走 `nsfwjs/core` + 显式传
`modelDefinitions`，只把 MobileNetV2（约 3.5MB base64 权重）打进产物；且全程动态 `import`，
不发消息的用户永远不会下载这个 chunk。权重内置在 npm 包里，**随构建产物离线分发，运行期零外部请求**。

### 3.4 血腥 / 暴力模型（`violence.js`）

位置：`im-ui/src/utils/violence.js`。与 nsfwjs 毫无关系，独立的 ONNX 推理，输出同样的
`[{className, probability}]` 形状汇入编排层。

```js
const MODEL_URL = `${import.meta.env.BASE_URL || '/'}models/violence/model.onnx`  // web 是 '/'，electron 是 './'
import wasmMjsUrl from 'onnxruntime-web/ort-wasm-simd-threaded.mjs?url'           // ?url 交给打包器发资源
import wasmBinUrl from 'onnxruntime-web/ort-wasm-simd-threaded.wasm?url'
const LABELS = ['NonViolent', 'Violent']           // 下标 1 才是违规类
export const VIOLENCE_LABEL = 'Violent'

async function getEntry() {
  if (notProvisioned) throw new Error('violence model not provisioned')   // 只撞一次 404 就记死
  if (!entryPromise) {
    const task = (async () => {
      const ort = await import('onnxruntime-web/wasm')                    // 子入口只含 wasm EP，避开 27MB jsep
      ort.env.wasm.wasmPaths = { mjs: wasmMjsUrl, wasm: wasmBinUrl }
      ort.env.wasm.numThreads = typeof SharedArrayBuffer === 'undefined' ? 1 : navigator.hardwareConcurrency || 1
      const response = await withTimeout(fetch(MODEL_URL, { credentials: 'same-origin' }), 'fetch', LOAD_TIMEOUT_MS)
      if (response.status === 404) { notProvisioned = true; throw new Error('violence model missing (404)') }
      const bytes = new Uint8Array(await response.arrayBuffer())
      const session = await withTimeout(
        ort.InferenceSession.create(bytes, { executionProviders: ['wasm'], graphOptimizationLevel: 'all' }), 'session', LOAD_TIMEOUT_MS)
      return { ort, session }
    })()
    entryPromise = task
    task.catch(() => { if (entryPromise === task) entryPromise = null })
  } else { resetIdleTimer(await entryPromise) }
  return entryPromise
}
```

预处理照抄模型的 `preprocessor_config.json`：**224×224 → `/255` → `(x-0.5)/0.5`**（把 0..255 变 -1..1）。
画布是 HWC，模型要 CHW（NCHW），`toTensor` 做转置；ONNX 导出的是 raw logits，自己过 softmax：

```js
function toTensor(ort, canvas) {
  const source = canvas.width === INPUT_SIZE && canvas.height === INPUT_SIZE ? canvas : scaleCanvas(canvas)
  const { data } = source.getContext('2d').getImageData(0, 0, INPUT_SIZE, INPUT_SIZE)
  const plane = INPUT_SIZE * INPUT_SIZE
  const values = new Float32Array(3 * plane)
  for (let i = 0; i < plane; i++) {                     // HWC → CHW 转置 + 归一化
    values[i]             = (data[i*4]     / 255 - 0.5) / 0.5
    values[plane + i]     = (data[i*4 + 1] / 255 - 0.5) / 0.5
    values[2 * plane + i] = (data[i*4 + 2] / 255 - 0.5) / 0.5
  }
  return new ort.Tensor('float32', values, [1, 3, INPUT_SIZE, INPUT_SIZE])
}

export async function scoreViolence(canvas) {
  const entry = await getEntry()
  const feeds = { [entry.session.inputNames[0]]: toTensor(entry.ort, canvas) }
  const results = await withTimeout(entry.session.run(feeds), 'run', INFER_TIMEOUT_MS)
  const output = results[entry.session.outputNames[0]]
  const count = Math.min(LABELS.length, output.dims[output.dims.length - 1])
  const probabilities = softmax(output.data, count)     // 减最大值再 exp，Float64 累加
  resetIdleTimer(entry)
  return LABELS.slice(0, count)
    .map((className, index) => ({ className, probability: probabilities[index] }))
    .sort((a, b) => b.probability - a.probability)      // 与 nsfwjs 同形状，编排层一视同仁
}
```

**默认关闭 + 投放才生效**：模型 83MB 不入库（`.gitignore` 的 `im-ui/public/models/`），
运维按 [`图片内容审核接入指南.md`](图片内容审核接入指南.md) 第九节投放到 `public/models/violence/model.onnx`，
再打开 `application.yml` 里注释的 `# Violent: 0.75`。没投放时前端首次 `fetch` 撞 404 → `notProvisioned` 记死 →
该检测器停用，**色情那条链路照常，不会每张图重试下载**。

> onnxruntime-web + Vite 的三个必踩坑（`?url` 子路径要走包 exports、入口用 `/wasm` 避开 jsep、
> 别把 wasm 拷进 `public/` 否则 dev 下 `?import` 回 500 报 `no available backend found`）见接入指南第九节。

### 3.5 后端：只下发策略 + 只接收上报

后端**不跑任何模型**，两个接口都在 `im-file/.../controller/ModerationController.java`（挂 `/api/file/moderation`）：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/file/moderation/policy` | 下发 `{ enabled, auditEnabled, thresholds }`，发送端据此决定要不要识别、按什么判违规 |
| POST | `/api/file/moderation/report` | 命中上报，**只写审计日志，服务端不采信其结论**（限流 30 次/分） |

**策略下发**（`ModerationServiceImpl.policy` + `cleanThresholds`）：阈值原样下发前先清一遍——
`null`、越界（`≤0` 或 `>1`）、空类别名都跳过并告警，把「配置写错」在下发时就收敛成「这条不生效」：

```java
private Map<String, Double> cleanThresholds(ImProperties.Moderation config) {
    Map<String, Double> thresholds = new LinkedHashMap<>();
    Map<String, Double> raw = config.getThresholds();
    if (raw == null || raw.isEmpty()) return thresholds;
    raw.forEach((className, value) -> {
        if (className == null || className.isBlank() || value == null || value <= 0 || value > 1) {
            log.warn("[审核] 阈值配置项无效，已跳过: class={}, threshold={}", className, value);
            return;
        }
        thresholds.put(className.trim(), value);
    });
    return thresholds;
}
```

**命中上报**（`report`）：写进审计专用 logger `com.im.moderation`（只落 `MODERATION/moderation.log`，
不进 info/warn/error 档），一行一条，客户端自由文本都经 `oneLine`（折空白、去引号反斜杠、限长）与
`probability`（夹到 0~1、定长三位小数）收敛，防日志注入：

```java
StringBuilder line = new StringBuilder("[审核命中]")
        .append(" userId=").append(userId)
        .append(" scene=").append(scene.getCode())          // requireImageScene 只收图片类场景（含 video_cover）
        .append(" class=").append(oneLine(req.getHitClass(), 32))
        .append(" prob=").append(probability(req.getHitProbability()))
        .append(" threshold=").append(probability(req.getThreshold()))
        .append(" size=").append(req.getFileSize() == null ? "-" : req.getFileSize());
String scores = formatScores(req.getScores(), maxEntries); // 最多 max-score-entries 条
if (!scores.isEmpty()) line.append(" scores=").append(scores);
AUDIT.info(line.toString());
```

### 3.6 图片审核的三个接入点

`guardImage(file, { scene })` 在三处发送前调用，`scene` 决定审计里的业务来源：

| 接入点 | 文件 | scene |
|---|---|---|
| 聊天发图 | `im-ui/src/views/ChatWindow.vue` | `chat_image` |
| 头像上传 | `im-ui/src/views/Profile.vue` | `avatar` |
| 直播 / 视频封面 | `im-ui/src/views/Live.vue` | `video_cover` |

聊天发图的时序（`ChatWindow.vue`）刻意把**审核排在最前**：

```js

  try {

}
// …通过后才挂占位气泡、上传，随后（非闪照）再跑 OCR 取图内文字
```

OCR 排在审核之后，因为识别一张反正要被拦掉的图纯属白花时间（OCR 首次要加载十几 MB，比模型贵得多）。

## 五、端到端时序：发一张图 / 一条文字发生了什么

**发一张图片（聊天）：**

```
用户选图
  → [发送端] guardImage：拉策略(缓存10min) → 按 thresholds 激活模型
       → toSquareCanvas(224×224) → 色情模型 score →（若配了 Violent）血腥模型 score
       → matchViolation
            命中 → reportModerationHit（POST /report，后端写审计）→ 弹「图片含违规内容，已拒发」→ 结束（字节没上传）
            通过 → 继续
  → [发送端] 上传文件拿 fileId →（非闪照）ocrImageText 取图内文字
  → [发送端] 发消息（content=fileId, extra.ocrText=…）
  → [服务端] AttachmentContentHandler.normalize：
       文件名 mask → OCR 文字 sanitize+限长+mask → 落库 extra
  → 接收端：看图；右键「图内文字」看遮蔽后的 OCR 文本
```

**发一条文字：**

```
用户发文本
  → [服务端] TextContentHandler.normalize：sanitize(XSS) → 长度校验 → mask(敏感词遮蔽成 *)
  → 落库、投递（消息照常送达，只是脏词变 *）
```

两个维度的根本差异一眼可见：**文字在服务端「改写后照发」，图片在发送端「命中就不发」**。

## 六、边界与已知局限

| 局限 | 影响 | 处理建议 |
|---|---|---|
| **图片判定在客户端，可绕过** | 直接调上传接口就能把违规图发上去 | 这是「正常使用路径上的闸门」，不是对抗性防御；要真防线得在服务端补推理链路（阈值 / 错误码 / 审计口径可复用），见接入指南路线 B/C |
| **血腥 / 暴力默认关** | 模型 83MB 不入库，没投放就整个检测器停用 | 要开按接入指南第九节投放 + 配 `Violent` |
| **血腥 / 暴力只有二分类** | 血迹与斗殴都算 `Violent`，分不开；卡通打斗看不懂 | 要分开处置得换或自训模型 |
| **真实照片精度未验收** | 合成图也能给到 0.66~0.73 | `Violent` 别压到 0.75 以下，投放后看日志分布再校 |
| **开了血腥 / 暴力每张图多等 1.2~2.3s** | 同步卡在发送前；无 SharedArrayBuffer 时只能单线程 wasm | 不想付这代价就别配 `Violent` |
| **敏感词是字典树，非语义** | 谐音、拼音缩写、形近字变体可能漏检 | DFA 只能覆盖「插干扰符」这一类变体；语义级需另接模型 |
| **OCR 识别率有限** | 艺术字、低分辨率、复杂背景取文不全 | 尽力而为，取不到就空串照常发；不阻断 |
| **全量判定不落盘，只记命中** | 看不到「判过但通过」的量，无法算精度 | 有意为之：全量落盘会把审计变成隐私负担 |

降级总原则：**文字与图片的每一个旁路能力（OCR、色情、血腥暴力）异常时都放行 / 返回空，绝不因为审核环节出问题把用户的正常发送卡住**。
